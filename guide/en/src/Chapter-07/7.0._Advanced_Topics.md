# 7. Advanced Topics

By this point you can train every estimator and network in the crate, split and scale data, and read off metrics. This chapter is about the cross-cutting concerns that surface once those models leave your editor and go into a test suite, a benchmark, or someone else's binary: making a run repeat exactly, moving a trained model between processes, getting the parallel kernels to match your hardware, and stripping the dependency tree down to what you actually compile. None of it changes what a model computes; all of it changes whether you can trust, ship, and afford the result.

These sections assume you have worked through [Getting Started](../Chapter-01/1.0._Getting_Started.md) and have trained at least one model from [Classical Machine Learning](../Chapter-02/2.0._Classical_Machine_Learning.md) or [Neural Networks](../Chapter-03/3.0._Neural_Networks.md). They are largely independent, so read them in any order — but 7.1 is the natural entry point, because reproducibility is what makes the persistence round-trips and performance comparisons in the later sections verifiable at all.

## 7.1. Reproducibility and Random Seeds

Every randomized component — weight initialization, dropout and noise masks, the `Sequential` minibatch shuffle, k-means centroids, SVC/LinearSVC, MeanShift, Isolation Forest, `train_test_split`, t-SNE — draws its RNG through one resolver, so a single `set_global_seed(seed)` call on the current thread fixes them all together. [Reproducibility and Random Seeds](./7.1._Reproducibility_and_Random_Seeds.md) works through the three-way resolution between a per-model `random_state: Option<u64>`, the thread-local global seed, and OS entropy; why an explicit local seed never perturbs the seeds handed to unseeded components; and the thread-locality trap that bites people under `--test-threads=1`. It underpins the deterministic splits in [Train-Test Split](../Chapter-04/4.1._Train_Test_Split.md).

```rust
use rustyml::set_global_seed;

fn main() {
    // Fix every unseeded draw on this thread before constructing any model.
    set_global_seed(42);
}
```

## 7.2. Model Persistence in Depth

`save_to_path` / `load_from_path` serialize a trained model to a compact `postcard` binary. [Model Persistence in Depth](./7.2._Model_Persistence_in_Depth.md) goes past the happy path: what actually lands in the bytes (the fitted parameters and hyperparameters, not your dataset), why loading a neural network reconstructs weights into an architecture you rebuild by hand rather than the graph itself, and how a layer-count or weight-shape disagreement surfaces as `IoError::ModelStructureMismatch` instead of silently loading garbage. It pairs with [Saving and Loading Weights](../Chapter-03/3.9._Saving_and_Loading_Weights.md), which covers the network-specific save/load mechanics in full.

## 7.3. Performance Tuning and Parallelism

Every parallel kernel chooses serial-versus-rayon (and, for GEMM, which parallel strategy) by comparing a work estimate against a calibrated threshold, and those thresholds are tuned on the maintainer's machine, not yours. [Performance Tuning and Parallelism](./7.3._Performance_Tuning_and_Parallelism.md) shows how the `rustyml::tuning` facade overrides each gate at runtime — GEMM/GEMV FLOP crossovers, elementwise and reduction element counts, the conv/pool/norm gates, and the tree gates — through a single relaxed atomic store, so you can retune for your core count and cache sizes without a recompile. A gate only selects an execution strategy; it never changes what is computed. See [Matrix Multiplication](../Chapter-06/6.2._Matrix_Multiplication.md) and [Parallel Reductions](../Chapter-06/6.3._Parallel_Reductions.md) for the kernels these gates govern.

## 7.4. Minimal Builds and Modular Integration

The crate splits into feature-gated modules — `machine_learning`, `neural_network`, `utils`, `metrics`, and the shared `math` core — so a project that only needs k-means never compiles the neural-network stack or its `indicatif` progress-bar dependency. [Minimal Builds and Modular Integration](./7.4._Minimal_Builds_and_Modular_Integration.md) maps which feature pulls in which dependencies, what the `default`, `full`, and `show_progress` flags actually turn on, and how to drop RustyML into an existing pipeline as one module among many. For the first-pass version of this material, see [Installation and Feature Flags](../Chapter-01/1.2._Installation_and_Feature_Flags.md).
