# 1. Getting Started

RustyML is a machine learning and deep learning library written entirely in Rust — no BLAS to link, no Python runtime, no C++ bindings to fight with. This chapter takes you from an empty `Cargo.toml` to a trained model on disk, and pins down the conventions every later chapter silently assumes: how data flows through `ndarray`, how feature flags gate what you compile, where the prelude lives, and how failures come back. If you are arriving from scikit-learn or Keras the shapes are familiar — estimators expose `fit`/`predict`, neural layers stack into a `Sequential` — but the ergonomics are Rust's: a `Result` where Python would raise, borrowed views where NumPy would copy, and feature flags where `pip install` gives you one monolith. The sections below are organized around those differences.

**Prerequisites.** Be comfortable with `cargo`, Rust's ownership and borrowing, and the basic supervised loop (train, predict, evaluate). Prior `ndarray` experience is not required — [1.3](./1.3._Working_with_ndarray.md) covers what the estimators need. Everything runs on stable Rust (edition 2024, toolchain 1.89 or newer) with no system libraries to install.

[**1.1 What is RustyML**](./1.1._What_is_RustyML.md) sets expectations before you commit code: what actually ships — classical ML estimators, a Keras-shaped neural-network stack, preprocessing, metrics, and shared low-level math — and an honest account of what "pure Rust" buys you (portability, no linker surprises, memory safety) versus what it costs against the mature Python ecosystem. Start here if you are still deciding whether the library fits your problem.

[**1.2 Installation and Feature Flags**](./1.2._Installation_and_Feature_Flags.md) is the section people skip and regret. RustyML is split into `machine_learning`, `neural_network`, `utils`, `metrics`, and `math`, and you compile only what you switch on. It explains the `default`, `full`, and `show_progress` bundles and why enabling just the module you use keeps builds lean. Get the flags wrong and your imports simply will not resolve — the types are gated behind the features that define them.

[**1.3 Working with ndarray**](./1.3._Working_with_ndarray.md) covers the dependency the whole book leans on. Every model speaks `ndarray`: `Array2<f64>` for feature matrices, `Array1<_>` for targets, borrowed `ArrayView`s at the call boundary. It shows how to build arrays from plain `Vec`s, the row-major (samples × features) layout the estimators expect, and why passing a view instead of an owned array avoids a copy on every call.

[**1.4 Your First End-to-End Model**](./1.4._Your_First_End_to_End_Model.md) assembles the pieces into a runnable program: build a tiny dataset, `fit` a `LinearRegression`, `predict`, then round-trip the model through `save_to_path` / `load_from_path`. Watching the full compile-train-persist loop close once removes any remaining doubt about how the parts connect.

[**1.5 The Prelude and Imports**](./1.5._The_Prelude_and_Imports.md) explains the import ergonomics. `use rustyml::prelude::*` pulls every enabled category's types, traits, and functions into scope in one line, or you can take one category at a time (`prelude::machine_learning`, `prelude::metrics`, and so on). It also covers when the shared traits — `Fit`, `Predict`, `Transform` — must be in scope, the usual cause of a puzzling "method not found".

[**1.6 Error Handling**](./1.6._Error_Handling.md) closes the loop on failure. Fallible operations return `Result<T, Error>` over one unified `Error` enum whose variants name the problem precisely — `NotFitted`, `DimensionMismatch`, `InvalidParameter`, `NonFinite`, and more. It shows how to `match` them, why `Error` is `#[non_exhaustive]` (so you keep a `_` arm), and how `.context()` attaches a breadcrumb to a wrapped lower-level error. The guide's examples `.unwrap()` for brevity; production code should not.

**Reading order.** Go straight through on a first pass. If you already know Rust tooling, skim [1.2](./1.2._Installation_and_Feature_Flags.md) and [1.3](./1.3._Working_with_ndarray.md) and land on [1.4](./1.4._Your_First_End_to_End_Model.md); if you are still evaluating, read [1.1](./1.1._What_is_RustyML.md) first. Later chapters — [Classical Machine Learning](../Chapter-02/2.0._Classical_Machine_Learning.md), [Neural Networks](../Chapter-03/3.0._Neural_Networks.md), and beyond — take the array, feature-flag, and error conventions established here as given.

The whole loop in one screen, so you know where you are headed:

```rust
use rustyml::machine_learning::LinearRegression;
use ndarray::{Array1, Array2};

fn main() {
    // 3 samples, 1 feature; the underlying relationship is y = 2x.
    let x = Array2::from_shape_vec((3, 1), vec![1.0, 2.0, 3.0]).unwrap();
    let y = Array1::from_vec(vec![2.0, 4.0, 6.0]);

    // new(fit_intercept, learning_rate, max_iter, tol) -> Result.
    let mut model = LinearRegression::new(true, 0.05, 5000, 1e-9).unwrap();
    model.fit(&x, &y).unwrap();

    let preds = model.predict(&x).unwrap();
    println!("predicted {} values", preds.len());
}
```
