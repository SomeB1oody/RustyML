# 3.8. Regularization and Normalization Layers

This page covers the layers that do not learn a mapping so much as reshape the signal flowing through the network: dropout and its spatial variants, the two Gaussian noise layers, and the four normalization layers (batch, layer, group, instance). They live together in `rustyml::neural_network::layers::regularization` for one concrete reason — every one of them behaves differently during training than during inference, and the crate factors that split out into a single shared mechanism. Get that mechanism straight first and the rest of the page is detail; miss it and batch normalization in particular will quietly give you wrong numbers. If you are arriving from [Dense Layers and Activations](./3.2._Dense_Layers_and_Activations.md), everything here plugs into a [`Sequential`](./3.1._The_Sequential_Model.md) model with the same `.add(...)` call, and every constructor returns a `Result` for the reasons laid out in [Error Handling](../Chapter-01/1.6._Error_Handling.md).

Everything is imported through `use rustyml::neural_network::layers::*;`, which re-exports `Dropout`, `SpatialDropout1D`/`2D`/`3D`, `GaussianNoise`, `GaussianDropout`, `BatchNormalization`, `LayerNormalization` (plus its `LayerNormalizationAxis`), `GroupNormalization`, and `InstanceNormalization`. As everywhere in this crate, a `Tensor` is `ndarray::ArrayD<f32>` — single precision, dynamic rank.

## 3.8.1. Training mode versus inference mode

Every mode-dependent layer carries a private `training: bool` flag and exposes two ways to run forward. The [`Layer`](./3.1._The_Sequential_Model.md) trait defines both:

```rust,ignore
fn forward(&mut self, input: &Tensor) -> Result<Tensor, Error>;   // records caches, honors the flag
fn predict(&self, input: &Tensor) -> Result<Tensor, Error>;       // always eval, writes no caches
```

`forward` takes `&mut self`, consults the `training` flag, and stores whatever it needs for the backward pass (masks, batch statistics, the noise draw). `predict` takes `&self`, always runs the inference path, and records nothing — which is why a compiled model can be shared across threads for concurrent serving. You flip the flag with `set_training_if_mode_dependent(is_training)` (the trait method) or the inherent `set_training(is_training)`; layers that don't care about the mode (Dense, activations, pooling) inherit a no-op and ignore both.

Inside a `Sequential` you almost never touch this yourself. `fit`/`fit_with_batches` set every layer to training mode and call `forward`; `predict` calls each layer's `predict`. The trap is calling `forward` by hand for inference: a `BatchNormalization` layer whose flag is still `true` will compute batch statistics from your "test" batch and mutate its running averages, so use `model.predict(...)` — or set the flag to `false` — for anything that isn't a training step. Here is exactly what each family does in each mode:

| Layer | `forward` in training mode | `forward` in inference / `predict` | `backward` in inference mode |
| --- | --- | --- | --- |
| `Dropout`, `SpatialDropout*` | drop a fraction, rescale survivors | identity (pass through unchanged) | gradient passed through |
| `GaussianNoise` | add `N(0, stddev²)` | identity | gradient passed through |
| `GaussianDropout` | multiply by `N(1, σ)` | identity | gradient passed through |
| `BatchNormalization` | normalize with **batch** stats, update running stats | normalize with **running** stats | gradient passed through |
| `LayerNormalization`, `GroupNormalization`, `InstanceNormalization` | normalize with stats from the current input | **same** stats from the current input | gradient passed through |

The bottom row is worth staring at: layer, group, and instance normalization compute their statistics from the current input in every mode, so their `forward` output is identical whether the flag is on or off, and `predict` equals `forward` bit-for-bit. Only their backward pass is mode-aware — in inference mode it returns the upstream gradient untouched instead of running the real gradient. Batch normalization is the sole layer here that keeps state (running mean and variance) and therefore genuinely computes something different in the two modes.

## 3.8.2. Dropout

`Dropout::new(rate, input_shape)` builds the classic layer. `rate` is the fraction of units to zero and must lie in `[0.0, 1.0]` inclusive (a value outside that returns `Error::InvalidParameter`); `input_shape` is checked against every input, but only for its rank and its per-sample axes — axis 0 is the batch, and because that varies with whoever calls `forward` it is never compared, so a layer declared `vec![4, 8]` takes a batch of any size while still rejecting rows that are not 8 wide. The wildcard `vec![]` turns the check off entirely. The implementation is **inverted dropout**: during a training `forward`, it samples a uniform mask, keeps each unit with probability `1 - rate`, and scales the survivors by `1 / (1 - rate)` so the expected activation is unchanged. That scaling is the whole point — it means inference is a pure identity (`predict` returns the input verbatim), with no rescaling to remember at serving time. The two boundaries short-circuit: `rate == 0.0` is the identity, `rate == 1.0` zeros everything.

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // 50% rate, expecting [4, 8] inputs; seed the mask so this run is reproducible.
    let mut dropout = Dropout::new(0.5, vec![4, 8]).unwrap().with_random_state(7);
    let input = Array::ones((4, 8)).into_dyn();

    // Training: about half the units become 0, the survivors become 1/(1-0.5) = 2.0.
    dropout.set_training_if_mode_dependent(true);
    let train_out = dropout.forward(&input).unwrap();
    let kept = train_out.iter().filter(|&&v| v != 0.0).count();
    println!("kept {kept}/{} units, each rescaled to 2.0", input.len());

    // Inference: inverted dropout makes the layer the identity.
    dropout.set_training_if_mode_dependent(false);
    assert_eq!(dropout.forward(&input).unwrap(), input);

    // predict() is the eval path regardless of the flag, and never caches a mask.
    assert_eq!(dropout.predict(&input).unwrap(), input);
}
```

The mask is drawn from a per-layer `StdRng`. By default `Dropout::new` seeds it from the global seed (or from OS entropy if none is set); `with_random_state(seed)` re-seeds it deterministically. Because the RNG advances with each draw, two consecutive training `forward` calls produce different masks — seeding fixes the *sequence* across process runs, not equality between calls. See [Reproducibility and Random Seeds](../Chapter-07/7.1._Reproducibility_and_Random_Seeds.md) for how the global seed threads through every randomized component. Dropout has no trainable parameters, and calling `backward` before `forward` (so no mask was cached) returns `NnError::ForwardPassNotRun`; in inference mode or at `rate == 0.0` the backward simply passes the gradient through.

## 3.8.3. Spatial dropout for feature maps

Plain dropout is a poor fit for convolutional feature maps. Adjacent pixels in a channel are strongly correlated, so zeroing scattered individual elements removes almost no information — a dropped pixel's value is essentially recoverable from its neighbors, and the regularizing effect washes out. `SpatialDropout1D`, `SpatialDropout2D`, and `SpatialDropout3D` fix this by dropping an entire channel at a time: when a channel is dropped, all of its spatial positions go to zero together, which forces the network to not rely on any single feature map. This mirrors Keras' `SpatialDropout*`.

The three differ only in the expected rank, all in channels-last layout: `SpatialDropout1D` wants 3-D `(batch, length, channels)`, `SpatialDropout2D` wants 4-D `(batch, height, width, channels)`, and `SpatialDropout3D` wants 5-D `(batch, depth, height, width, channels)`. A wrong rank returns `Error::InvalidInput`. Internally they sample one keep/drop value per `(batch, channel)` — a tiny `[batch, channels]` mask — and apply the same `1 / (1 - rate)` inverted-dropout scale across the whole channel, so no full-size mask is ever materialized. Construction, seeding (`with_random_state`), the boundary behaviors, and the `ForwardPassNotRun` contract are identical to plain `Dropout`; the error even names the concrete layer, so a premature backward on a `SpatialDropout2D` says `ForwardPassNotRun("SpatialDropout2D")`.

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // (batch=1, height=4, width=4, channels=8): whole channels drop as a unit.
    let mut sd = SpatialDropout2D::new(0.5, vec![1, 4, 4, 8]).unwrap().with_random_state(3);
    sd.set_training_if_mode_dependent(true);

    let input = Array::ones((1, 4, 4, 8)).into_dyn();
    let out = sd.forward(&input).unwrap();

    // Every position within a channel shares one value: 0.0 (dropped) or 2.0 (kept & rescaled).
    for c in 0..8 {
        let first = out[[0, 0, 0, c]];
        assert!((0..4).all(|h| (0..4).all(|w| out[[0, h, w, c]] == first)));
        println!("channel {c}: all 16 spatial positions hold {first}");
    }
}
```

## 3.8.4. Gaussian noise and Gaussian dropout

Two layers regularize by injecting noise rather than by zeroing. `GaussianNoise::new(stddev, input_shape)` is **additive**: during training it adds zero-mean `N(0, stddev²)` noise, `output = input + noise`. It is a data-augmentation flavor of regularization — it perturbs inputs without changing their expected value but does inflate their variance, and with a large enough `stddev` a positive input can go negative. `stddev` must be non-negative and finite (a negative or `NaN`/`Inf` value is rejected at construction, which is deliberate: it would otherwise panic inside the sampler on the first forward). Its backward pass is a pure pass-through in every mode, because the noise is independent of the input, so `d(x + noise)/dx = 1`; it caches nothing and never returns `ForwardPassNotRun`.

`GaussianDropout::new(rate, input_shape)` is **multiplicative** and is the closer analogue to plain dropout. It multiplies each input by a sample from `N(1, σ)` with `σ = sqrt(rate / (1 - rate))`, so the mean-1 noise leaves `E[output] = input` — the same expectation-preserving idea as inverted dropout, but with continuous multipliers instead of hard zeros. Here `rate` must be in `[0.0, 1.0)` — exclusive of 1, since `σ` diverges as `rate → 1`. Unlike `GaussianNoise`, it caches the exact noise draw so its backward can reuse it (`y = x * noise ⇒ dx = grad * noise`); a backward before any training forward returns `ForwardPassNotRun`. Both layers are the identity at inference (and whenever `stddev`/`rate` is 0), and neither has trainable parameters.

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    let input = Array::from_elem((2, 4), 3.0_f32).into_dyn();

    // Additive: output = input + N(0, 0.5^2). Mean preserved, variance added.
    let mut noise = GaussianNoise::new(0.5, vec![2, 4]).unwrap().with_random_state(1);
    noise.set_training_if_mode_dependent(true);
    let noisy = noise.forward(&input).unwrap();

    // Multiplicative: output = input * N(1, sqrt(rate/(1-rate))). E[output] stays at input.
    let mut gdrop = GaussianDropout::new(0.3, vec![2, 4]).unwrap().with_random_state(1);
    gdrop.set_training_if_mode_dependent(true);
    let scaled = gdrop.forward(&input).unwrap();

    println!("additive[0] = {}, multiplicative[0] = {}", noisy[[0, 0]], scaled[[0, 0]]);

    // Both are the identity at serving time.
    noise.set_training_if_mode_dependent(false);
    gdrop.set_training_if_mode_dependent(false);
    assert_eq!(noise.forward(&input).unwrap(), input);
    assert_eq!(gdrop.forward(&input).unwrap(), input);
}
```

## 3.8.5. The normalization layers at a glance

The four normalization layers share a skeleton: each subtracts a mean and divides by a standard deviation computed over some set of axes, then applies a learnable per-channel affine `gamma * x_normalized + beta`. `gamma` initializes to ones and `beta` to zeros, both are exposed to the optimizer as trainable parameters (and marked no-decay, so weight decay skips them — normalizing scale/shift is not something you want pulled toward zero), and every layer takes an `epsilon` (typically `1e-5`) added under the square root for numerical stability, which is also what makes a zero-variance input produce a finite all-zero output instead of a `NaN`. What separates them is purely *which axes the statistics reduce over*. For an input shaped `[N, ...spatial, C]` (batch `N` leading, channels `C` trailing):

| Layer | Mean/variance reduced over | One statistic per | Depends on batch? | `gamma`/`beta` length |
| --- | --- | --- | --- | --- |
| `BatchNormalization` | batch `N` (and all spatial) | channel | **yes** | `C` |
| `LayerNormalization` | the normalized axis (last, by default) | everything but that axis | no | normalized axis size |
| `GroupNormalization` | a group of channels + spatial, per sample | (sample, group) | no | `C` |
| `InstanceNormalization` | spatial only, per sample and channel | (sample, channel) | no | `C` |

Read the "depends on batch?" column as the practical decision axis. Batch norm couples samples together through shared statistics, which is what makes it powerful and also what makes it fragile at small batch sizes; the other three normalize each sample independently and are batch-size-invariant. All four preserve the input shape, and none of the guards below are optional — group and instance normalization require rank ≥ 3 (a 2-D input is `Error::InvalidInput`), while batch norm accepts 2-D and up.

## 3.8.6. BatchNormalization

`BatchNormalization::new(input_shape, momentum, epsilon)` — note the argument order: shape first, then the two scalars. `input_shape` must be non-empty (`Error::EmptyInput` otherwise), `momentum` must be in `[0.0, 1.0]`, and `epsilon` must be positive. Dimension 0 is the batch and the **last** dimension is the channel/feature; the per-channel parameters have length `input_shape.last()`. For a 2-D `[N, C]` input this is ordinary per-feature batch norm. For a rank-3-or-higher `[N, ...spatial, C]` input the statistics reduce over the batch **and** every spatial position, so there is one mean/variance/gamma/beta per channel — "spatial" batch norm, matching Keras' `axis=-1` default. Both are the same code path: with the channel axis innermost, `[N, ...spatial, C]` already *is* the `[M, C]` matrix the per-channel folds read, so collapsing the leading axes reinterprets the same bytes rather than reshaping them. (A 1-D `input_shape` like `vec![4]` is a special case with no channel axis: it uses length-1 scalar parameters broadcast over the whole input.)

The state that makes batch norm mode-dependent is the pair of running statistics. During a training `forward`, after normalizing with the current batch's mean and variance, it updates them as `running = running * momentum + batch * (1 - momentum)`. This is the **Keras** convention: a high momentum like `0.99` weights the history heavily and moves the running estimate slowly. If you come from PyTorch this is inverted — PyTorch's `momentum` weights the *new* batch — so a value you'd copy across will behave backwards. `momentum == 0.0` throws history away entirely (running stats equal the last batch's), and `momentum == 1.0` freezes them at their initialization (mean 0, variance 1), which quietly makes eval-mode normalization a near-identity — usually a bug. At inference, `forward`/`predict` normalize with those running statistics instead of any batch, which is precisely why feeding a test batch through `forward` in training mode corrupts the model.

Where you place it relative to the activation matters, and the fused-activation design of `Dense` shapes your options. The original paper puts batch norm *before* the nonlinearity. Because `Dense::new(.., .., Activation::ReLU)` folds the activation into the linear layer, getting "BN before activation" means using a linear `Dense`, then `BatchNormalization`, then a standalone activation layer:

```rust,ignore
use rustyml::neural_network::layers::activation::relu::ReLU;
// Dense(linear) -> BatchNorm -> ReLU  (BN before the nonlinearity, paper ordering)
model
    .add(Dense::new(4, 8, Activation::Linear).unwrap())
    .add(BatchNormalization::new(vec![6, 8], 0.99, 1e-5).unwrap())
    .add(ReLU::new());
```

The common alternative — activation first, then normalize — is just `Dense::new(.., .., Activation::ReLU)` followed by `BatchNormalization`. Both train fine; pick one and be consistent. A full runnable model, using the simpler activation-in-the-Dense form:

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::sequential::Sequential;
use rustyml::neural_network::optimizers::Adam;
use rustyml::neural_network::losses::MeanSquaredError;
use ndarray::Array;

fn main() {
    // The 6 in the BatchNormalization shape [6, 8] is not enforced; only the trailing 8 is.
    let x = Array::ones((6, 4)).into_dyn();
    let y = Array::ones((6, 1)).into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(4, 8, Activation::ReLU).unwrap())
        .add(BatchNormalization::new(vec![6, 8], 0.9, 1e-5).unwrap())
        .add(Dropout::new(0.3, vec![6, 8]).unwrap())
        .add(Dense::new(8, 1, Activation::Linear).unwrap())
        .compile(
            Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    // fit() runs the training path (batch stats, running-stat updates, dropout on);
    // predict() runs the eval path (running stats, dropout as identity).
    model.fit(&x, &y, 3).unwrap();
    println!("prediction shape: {:?}", model.predict(&x).unwrap().shape());
}
```

Note that the leading dimension of `input_shape` records a batch size but is not enforced: a `BatchNormalization` declared for `[6, 8]` accepts a batch of any size, so `fit_with_batches` trains at any `batch_size`, including the short final chunk left over when the dataset does not divide evenly. What the check does enforce is the rank and every per-sample axis, so an `[n, 16]` input — or one of the wrong rank — is still `Error::ShapeMismatch`. That also means the `vec![]` wildcard is not the way to make a layer survive mini-batching; reach for it only when the per-sample shape itself varies. You can also inject known weights directly with `set_weights(gamma, beta, running_mean, running_var)` (a shape mismatch returns `NnError::WeightShape`), which is how a loaded model restores its inference statistics — see the next section and [Saving and Loading Weights](./3.9._Saving_and_Loading_Weights.md).

## 3.8.7. LayerNormalization

`LayerNormalization::new(input_shape, epsilon)` normalizes across features *within each sample*, with no batch coupling and no running statistics — which is exactly why it is the normalization of choice for recurrent models and for any setting where the batch is small, variable, or size 1. Where batch norm's statistics get noisy or meaningless with a handful of samples, layer norm is unaffected because every sample stands alone. Its `forward` output is the same in training and inference (`predict` equals `forward`), and only its backward is mode-gated.

By default it normalizes the last (feature) dimension. `with_normalized_axis(...)` changes that, taking a `LayerNormalizationAxis`: `Default` (last axis), `Custom(axis)` for a single other axis, or `Multiple(vec![...])` to normalize jointly over several axes at once (Keras-style, where the statistics span the combined elements and `gamma`/`beta` become 1-D over their product). Changing the axis resizes `gamma`/`beta` to match, so call it before assigning weights. An empty, duplicated, or out-of-bounds axis list is rejected; a non-trailing `Custom` axis or a permuting `Multiple` list is handled correctly, just on a slower strided path.

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    let input = Array::from_shape_vec((2, 4), vec![1.0, 3.0, 5.0, 7.0, 2.0, -2.0, 0.0, 4.0])
        .unwrap()
        .into_dyn();

    // Default: each row (the last axis) is normalized to mean 0, variance 1.
    let mut ln = LayerNormalization::new(vec![2, 4], 1e-5).unwrap();
    let out = ln.forward(&input).unwrap();

    // Custom(0): normalize down each column (across the batch axis) instead.
    let mut ln_cols = LayerNormalization::new(vec![2, 4], 1e-5)
        .unwrap()
        .with_normalized_axis(LayerNormalizationAxis::Custom(0))
        .unwrap();
    let out_cols = ln_cols.forward(&input).unwrap();

    println!("row-norm {:?}, col-norm {:?}", out.shape(), out_cols.shape());

    // Statistics come from the current input, so predict() reproduces forward() exactly.
    assert_eq!(ln.predict(&input).unwrap(), out);
}
```

## 3.8.8. GroupNormalization and InstanceNormalization

These fill the middle ground for convolutional models where the batch is too small for batch norm to be reliable — detection and segmentation backbones, and generative models. `GroupNormalization::new(input_shape, num_groups, epsilon)` splits the channels into `num_groups` contiguous groups and normalizes within each group of one sample; with one group it is layer norm over all channels, and with as many groups as channels it is instance norm. `InstanceNormalization::new(input_shape, epsilon)` normalizes each `(sample, channel)` plane on its own, which is the standard choice for style transfer because it strips per-instance contrast while leaving batch relationships alone. Both require rank ≥ 3, take the channel axis as the trailing one like every other spatial layer, and like layer norm they carry no running statistics and are mode-independent in the forward direction. Their per-group mean and variance come from a single pass: the two accumulators are gathered together as sums of deviations from a value taken out of the data, so the variance falls out without a second walk of the sample and without the catastrophic cancellation a plain `E[x²] − E[x]²` would hit when the mean dwarfs the spread.

Instance norm is literally group norm with `num_groups` equal to the channel count, and the crate implements it that way, so the two produce identical output when configured to match:

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // [batch=1, positions=4, channels=4]
    let input = Array::from_shape_vec((1, 4, 4), (0..16).map(|v| v as f32).collect::<Vec<_>>())
        .unwrap()
        .into_dyn();

    // InstanceNorm normalizes every (sample, channel) plane independently...
    let mut inn = InstanceNormalization::new(vec![1, 4, 4], 1e-5).unwrap();
    let out_in = inn.forward(&input).unwrap();

    // ...which is exactly GroupNorm with one group per channel.
    let mut gn = GroupNormalization::new(vec![1, 4, 4], 4, 1e-5).unwrap();
    let out_gn = gn.forward(&input).unwrap();

    let max_diff = out_in
        .iter()
        .zip(out_gn.iter())
        .map(|(a, b)| (a - b).abs())
        .fold(0.0_f32, f32::max);
    println!("max |InstanceNorm - GroupNorm(groups=channels)| = {max_diff}");
    assert!(max_diff < 1e-6);
}
```

One divisibility rule to know: `num_groups` must evenly divide the channel count, and the crate checks it at `forward` time (not in the constructor), so a mismatched `GroupNormalization` builds fine but fails the first forward with `Error::InvalidParameter`. `num_groups == 0`, `channel_axis == 0`, an out-of-bounds axis, and a non-positive `epsilon` are all caught at construction. Both layers accept `set_weights(gamma, beta)`.

## 3.8.9. Seeding, determinism, and what gets saved

Two cross-cutting properties finish the picture. First, randomness: only the dropout and Gaussian layers draw random numbers, each from its own `StdRng` seeded via the crate's global-seed machinery — `new` seeds from the global seed or entropy, `with_random_state(seed)` pins it. The normalization layers are fully deterministic. Even the internal parallel/serial thresholds these layers use are bit-for-bit invariant (the parallel path produces the same result as the serial one), so enabling threads never changes your numbers; that is a performance knob only, covered in [Performance Tuning and Parallelism](../Chapter-07/7.3._Performance_Tuning_and_Parallelism.md). Seed everything together through [Reproducibility and Random Seeds](../Chapter-07/7.1._Reproducibility_and_Random_Seeds.md).

Second, persistence, which has one asymmetry worth internalizing before you save a model. The dropout and noise layers hold no trainable parameters — they serialize as empty, and their RNG state is *not* saved, which is harmless because they are the identity at inference anyway. `LayerNormalization`, `GroupNormalization`, and `InstanceNormalization` serialize just their `gamma` and `beta`, which is complete because they recompute statistics from each input. `BatchNormalization` is the exception: its weight record carries `gamma`, `beta`, **and** `running_mean` and `running_var`. Those running statistics are what inference uses, so if they were dropped a loaded model would normalize with garbage; because they are persisted, a saved-and-reloaded batch-norm model predicts identically to the original. The mechanics of the round-trip live in [Saving and Loading Weights](./3.9._Saving_and_Loading_Weights.md) and [Model Persistence in Depth](../Chapter-07/7.2._Model_Persistence_in_Depth.md).
