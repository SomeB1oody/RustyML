# 3.7. Recurrent Layers

RustyML ships three recurrent layers — `SimpleRNN`, `LSTM`, and `GRU` — that live under `rustyml::neural_network::layers::recurrent` and are re-exported through the prelude. All three share one contract: they consume a 3D sequence tensor, run a left-to-right recurrence over the time axis, and return the final hidden state. If you are coming from Keras, think of them as `SimpleRNN`/`LSTM`/`GRU` with `return_sequences=False` hard-wired on — that "hard-wired" part has real consequences for how you stack them, so read [section 3.7.7](#377-stacking-and-building-a-model) before you try to build a deep recurrent network.

## 3.7.1. The input/output contract

Every recurrent layer expects a 3D input tensor laid out as `(batch_size, timesteps, features)` and produces a 2D output `(batch_size, units)`. The `features` axis must equal the `input_dim` you passed to the constructor; `units` is the hidden width you asked for. The timestep axis is consumed by the recurrence and does not appear in the output — only the last hidden state `h_T` survives.

```rust
use ndarray::Array;
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::recurrent::SimpleRNN;
use rustyml::neural_network::traits::Layer;

fn main() {
    // input_dim = 4 features per timestep, units = 3 hidden neurons
    let rnn = SimpleRNN::new(4, 3, Tanh::new()).unwrap();

    // (batch = 2, timesteps = 5, features = 4)
    let x = Array::zeros((2, 5, 4)).into_dyn();

    // predict runs the recurrence without recording backward caches
    let out = rnn.predict(&x).unwrap();

    // The timestep axis is gone: only the last hidden state survives.
    println!("output shape: {:?}", out.shape()); // [2, 3] == (batch, units)
}
```

```text
output shape: [2, 3]
```

The constructor is identical across the three layers: `new(input_dim, units, activation) -> Result<Self, Error>`. The activation argument is `impl Into<Activation>`, so you can pass either an `Activation` enum variant (`Activation::Tanh`) or one of the thin layer wrappers (`Tanh::new()`, `ReLU::new()`, `Sigmoid::new()`, `Linear::new()`, `Softmax::new()`) — they convert to the same enum. See [3.2. Dense Layers and Activations](./3.2._Dense_Layers_and_Activations.md) for the full activation catalog. `new` returns `Error::InvalidParameter` if `input_dim` or `units` is 0. There is **no** `return_sequences`, `return_state`, `bidirectional`, or in-cell dropout option; the layer always returns the last state, always runs forward in time, and always uses a single dense implementation.

Feeding anything other than a 3D tensor is a hard error, not a silent reshape: `forward`/`predict` return `Error::InvalidInput` for a 2D or 4D input. Because the layer caches its forward activations for backprop, calling `backward` before `forward` returns `Error::NeuralNetwork(NnError::ForwardPassNotRun("SimpleRNN"))` (or `"LSTM"`/`"GRU"`). See [1.6. Error Handling](../Chapter-01/1.6._Error_Handling.md) for how these variants fit together.

One nuance worth internalizing early, because it differs from Keras: the `activation` argument controls only the *candidate/output* nonlinearity. In `SimpleRNN` it is applied to every hidden state. In `LSTM` and `GRU` it is applied to the candidate (and, for LSTM, to the cell state before the output gate) — but the gates themselves are **always** sigmoid. RustyML does not expose Keras's separate `recurrent_activation`; the gate nonlinearity is fixed. Tanh is the sensible default and what almost every published architecture uses.

## 3.7.2. SimpleRNN and why gated cells exist

`SimpleRNN` is the textbook Elman recurrence. Starting from a zero hidden state, each timestep mixes the current input with the previous hidden state through two weight matrices and one bias:

```text
h_0 = 0
h_t = activation( x_t @ W + h_{t-1} @ U + b )     for t = 1..T
output = h_T
```

Here `W` is the input kernel `(input_dim, units)`, `U` is the recurrent kernel `(units, units)`, `b` is the bias `(1, units)`, and `@` is a matmul that runs over the batch dimension. `W` is initialized Xavier/Glorot uniform and `U` orthogonal (Gram-Schmidt); the orthogonal recurrent kernel is deliberate — it keeps the state transition norm-preserving at initialization, which is the cheapest thing you can do to delay the problem this section is about.

That problem is vanishing (and exploding) gradients. Backpropagating from `h_T` to `h_1` multiplies the upstream gradient by a fresh Jacobian at every step: roughly `grad_{t-1} = (activation'(h_t) ⊙ grad_t) @ Uᵀ`. Chain `T` of those together and you are raising a matrix to the `T`-th power. If its effective magnitude is below one the gradient decays exponentially and the network cannot learn dependencies more than a handful of steps back; above one and it blows up. Orthogonal `U` fixes the `Uᵀ` factor to be norm-preserving, and `tanh' ≤ 1` keeps things bounded, but the product still tends toward zero over long sequences. This is why `SimpleRNN` is fine for short sequences (a few dozen steps) and useless for long-range dependencies — and why LSTM and GRU exist.

## 3.7.3. LSTM: an additive memory highway

LSTM adds a second state — the cell state `c_t` — whose update is *additive*, and it uses three sigmoid gates to decide what to write, keep, and read. RustyML stores the four weight blocks fused side by side in the Keras column order `[input | forget | cell | output]`, written `[i | f | g | o]`:

```text
i_t = sigmoid( x_t @ W_i + h_{t-1} @ U_i + b_i )     input gate  (how much candidate to write)
f_t = sigmoid( x_t @ W_f + h_{t-1} @ U_f + b_f )     forget gate (how much old cell to keep)
g_t = act(     x_t @ W_g + h_{t-1} @ U_g + b_g )     candidate   ("cell gate")
o_t = sigmoid( x_t @ W_o + h_{t-1} @ U_o + b_o )     output gate (how much cell to expose)
c_t = f_t * c_{t-1} + i_t * g_t                      cell state  (additive update)
h_t = o_t * act(c_t)                                 hidden state
```

`*` is elementwise and `act` is the configurable activation (default Tanh, applied to both the candidate and the cell state). The line that matters is `c_t = f_t * c_{t-1} + i_t * g_t`. Its gradient with respect to `c_{t-1}` is just `f_t` — an elementwise multiply, no repeated matmul. When the forget gate is open (`f ≈ 1`) the cell state carries the gradient backward almost unattenuated, a near-identity highway that the additive term feeds into. That is the whole trick: memory persists and gradient flows because the dominant path is addition, not repeated matrix multiplication.

To give that highway a running start, RustyML initializes the **forget-gate bias to 1.0** (all other biases are zero). Before training has shaped the gates, `f` starts biased open so the cell state — and its gradient — survive from the first epoch. The integration test `lstm_forget_bias_is_one_not_zero` exists precisely to pin this behavior. LSTM costs four gates' worth of parameters: `param_count = 4 * (input_dim * units + units * units + units)`.

## 3.7.4. GRU: the same idea with merged gates

GRU keeps the additive-blend intuition but folds LSTM's input and forget gates into a single **update** gate and drops the separate cell state, so it needs three weight blocks instead of four, stored fused in the order `[reset | update | candidate]` = `[r | z | h]`:

```text
r_t = sigmoid( x_t @ W_r + h_{t-1} @ U_r + b_r )          reset gate
z_t = sigmoid( x_t @ W_z + h_{t-1} @ U_z + b_z )          update gate
n_t = act( x_t @ W_h + (r_t * h_{t-1}) @ U_h + b_h )      candidate
h_t = (1 - z_t) * h_{t-1} + z_t * n_t                     hidden state
```

The update gate `z_t` runs a convex blend: `z ≈ 0` copies the previous hidden state through unchanged (a gradient highway, exactly like an open LSTM forget gate), `z ≈ 1` replaces it with the fresh candidate. The tests `gru_update_gate_zero_leaves_hidden_unchanged` and `gru_update_gate_one_replaces_hidden_with_candidate` bracket those two extremes. Note precisely *where* the reset gate acts: RustyML computes `r_t * h_{t-1}` **before** the candidate's recurrent matmul (`(r_t * h_{t-1}) @ U_h`), which is the original Cho et al. formulation — Keras's `reset_after=False`, not the CuDNN `reset_after=True` variant that applies the reset after the matmul and carries two biases. There is a single bias per gate here.

GRU's `param_count = 3 * (input_dim * units + units * units + units)` — three quarters of an LSTM of the same width. In practice GRU trains a little faster and matches LSTM on many tasks; LSTM sometimes edges ahead when a long, precisely-controlled memory matters. Both initialize their input kernels Xavier/Glorot (with the per-gate fan `input_dim + units`, not the fused width) and each gate's recurrent block as an independent orthogonal matrix.

## 3.7.5. Weights, shapes, and setting them by hand

The trainable tensors and their shapes:

| Layer | kernel | recurrent_kernel | bias | fused column blocks |
|---|---|---|---|---|
| SimpleRNN | `(input_dim, units)` | `(units, units)` | `(1, units)` | none |
| LSTM | `(input_dim, 4 * units)` | `(units, 4 * units)` | `(1, 4 * units)` | `[i \| f \| g \| o]` |
| GRU | `(input_dim, 3 * units)` | `(units, 3 * units)` | `(1, 3 * units)` | `[r \| z \| h]` |

Fusing every gate into one matrix is not cosmetic — it lets the input projection and the recurrent projection run as one large GEMM per timestep instead of one-per-gate, which is a meaningful cache/SIMD win. You can inspect the live arrays through `get_weights()`, which returns a `LayerWeight::{SimpleRNN,LSTM,GRU}` carrying borrowed `kernel`/`recurrent_kernel`/`bias` fields:

```rust
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::layer_weight::LayerWeight;
use rustyml::neural_network::layers::recurrent::LSTM;
use rustyml::neural_network::traits::Layer;

fn main() {
    // input_dim = 4, units = 8. with_random_state makes the init reproducible.
    let lstm = LSTM::new(4, 8, Tanh::new()).unwrap().with_random_state(42);

    match lstm.get_weights() {
        LayerWeight::LSTM(w) => {
            // All 4 gates are fused side by side: width == 4 * units.
            println!("kernel           {:?}", w.kernel.shape()); // [4, 32]
            println!("recurrent_kernel {:?}", w.recurrent_kernel.shape()); // [8, 32]
            println!("bias             {:?}", w.bias.shape()); // [1, 32]
        }
        _ => unreachable!(),
    }
}
```

```text
kernel           [4, 32]
recurrent_kernel [8, 32]
bias             [1, 32]
```

For reproducible initialization, `with_random_state(seed)` re-runs the kernel and recurrent-kernel draws deterministically (the forget-bias-1.0 rule still applies); without it, weights are seeded from the global seed or entropy. See [7.1. Reproducibility and Random Seeds](../Chapter-07/7.1._Reproducibility_and_Random_Seeds.md).

To install weights by hand — porting from another framework, or unit-testing an exact recurrence — every layer has `set_weights(kernel, recurrent_kernel, bias)` taking the fused matrices, and LSTM/GRU additionally have `set_gate_weights(...)` that accepts one `(kernel, recurrent_kernel, bias)` triple *per gate* and concatenates them into the fused layout for you. The per-gate argument order is `(input, forget, cell, output)` for LSTM (twelve arrays) and `(reset, update, candidate)` for GRU (nine arrays). Any shape that does not match returns `Error::NeuralNetwork(NnError::WeightShape { .. })`. When you save or load a whole model these arrays are serialized as-is; see [3.9. Saving and Loading Weights](./3.9._Saving_and_Loading_Weights.md).

## 3.7.6. BPTT and the cost model

Training uses backpropagation through time with a **full unroll** — there is no truncation window. On the forward pass the layer caches everything the backward pass needs: `SimpleRNN` stores every hidden state (with `h_0 = 0` prepended); `LSTM` additionally stores the cell states, `activation(c_t)`, and all four gate activations per timestep; `GRU` stores the reset/update gates, the candidate, and the `r_t * h_{t-1}` product. `predict` passes `None` for those caches and skips the recording (and the clones), which is why inference is cheaper than a training `forward`. Memory therefore scales linearly with `timesteps` — long sequences cost RAM, not just time.

`backward` walks the timesteps in reverse. It expects a 2D upstream gradient `(batch, units)` — the gradient of the loss with respect to the final hidden state — because that final state is the only thing the layer emitted. At each step it computes the per-timestep pre-activation gradient and threads `grad_h` (and `grad_c` for LSTM) back to the previous step; this part is inherently **sequential over time**. It then batches the weight-gradient reductions: the per-timestep `dz` values are collapsed over `(batch, timesteps)` and the kernel/recurrent/bias gradients each fall out of a single large GEMM. Gradients are stored with replace semantics and are **not** clipped inside the layer — if you need gradient clipping, use an optimizer that offers it (see [3.4. Optimizers](./3.4._Optimizers.md)).

The performance shape to keep in mind: **sequential over the time axis, parallel over the batch (and fused gate) axis**. The input projection `x @ W` does not depend on the recurrence, so it is done once as a single batched GEMM across all timesteps up front. Only the `h_{t-1} @ U` term must run step by step, and each of those steps is itself a batch-parallel GEMM. GRU squeezes a little more out of this by fusing the reset and update recurrent projections into one GEMM (they both read `h_{t-1}`); only the candidate's recurrent projection stays separate, because its input `r_t * h_{t-1}` depends on the freshly computed reset gate. Every matmul routes through `gemm_par_auto`, the crate's size-adaptive parallel GEMM ([6.2. Matrix Multiplication](../Chapter-06/6.2._Matrix_Multiplication.md)), so wide layers and large batches get thread parallelism automatically while tiny ones stay serial to avoid overhead. The practical takeaway: throwing more sequences (batch) at a recurrent layer parallelizes well; throwing more timesteps at it does not — that axis is a serial dependency chain. [7.3. Performance Tuning and Parallelism](../Chapter-07/7.3._Performance_Tuning_and_Parallelism.md) covers the thread-pool knobs.

## 3.7.7. Stacking and building a model

Because a recurrent layer returns only the last hidden state — a 2D `(batch, units)` tensor — you **cannot** feed its output straight into another recurrent layer, which demands a 3D `(batch, timesteps, features)` input and would reject the 2D tensor with `Error::InvalidInput`. With no `return_sequences` option there is no way to emit a per-timestep sequence, so deep stacks of recurrent layers in the Keras sense are not expressible here. This is a genuine limitation to plan around, not a detail to gloss over.

The idiomatic pattern is therefore a recurrent layer as a sequence encoder followed by a dense head that maps the final state to your targets. That composes cleanly: the recurrent layer turns `(batch, timesteps, features)` into `(batch, units)`, and `Dense` consumes exactly that 2D shape. The example below learns a genuine sequence task — predict the sum of a length-3 scalar sequence — with an `LSTM` encoder, a `Dense` readout, `Adam`, and mean-squared error. It converges in a few hundred full-batch epochs (recall from [3.1. The Sequential Model](./3.1._The_Sequential_Model.md) that `fit` is one full-batch gradient step per epoch):

```rust
use ndarray::Array;
use rustyml::neural_network::sequential::Sequential;
use rustyml::prelude::*;

fn main() {
    // 4 sequences, 3 timesteps, 1 feature. Target = sum of the 3 scalars.
    let x = Array::from_shape_vec(
        (4, 3, 1),
        vec![
            0.1, 0.2, 0.1, // sum 0.4
            0.3, 0.1, 0.2, // sum 0.6
            0.0, 0.2, 0.2, // sum 0.4
            0.2, 0.2, 0.1, // sum 0.5
        ],
    )
    .unwrap()
    .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![0.4, 0.6, 0.4, 0.5])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        // Recurrent feature extractor: (batch, 3, 1) -> (batch, 16)
        .add(LSTM::new(1, 16, Tanh::new()).unwrap().with_random_state(42))
        // Read the last hidden state out to a single scalar.
        .add(Dense::new(16, 1, Linear::new()).unwrap())
        .compile(
            Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    model.fit(&x, &y, 300).unwrap();

    let pred = model.predict(&x).unwrap();
    println!("target      : {:?}", y.as_slice().unwrap());
    println!("prediction  : {:?}", pred.as_slice().unwrap());
}
```

After 300 epochs the four predictions land within a few percent of `[0.4, 0.6, 0.4, 0.5]` — the LSTM has learned to accumulate the sequence and the dense head reads the accumulator out. Swap `LSTM` for `GRU` or `SimpleRNN` and the same harness still compiles and trains; on this trivially short sequence all three converge, which is exactly why the vanishing-gradient advantage of the gated cells only shows up once the sequences get long. `model.summary()` prints each recurrent layer's output shape as `(None, units)`, the `None` standing in for the dynamic batch dimension. For anything larger than a toy dataset, prefer `fit_with_batches` over `fit` so each epoch takes several mini-batch steps and reshuffles.
