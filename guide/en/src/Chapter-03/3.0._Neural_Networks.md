# 3. Neural Networks

RustyML ships a small, Keras-shaped deep-learning framework written in pure Rust: you stack layers into a [`Sequential`](./3.1._The_Sequential_Model.md) model, `compile` it with an optimizer and a loss, and call `fit`/`predict`. Every tensor that flows through it is a `Tensor`, which is just `ndarray::ArrayD<f32>` — single-precision, dynamic rank, no GPU, no autograd tape. Each layer implements forward and backward by hand and hands its parameters to the optimizer through a flat view, so the whole thing is deterministic and debuggable. If you have used Keras you will recognize the shape of the API immediately; the differences (strict `f32`, explicit input dimensions, `Result`-returning constructors) are what this chapter exists to explain.

Before starting here, read [Chapter 1](../Chapter-01/1.0._Getting_Started.md) — especially [Working with ndarray](../Chapter-01/1.3._Working_with_ndarray.md), [Installation and Feature Flags](../Chapter-01/1.2._Installation_and_Feature_Flags.md) (the `neural_network` feature gates this whole module), and [Error Handling](../Chapter-01/1.6._Error_Handling.md), since layer and loss constructors return `Result`. The end-to-end shape of a model is:

```rust
use rustyml::neural_network::{
    sequential::Sequential,
    layers::{Activation, Dense},
    optimizers::Adam,
    losses::MeanSquaredError,
};
use ndarray::Array;

fn main() {
    let x = Array::ones((8, 4)).into_dyn(); // 8 samples, 4 features
    let y = Array::ones((8, 1)).into_dyn(); // 8 samples, 1 target

    let mut model = Sequential::new();
    model
        .add(Dense::new(4, 16, Activation::ReLU).unwrap())
        .add(Dense::new(16, 1, Activation::Linear).unwrap())
        .compile(
            Adam::new(0.001, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    model.fit(&x, &y, 5).unwrap();
    let preds = model.predict(&x).unwrap();
    println!("prediction shape: {:?}", preds.shape());
}
```

[The Sequential Model](./3.1._The_Sequential_Model.md) is the container that turns a pile of layers into a trainable network. It owns the training loop, the optimizer, and the loss, and exposes `add`, `compile`, `fit`, `predict`, `summary`, and weight save/load. It also holds the batch-shuffle seed (`set_seed`) and the learning-rate hook (`set_learning_rate`). Start here even if you only came for one specific layer.

[Dense Layers and Activations](./3.2._Dense_Layers_and_Activations.md) covers the fully connected layer — the workhorse of tabular models and the output stage of most networks — and the `Activation` enum (`ReLU`, `Sigmoid`, `Tanh`, `Softmax`, `Linear`) you fold into it or drop in as a standalone layer. Read this second; everything downstream assumes you know how a `Dense` layer declares its `input_dim` and `units`.

[Loss Functions](./3.3._Loss_Functions.md) is the objective half of `compile`: mean squared error and mean absolute error for regression, and binary, categorical, and sparse-categorical cross-entropy for classification. The section is worth reading closely because the averaging conventions differ on purpose (per-element vs per-prediction-site), which quietly rescales your effective learning rate when you switch families, and the cross-entropy losses take a `from_logits` flag that changes whether you need a `Softmax` on the output.

[Optimizers](./3.4._Optimizers.md) is the update half of `compile`: SGD with momentum, Adam, AdamW, RMSprop, and AdaGrad. This is where clip-by-global-norm (`clip_norm`), coupled vs decoupled weight decay, and mid-training learning-rate scheduling live. Together, 3.1 through 3.4 give you a complete, trainable feed-forward network.

The remaining sections add specialized layers, all of which plug into the same `Sequential`. [Convolutional Layers](./3.5._Convolutional_Layers.md) provides 1D/2D/3D convolution plus depthwise and separable variants for spatial data. [Pooling Layers](./3.6._Pooling_Layers.md) provides parameter-free max/average downsampling and their global variants. [Recurrent Layers](./3.7._Recurrent_Layers.md) covers `SimpleRNN`, `LSTM`, and `GRU` for sequences. [Regularization and Normalization Layers](./3.8._Regularization_and_Normalization_Layers.md) covers dropout (including spatial), Gaussian noise, and batch/layer/group/instance normalization — the mode-dependent layers that behave differently in `fit` than in `predict`, which the model switches for you.

[Saving and Loading Weights](./3.9._Saving_and_Loading_Weights.md) closes the chapter. `save_to_path`/`load_from_path` persist weights only, in postcard binary, not the architecture — so you rebuild the identical layer stack in code, then load. Read it once you have a model worth keeping, and see [Model Persistence in Depth](../Chapter-07/7.2._Model_Persistence_in_Depth.md) for the format details and versioning caveats.
