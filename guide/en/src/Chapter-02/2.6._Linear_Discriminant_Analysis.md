# 2.6. Linear Discriminant Analysis

Linear Discriminant Analysis wears two hats from a single fit. It is a generative classifier — it models each class as a Gaussian with its own mean but a covariance shared across all classes, then applies Bayes' rule to pick the most probable label — and it is a supervised dimensionality reducer that projects your features onto the directions that separate the classes best. RustyML's `LDA` gives you both from one `fit` call: `predict` (plus `decision_function` and `predict_proba`) for the classifier, and `transform` / `fit_transform` for the projection. This page covers the real API, the in-house linear algebra behind it, the Gaussian assumptions you are signing up for, and what actually happens when your covariance goes singular.

## 2.6.1. What the crate implements

Everything lives under `rustyml::machine_learning::{LDA, Shrinkage, Solver}` (also re-exported through [the prelude](../Chapter-01/1.5._The_Prelude_and_Imports.md)). The model takes an `f64` feature matrix and `i32` labels — LDA is a classifier, so labels are integer class ids, not floats. Here is the surface you work with:

| Method | Signature (abridged) | Returns |
| --- | --- | --- |
| `LDA::new` | `new(n_components: usize)` | `Result<LDA, Error>` |
| `LDA::default` | `default()` | `LDA` (auto components) |
| `with_solver` | `with_solver(Solver)` | `LDA` |
| `with_shrinkage` | `with_shrinkage(Shrinkage)` | `Result<LDA, Error>` |
| `fit` | `fit(&x, &y)` where `y: &Array1<i32>` | `Result<&mut LDA, Error>` |
| `predict` | `predict(&x)` | `Result<Array1<i32>, Error>` |
| `decision_function` | `decision_function(&x)` | `Result<Array2<f64>, Error>` |
| `predict_proba` | `predict_proba(&x)` | `Result<Array2<f64>, Error>` |
| `transform` | `transform(&x)` | `Result<Array2<f64>, Error>` |
| `fit_transform` | `fit_transform(&x, &y)` | `Result<Array2<f64>, Error>` |

There is no QDA (quadratic discriminant analysis) in the crate — the shared-covariance, linear-boundary variant is the only one. Getters `get_classes`, `get_priors`, `get_means`, and `get_projection` return `None` before `fit` and `Some(&…)` after, which is the cleanest way to check whether a model is trained.

## 2.6.2. A first classifier

Start with three well-separated clusters in 2D. `LDA::default()` resolves the component count automatically, so you do not have to think about projection when you only want labels.

```rust
use ndarray::array;
use rustyml::machine_learning::LDA;

fn main() {
    // Three tight, well-separated clusters, 3 samples each.
    let x = array![
        [1.0, 1.0], [1.5, 0.8], [0.8, 1.2],
        [5.0, 5.0], [5.2, 4.8], [4.8, 5.2],
        [9.0, 1.0], [9.2, 0.8], [8.8, 1.2],
    ];
    let y = array![0, 0, 0, 1, 1, 1, 2, 2, 2];

    let mut lda = LDA::default();
    lda.fit(&x, &y).unwrap();

    let preds = lda.predict(&x).unwrap();
    println!("predictions: {:?}", preds);

    // Per-class discriminant scores (n_samples, n_classes) and softmax posteriors.
    let scores = lda.decision_function(&x).unwrap();
    let proba = lda.predict_proba(&x).unwrap();
    println!("scores shape:   {:?}", scores.shape());
    println!("proba shape:    {:?}", proba.shape());
    println!("class order:    {:?}", lda.get_classes().unwrap());
}
```

The three prediction entry points share one core. For a sample `x`, LDA computes a linear discriminant score per class, `score_j(x) = x · (Σ⁻¹ μ_j) − 0.5 · μ_j · Σ⁻¹ μ_j + ln(prior_j)`, where `Σ` is the shared covariance, `μ_j` the class mean, and `prior_j` the class frequency in the training set. `decision_function` returns those raw scores as an `(n_samples, n_classes)` matrix; `predict` is its per-row argmax mapped back to the original label; `predict_proba` is a numerically stable row-wise softmax of the same scores, so each row is a valid distribution that sums to 1. The column order of `decision_function` and `predict_proba` follows `get_classes()`, which is sorted ascending — do not assume it matches the order labels first appeared in `y`.

Priors here are pure class frequencies (`n_class / n_samples`), so they are `1/3, 1/3, 1/3` for this balanced set. That matters when your training classes are imbalanced: the `ln(prior_j)` term shifts the boundary toward the rarer class, exactly as a Bayes classifier should. If you need equal priors, balance your training set — there is no `priors=` override on the constructor.

## 2.6.3. Supervised projection and the n_classes − 1 ceiling

The projection side is what distinguishes LDA from PCA. LDA finds directions that maximize between-class scatter relative to within-class scatter, and there are only `n_classes − 1` such directions with non-zero separability (the between-class scatter matrix has rank at most `n_classes − 1`). The crate enforces this: the usable component count is `min(n_classes − 1, n_features)`, resolved at fit time. `LDA::default()` (or `n_components = None`) takes that maximum; `LDA::new(k)` requests exactly `k` and errors at `fit` if `k` exceeds the cap.

For a 2D scatter plot you therefore need at least three classes, since two classes give you only one discriminant axis. `fit_transform` trains and projects in one call:

```rust
use ndarray::array;
use rustyml::machine_learning::{LDA, Shrinkage, Solver};

fn main() {
    let x = array![
        [1.0, 1.0], [1.5, 0.8], [0.8, 1.2],
        [5.0, 5.0], [5.2, 4.8], [4.8, 5.2],
        [9.0, 1.0], [9.2, 0.8], [8.8, 1.2],
    ];
    let y = array![0, 0, 0, 1, 1, 1, 2, 2, 2];

    // 3 classes -> at most 2 discriminant axes; project straight to 2D.
    let mut lda = LDA::new(2)
        .unwrap()
        .with_solver(Solver::Eigen)
        .with_shrinkage(Shrinkage::Auto)
        .unwrap();

    let coords = lda.fit_transform(&x, &y).unwrap(); // (9, 2)
    println!("embedding shape: {:?}", coords.shape());
    for (row, &label) in coords.outer_iter().zip(y.iter()) {
        println!("class {label}: ({:.3}, {:.3})", row[0], row[1]);
    }

    // The projection matrix maps n_features -> n_components; its columns are unit vectors.
    let w = lda.get_projection().unwrap();
    println!("projection shape: {:?}", w.shape()); // [2, 2]
}
```

```text
embedding shape: [9, 2]
projection shape: [2, 2]
```

The projection matrix `W` has shape `(n_features, n_components)`; `transform` is just `x · W`. Each column is normalized to unit L2 norm, and the columns are ordered by class separability (largest generalized eigenvalue first), so the first component is the single most discriminative axis — useful if you later want a 1D reduction from the same fit. Because a discriminant axis and its negation separate the classes equally well, the sign of any column is arbitrary; treat the orientation of a plotted axis as meaningless and never read directionality into it.

`transform` and `fit_transform` are the same reduction step; `fit_transform(&x, &y)` is exactly `fit(&x, &y)` followed by `transform(&x)`, just without re-validating twice.

## 2.6.4. Solvers and the in-house linear algebra

`Solver` selects how the shared covariance is inverted for the classifier's scoring coefficients `Σ⁻¹ μ_c`. The important and easily-missed fact: the solver only affects `predict` / `decision_function` / `predict_proba`. The `transform` projection is solver-independent — it is always derived from a symmetric eigendecomposition of the within-class covariance — so switching solvers changes your decision boundary's numerics but never your 2D embedding.

| `Solver` | How it scores | When to reach for it |
| --- | --- | --- |
| `SVD` (default) | SVD pseudo-inverse of `Σ`, small singular values truncated | General default; most robust to rank deficiency |
| `Eigen` | Symmetric eigendecomposition inverse, tiny eigenvalues zeroed | Well-conditioned covariance; comparable to `SVD` |
| `LSQR` | Iterative Paige–Saunders least squares, forms no explicit inverse | Very high dimension where materializing an inverse is wasteful |

All three reach identical labels on well-separated data; they differ only in how they cope with an ill-conditioned `Σ`. `SVD` and `Eigen` both build a pseudo-inverse that discards directions whose singular value / eigenvalue falls below a relative tolerance, so a rank-deficient covariance degrades gracefully rather than blowing up. `LSQR` sidesteps the inverse entirely by solving each `Σ · coef_c = μ_c` system iteratively, which is the memory-frugal choice when `n_features` is large.

The linear algebra is entirely in-house pure Rust — RustyML deliberately carries no LAPACK or `nalgebra` dependency (see [prefer in-house numerics](../Chapter-06/6.0._Math_Utilities.md)). The symmetric eigendecomposition is Householder tridiagonalization followed by the implicit-shift QL iteration (the classic EISPACK `tred2`/`tql2` pair); the SVD is a one-sided Jacobi method that computes small singular values to high relative accuracy; `LSQR` is the Golub–Kahan bidiagonalization with running Givens rotations. These are deterministic to machine precision on the small-to-mid covariance matrices LDA produces, which is why LDA needs no random seed.

## 2.6.5. Shrinkage and covariance regularization

With few samples per feature, the raw sample covariance is a noisy estimate and its inverse amplifies that noise. Shrinkage pulls `Σ` toward a scaled identity to trade a little bias for a lot of variance reduction. `Shrinkage` has two forms:

- `Shrinkage::Auto` — the Ledoit–Wolf closed-form optimal intensity, computed from the data, no tuning knob.
- `Shrinkage::Manual(alpha)` — an explicit `alpha ∈ [0, 1]`, where `0` is no shrinkage and `1` shrinks fully to the identity target. `with_shrinkage` validates this and returns `Error::InvalidParameter` if `alpha` is outside `[0, 1]` or not finite, which is why it returns a `Result`.

Two subtleties worth knowing. First, RustyML always adds a tiny fixed diagonal ridge (about `1e-6 ×` the average variance) to the covariance regardless of your shrinkage choice, purely to keep the factorizations stable; `Shrinkage::Manual(0.0)` and no shrinkage at all therefore produce identical results. Second — and this is a real divergence from scikit-learn — shrinkage here is orthogonal to the solver. scikit-learn refuses shrinkage with its `svd` solver; RustyML applies shrinkage to the covariance before any solver runs, so `Solver::SVD` with `Shrinkage::Auto` is perfectly valid and often what you want. Prefer `Shrinkage::Auto` as your default whenever you have collinear features or a thin sample-to-feature ratio.

## 2.6.6. Assumptions, and the symptoms when they break

LDA's optimality rests on two assumptions: each class is Gaussian, and all classes share one covariance matrix. The shared covariance is what makes the decision boundary linear — the quadratic terms cancel. When the assumptions hold, LDA is remarkably data-efficient because it estimates one covariance from all classes pooled together instead of one per class.

When they break, the symptoms are specific. If the classes have genuinely different covariances (heteroscedastic — one class is a tight blob, another a broad cloud), the true Bayes boundary is quadratic, and LDA's forced-linear boundary systematically misclassifies in the region where the spreads differ: the wide class tends to "swallow" territory near the boundary. There is no QDA in the crate to fall back on, so for strongly heteroscedastic data reach for a non-linear classifier — a [decision tree](./2.4._Decision_Trees.md), an [SVM with an RBF kernel](./2.5._Support_Vector_Machines.md), or a [KNN classifier](./2.3._K_Nearest_Neighbors.md). If a class is multimodal or plainly non-Gaussian, the projection can fail to separate it even though the classifier still limps along; inspect a `transform` scatter before trusting the reduction.

## 2.6.7. Singular covariance and high dimensions

The scope question most people ask: what happens when features are collinear, or when `n_features > n_samples`, so the covariance is singular? RustyML does **not** raise a dedicated "singular matrix" error. There is no guard on `n_features` versus `n_samples` at all — the only sample-count check is that `n_samples` must exceed `n_classes` and each class needs at least two samples. A rank-deficient covariance is absorbed two ways: the always-on diagonal ridge nudges it toward invertibility, and the `SVD`/`Eigen` pseudo-inverse (and the whitening step inside the projection) simply zero out the directions whose eigenvalue falls below a relative tolerance, projecting onto the covariance's non-null subspace instead of dividing by ~0.

```rust
use ndarray::array;
use rustyml::machine_learning::LDA;

fn main() {
    // The third column is the sum of the first two: the feature matrix is
    // rank-deficient, so the shared covariance is singular.
    let x = array![
        [1.0, 2.0, 3.0],
        [1.5, 2.5, 4.0],
        [2.0, 3.0, 5.0],
        [6.0, 5.0, 11.0],
        [6.5, 4.5, 11.0],
        [7.0, 5.5, 12.5],
    ];
    let y = array![0, 0, 0, 1, 1, 1];

    // No singular-matrix error: the ridge + pseudo-inverse absorb the rank deficiency.
    let mut lda = LDA::default();
    lda.fit(&x, &y).unwrap();

    let coords = lda.transform(&x).unwrap(); // (6, 1): 2 classes -> 1 component
    assert!(coords.iter().all(|v| v.is_finite()));
    println!("reduced to {:?}, all finite", coords.shape());
}
```

The one place the projection can still bail is `Error::Computation("Discriminant direction norm too small for stable projection")`, raised only if a selected discriminant axis collapses to a near-zero vector — which happens when you demand more components than the data can support in its degenerate subspace. That is a hard numerical failure, not a validation slip, so treat it as a signal to reduce `n_components` or regularize harder. For `n_features > n_samples` or heavily collinear data, do not rely on the fixed `1e-6` ridge alone; turn on `Shrinkage::Auto`, which conditions the covariance far better than the minimal stabilizer and is the difference between a usable projection and one dominated by noise directions.

## 2.6.8. LDA versus PCA versus logistic regression

Three neighbors are worth contrasting directly, because the choice among them is usually the real question.

| | Supervised? | Boundary / axes | Assumptions | Component ceiling |
| --- | --- | --- | --- | --- |
| **LDA** | Yes (uses labels) | Directions of max class separation | Gaussian classes, shared covariance | `n_classes − 1` |
| [**PCA**](./2.10._Principal_Component_Analysis.md) | No (ignores labels) | Directions of max total variance | None (just second moments) | `n_features` |
| [**Logistic regression**](./2.2._Logistic_Regression.md) | Yes | Linear decision boundary only | None on class shape | (not a reducer) |

PCA maximizes variance without ever looking at `y`, so its top components can happily align with the direction that separates classes *least* if that is where the spread lives; LDA maximizes separation directly but is capped at `n_classes − 1` axes. Reach for LDA when you want a supervised low-dimensional view or a fast generative classifier and your classes are roughly Gaussian; reach for PCA when you want an unsupervised compression or need more than `n_classes − 1` dimensions.

Against logistic regression the split is generative versus discriminative. LDA models the class-conditional densities and applies Bayes' rule; logistic regression models `P(y | x)` directly and makes no assumption about the shape of each class. When the Gaussian/equal-covariance assumptions genuinely hold, LDA converges to a good boundary from fewer samples. When they do not, logistic regression is the more robust linear classifier because it never committed to a class shape in the first place. A common workflow is to keep both around and let held-out accuracy — measured with the [classification metrics](../Chapter-05/5.2._Classification_Metrics.md) — decide.

## 2.6.9. Errors, persistence, and reproducibility

The error surface follows the crate-wide [error handling](../Chapter-01/1.6._Error_Handling.md) conventions. `LDA::new(0)` is an `Error::InvalidParameter` (components must be positive). An out-of-range `Shrinkage::Manual` is also `InvalidParameter`, caught at build time. Structural problems surface at `fit`: fewer than two classes, `n_samples ≤ n_classes`, a class with only one sample, and an over-large `n_components` are all `Error::InvalidInput`; a non-finite entry in `x` is `Error::NonFinite`; an `x`/`y` length disagreement is `Error::DimensionMismatch`. At predict or transform time, a wrong feature count is `Error::DimensionMismatch` and an unfitted model is `Error::NotFitted("LDA")`.

```rust
use ndarray::array;
use rustyml::error::Error;
use rustyml::machine_learning::{LDA, Shrinkage};

fn main() {
    // Manual shrinkage must lie in [0, 1]; 1.5 is rejected when you build the model.
    match LDA::new(1).unwrap().with_shrinkage(Shrinkage::Manual(1.5)) {
        Err(Error::InvalidParameter { name, .. }) => println!("rejected parameter: {name}"),
        _ => unreachable!(),
    }

    // n_components is only bounded once the class count is known, so an over-large
    // request survives the constructor and fails at fit.
    let x = array![
        [1.0, 1.0], [1.5, 0.8], [0.8, 1.2],
        [5.0, 5.0], [5.2, 4.8], [4.8, 5.2],
    ];
    let y = array![0, 0, 0, 1, 1, 1]; // 2 classes -> max_components = 1
    let mut lda = LDA::new(2).unwrap();
    match lda.fit(&x, &y) {
        Err(Error::InvalidInput(msg)) => println!("fit rejected: {msg}"),
        _ => unreachable!(),
    }
}
```

A fitted `LDA` serializes with `save_to_path` / `load_from_path`, which use postcard binary (the `.bin` here is just a filename — the format is binary regardless of extension). The round-trip restores classes, priors, means, projection, and the cached scoring coefficients, so a loaded model predicts and transforms identically without a re-fit. See [model persistence in depth](../Chapter-07/7.2._Model_Persistence_in_Depth.md) for the format details.

```rust
use ndarray::array;
use rustyml::machine_learning::LDA;
use std::fs;

fn main() {
    let x = array![
        [1.0, 1.0], [1.5, 0.8], [0.8, 1.2],
        [5.0, 5.0], [5.2, 4.8], [4.8, 5.2],
        [9.0, 1.0], [9.2, 0.8], [8.8, 1.2],
    ];
    let y = array![0, 0, 0, 1, 1, 1, 2, 2, 2];

    let mut lda = LDA::new(2).unwrap();
    lda.fit(&x, &y).unwrap();
    let before = lda.predict(&x).unwrap();

    let path = "lda_model.bin";
    lda.save_to_path(path).unwrap();
    let loaded = LDA::load_from_path(path).unwrap();
    let after = loaded.predict(&x).unwrap();

    assert_eq!(before, after);
    fs::remove_file(path).unwrap();
    println!("round-trip predictions identical");
}
```

LDA is fully deterministic: it draws no random numbers, so the same data yields the same projection, coefficients, and labels every run — no seed to set (contrast the stochastic models in [reproducibility and random seeds](../Chapter-07/7.1._Reproducibility_and_Random_Seeds.md)). The only run-to-run freedom is the arbitrary sign of each discriminant axis, which is a mathematical property of eigenvectors, not nondeterminism. Fitting parallelizes the per-class statistics and the final label scan once the work clears the crate's calibrated threshold, but parallelism never changes the result — it only changes how fast you get it, which is the topic of [performance tuning and parallelism](../Chapter-07/7.3._Performance_Tuning_and_Parallelism.md).
