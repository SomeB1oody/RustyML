# 3.8. 正则化与归一化层

本页讲的这些层，与其说在学习某种映射，不如说在重塑流经网络的信号：dropout 及其空间变体、两个高斯噪声层，以及四个归一化层（batch、layer、group、instance）。它们同住在 `rustyml::neural_network::layers::regularization` 里，原因很具体——每一个在训练时的行为都跟推理时不同，而 crate 把这个区别抽出来，落到一套共享机制上。先把这套机制弄明白，本页余下的内容就都是细节；没搞懂，尤其是 batch normalization，会悄悄给你算出错误的数字。如果你从[全连接层与激活函数](./3.2._全连接层与激活函数.md)一路读过来，这里的每个层都用同一个 `.add(...)` 调用接进 [`Sequential`](./3.1._Sequential模型.md) 模型，而每个构造函数都返回 `Result`，理由见[错误处理](../Chapter-01/1.6._错误处理.md)。

全部通过 `use rustyml::neural_network::layers::*;` 导入，它重新导出了 `Dropout`、`SpatialDropout1D`/`2D`/`3D`、`GaussianNoise`、`GaussianDropout`、`BatchNormalization`、`LayerNormalization`（连同它的 `LayerNormalizationAxis`）、`GroupNormalization` 和 `InstanceNormalization`。和这个 crate 里到处一样，`Tensor` 就是 `ndarray::ArrayD<f32>`——单精度、动态秩。

## 3.8.1. 训练模式与推理模式

每个依赖模式的层都持有一个私有的 `training: bool` 标志，并暴露两种前向执行方式。[`Layer`](./3.1._Sequential模型.md) trait 同时定义了它们：

```rust,ignore
fn forward(&mut self, input: &Tensor) -> Result<Tensor, Error>;   // 记录缓存，尊重标志
fn predict(&self, input: &Tensor) -> Result<Tensor, Error>;       // 始终走求值路径，不写缓存
```

`forward` 接收 `&mut self`，查看 `training` 标志，并把反向传播需要的一切都存下来（掩码、batch 统计量、噪声抽样）。`predict` 接收 `&self`，始终走推理路径，什么也不记录——正因如此，编译好的模型可以跨线程共享，用于并发服务。翻转这个标志用 `set_training_if_mode_dependent(is_training)`（trait 方法）或固有方法 `set_training(is_training)`；那些不关心模式的层（Dense、激活、池化）继承的是一个空操作，两个方法它们都会忽略。

在 `Sequential` 内部，你几乎从不需要自己碰这个标志。`fit`/`fit_with_batches` 会把每一层设为训练模式并调用 `forward`；`predict` 则调用每一层的 `predict`。真正的坑是手动调用 `forward` 来做推理：一个标志仍为 `true` 的 `BatchNormalization` 层，会拿你的“测试” batch 去算 batch 统计量，还会改动它的滑动平均——所以凡是不属于训练步骤的场合，都用 `model.predict(...)`，或者把标志设为 `false`。下表精确列出每一族在各个模式下的行为：

| 层 | 训练模式下的 `forward` | 推理 / `predict` 下的 `forward` | 推理模式下的 `backward` |
| --- | --- | --- | --- |
| `Dropout`、`SpatialDropout*` | 丢弃一部分单元，对存活的重新缩放 | 恒等（原样透传） | 梯度原样透传 |
| `GaussianNoise` | 加上 `N(0, stddev²)` | 恒等 | 梯度原样透传 |
| `GaussianDropout` | 乘以 `N(1, σ)` | 恒等 | 梯度原样透传 |
| `BatchNormalization` | 用 **batch** 统计量归一化，更新滑动统计量 | 用**滑动**统计量归一化 | 梯度原样透传 |
| `LayerNormalization`、`GroupNormalization`、`InstanceNormalization` | 用当前输入算出的统计量归一化 | 用当前输入算出的**同样**统计量 | 梯度原样透传 |

最后一行值得盯着看：layer、group 和 instance normalization 在任何模式下都从当前输入计算统计量，所以无论标志开还是关，它们的 `forward` 输出都一样，`predict` 和 `forward` 逐位相等。只有它们的反向传播感知模式——推理模式下它原样返回上游梯度，而不去跑真正的梯度。batch normalization 是这里唯一持有状态（滑动均值与方差）的层，因此它在两个模式下确实会算出不同的东西。

## 3.8.2. Dropout

`Dropout::new(rate, input_shape)` 构造经典的 dropout 层。`rate` 是要置零的单元比例，必须落在闭区间 `[0.0, 1.0]` 内（越界会返回 `Error::InvalidParameter`）；`input_shape` 会对照每个输入做校验，但只校验秩和逐样本的那些轴——第 0 维是 batch，它随调用 `forward` 的人而变，因此从不参与比较，于是一个声明为 `vec![4, 8]` 的层接受任意大小的 batch，却仍会拒掉宽度不是 8 的行。通配的 `vec![]` 则把这项校验整个关掉。实现采用的是 **inverted dropout**：训练 `forward` 时，它抽一个均匀掩码，以概率 `1 - rate` 保留每个单元，再把存活的单元乘上 `1 / (1 - rate)`，于是激活的期望值保持不变。这个缩放正是关键所在——它让推理成为纯粹的恒等映射（`predict` 原样返回输入），服务时无需再记着做任何缩放。两个边界值会短路：`rate == 0.0` 是恒等，`rate == 1.0` 把一切都置零。

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // 50% 的丢弃率，期望 [4, 8] 的输入；给掩码播种，让这次运行可复现。
    let mut dropout = Dropout::new(0.5, vec![4, 8]).unwrap().with_random_state(7);
    let input = Array::ones((4, 8)).into_dyn();

    // 训练：大约一半单元变为 0，存活的变为 1/(1-0.5) = 2.0。
    dropout.set_training_if_mode_dependent(true);
    let train_out = dropout.forward(&input).unwrap();
    let kept = train_out.iter().filter(|&&v| v != 0.0).count();
    println!("kept {kept}/{} units, each rescaled to 2.0", input.len());

    // 推理：inverted dropout 让这个层成为恒等映射。
    dropout.set_training_if_mode_dependent(false);
    assert_eq!(dropout.forward(&input).unwrap(), input);

    // predict() 无论标志如何都走求值路径，且从不缓存掩码。
    assert_eq!(dropout.predict(&input).unwrap(), input);
}
```

掩码抽自每层独立的 `StdRng`。默认情况下 `Dropout::new` 用全局种子给它播种（没设全局种子就取自系统熵）；`with_random_state(seed)` 则用确定的种子重新播种。由于 RNG 每抽一次就往前推进，连续两次训练 `forward` 会产生不同的掩码——播种固定的是跨进程运行的*序列*，而不是两次调用之间的相等性。全局种子如何贯穿每个随机化组件，见[可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)。Dropout 没有可训练参数；在 `forward` 之前调用 `backward`（此时没有缓存掩码）会返回 `NnError::ForwardPassNotRun`；在推理模式下或 `rate == 0.0` 时，反向传播只是把梯度原样透传。

## 3.8.3. 面向特征图的空间 Dropout

普通 dropout 并不适合卷积特征图。一个通道内相邻的像素高度相关，所以零星地把单个元素置零几乎抹不掉多少信息——被丢掉的像素值基本能从邻居那里恢复回来，正则化效果也就被稀释了。`SpatialDropout1D`、`SpatialDropout2D` 和 `SpatialDropout3D` 的做法是一次丢弃一整个通道：某个通道被丢弃时，它所有的空间位置一起归零，逼着网络不去依赖任何单一的特征图。这对应 Keras 的 `SpatialDropout*`。

这三者只在期望的秩上有区别，全部采用 channels-last 布局：`SpatialDropout1D` 要三维 `(batch, length, channels)`，`SpatialDropout2D` 要四维 `(batch, height, width, channels)`，`SpatialDropout3D` 要五维 `(batch, depth, height, width, channels)`。秩不对会返回 `Error::InvalidInput`。它们内部为每个 `(batch, channel)` 抽一个保留/丢弃值——一个小小的 `[batch, channels]` 掩码——然后对整个通道套用同样的 `1 / (1 - rate)` inverted-dropout 缩放，所以从不会实体化一个满尺寸的掩码。构造、播种（`with_random_state`）、边界行为，以及 `ForwardPassNotRun` 的约定，都跟普通 `Dropout` 一致；错误里甚至会点明具体的层，所以在 `SpatialDropout2D` 上过早调用 backward 会报 `ForwardPassNotRun("SpatialDropout2D")`。

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // (batch=1, channels=8, height=4, width=4)：整个通道作为一个整体被丢弃。
    let mut sd = SpatialDropout2D::new(0.5, vec![1, 8, 4, 4]).unwrap().with_random_state(3);
    sd.set_training_if_mode_dependent(true);

    let input = Array::ones((1, 8, 4, 4)).into_dyn();
    let out = sd.forward(&input).unwrap();

    // 同一通道内的每个位置共享同一个值：0.0（被丢弃）或 2.0（保留并重新缩放）。
    for c in 0..8 {
        let first = out[[0, c, 0, 0]];
        let uniform = (0..4).all(|h| (0..4).all(|w| out[[0, c, h, w]] == first));
        println!("channel {c}: value {first}, uniform across the map = {uniform}");
    }
}
```

## 3.8.4. 高斯噪声与高斯 Dropout

有两个层靠注入噪声而非置零来做正则化。`GaussianNoise::new(stddev, input_shape)` 是**加性**的：训练时它加上零均值的 `N(0, stddev²)` 噪声，`output = input + noise`。这是一种数据增强风味的正则化——它扰动输入却不改变其期望值，但确实抬高了方差，而且 `stddev` 足够大时，一个正的输入可能变负。`stddev` 必须非负且有限（负值或 `NaN`/`Inf` 会在构造时被拒绝，这是有意为之：否则它会在第一次前向时于采样器内部 panic）。它的反向传播在任何模式下都是纯透传，因为噪声与输入独立，所以 `d(x + noise)/dx = 1`；它不缓存任何东西，也从不返回 `ForwardPassNotRun`。

`GaussianDropout::new(rate, input_shape)` 是**乘性**的，跟普通 dropout 更接近。它给每个输入乘上一个来自 `N(1, σ)` 的抽样，其中 `σ = sqrt(rate / (1 - rate))`，于是这个均值为 1 的噪声让 `E[output] = input`——跟 inverted dropout 保持期望不变是同一个思路，只不过用连续的乘数代替了硬性置零。这里 `rate` 必须落在 `[0.0, 1.0)`——不含 1，因为 `rate → 1` 时 `σ` 会发散。跟 `GaussianNoise` 不同，它会缓存确切的噪声抽样，好让反向传播复用（`y = x * noise ⇒ dx = grad * noise`）；在任何训练前向之前调用 backward 会返回 `ForwardPassNotRun`。两个层在推理时都是恒等映射（`stddev`/`rate` 为 0 时也一样），且都没有可训练参数。

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    let input = Array::from_elem((2, 4), 3.0_f32).into_dyn();

    // 加性：output = input + N(0, 0.5^2)。均值保持，方差增加。
    let mut noise = GaussianNoise::new(0.5, vec![2, 4]).unwrap().with_random_state(1);
    noise.set_training_if_mode_dependent(true);
    let noisy = noise.forward(&input).unwrap();

    // 乘性：output = input * N(1, sqrt(rate/(1-rate)))。E[output] 仍等于 input。
    let mut gdrop = GaussianDropout::new(0.3, vec![2, 4]).unwrap().with_random_state(1);
    gdrop.set_training_if_mode_dependent(true);
    let scaled = gdrop.forward(&input).unwrap();

    println!("additive[0] = {}, multiplicative[0] = {}", noisy[[0, 0]], scaled[[0, 0]]);

    // 两者在服务时都是恒等映射。
    noise.set_training_if_mode_dependent(false);
    gdrop.set_training_if_mode_dependent(false);
    assert_eq!(noise.forward(&input).unwrap(), input);
    assert_eq!(gdrop.forward(&input).unwrap(), input);
}
```

## 3.8.5. 归一化层速览

四个归一化层共用一副骨架：各自减去一个均值，再除以在某组轴上算出的标准差，然后套一个可学习的、逐通道的仿射变换 `gamma * x_normalized + beta`。`gamma` 初始化为全 1，`beta` 初始化为全 0，两者都作为可训练参数暴露给优化器（并被标记为 no-decay，于是权重衰减会跳过它们——归一化的缩放/平移可不是你想往零拉的东西）；每个层还接收一个 `epsilon`（通常是 `1e-5`），加在平方根下面以保证数值稳定，这也正是让零方差输入产生有限的全零输出、而不是 `NaN` 的原因。区分它们的，纯粹是*统计量在哪些轴上归约*。对一个形状为 `[N, C, ...spatial]`（batch `N`、通道 `C`）的输入：

| 层 | 均值/方差归约的轴 | 每个统计量对应 | 依赖 batch？ | `gamma`/`beta` 长度 |
| --- | --- | --- | --- | --- |
| `BatchNormalization` | batch `N`（及所有空间轴） | 通道 | **是** | `C` |
| `LayerNormalization` | 归一化轴（默认最后一个） | 除该轴外的一切 | 否 | 归一化轴的大小 |
| `GroupNormalization` | 每个样本内一组通道 + 空间轴 | (样本, 组) | 否 | `C` |
| `InstanceNormalization` | 仅空间轴，逐样本逐通道 | (样本, 通道) | 否 | `C` |

把“依赖 batch？”这一列当作实际选型的判据。batch norm 通过共享统计量把样本耦合在一起，这既是它强大的原因，也是它在小 batch 下脆弱的原因；另外三个各自独立地归一化每个样本，与 batch 大小无关。四者都保持输入形状，而下面这些校验一个都不能少——group 和 instance normalization 要求秩 ≥ 3（二维输入会得到 `Error::InvalidInput`），batch norm 则接受二维及以上。

## 3.8.6. BatchNormalization

`BatchNormalization::new(input_shape, momentum, epsilon)`——注意参数顺序：形状在前，两个标量在后。`input_shape` 必须非空（否则报 `Error::EmptyInput`），`momentum` 必须落在 `[0.0, 1.0]`，`epsilon` 必须为正。第 0 维是 batch，**最后一维**是通道/特征；逐通道参数的长度是 `input_shape.last()`。对二维 `[N, C]` 输入，这就是普通的逐特征 batch norm。对秩为 3 或更高的 `[N, ...spatial, C]` 输入，统计量会在 batch **和**每个空间位置上归约，于是每个通道对应一份均值/方差/gamma/beta——即“spatial” batch norm，与 Keras 的 `axis=-1` 默认一致。两者走的是同一条代码路径：通道轴在最内层时，`[N, ...spatial, C]` 本身**就是**逐通道折叠要读的那个 `[M, C]` 矩阵，把前导轴合起来只是对同一批字节的重新解读，而不是一次 reshape。（像 `vec![4]` 这样的一维 `input_shape` 是个没有通道轴的特例：它用长度为 1 的标量参数，广播到整个输入上。）

让 batch norm 依赖模式的那份状态，是一对滑动统计量。训练 `forward` 时，先用当前 batch 的均值和方差做归一化，再按 `running = running * momentum + batch * (1 - momentum)` 更新它们。这是 **Keras** 的约定：像 `0.99` 这样高的 momentum 会重仓历史，让滑动估计缓慢移动。如果你从 PyTorch 过来，这是反着的——PyTorch 的 `momentum` 加权的是*新* batch——所以直接照搬一个值会得到相反的行为。`momentum == 0.0` 会把历史彻底丢掉（滑动统计量等于最后一个 batch 的），`momentum == 1.0` 则把它们冻结在初始值（均值 0、方差 1），这会悄悄让求值模式下的归一化近乎恒等——通常是个 bug。推理时，`forward`/`predict` 用的是这些滑动统计量而非任何 batch，这正是为什么在训练模式下把测试 batch 喂进 `forward` 会毁掉模型。

它相对激活放在哪里是有讲究的，而 `Dense` 折叠激活的设计限定了你的选择。原始论文把 batch norm 放在非线性*之前*。由于 `Dense::new(.., .., Activation::ReLU)` 把激活折进了线性层，要做到“BN 在激活之前”，就得先用一个线性的 `Dense`，再接 `BatchNormalization`，再接一个独立的激活层：

```rust,ignore
use rustyml::neural_network::layers::activation::relu::ReLU;
// Dense(linear) -> BatchNorm -> ReLU  （BN 在非线性之前，论文的顺序）
model
    .add(Dense::new(4, 8, Activation::Linear).unwrap())
    .add(BatchNormalization::new(vec![6, 8], 0.99, 1e-5).unwrap())
    .add(ReLU::new());
```

常见的另一种做法——先激活、再归一化——就是 `Dense::new(.., .., Activation::ReLU)` 后面跟一个 `BatchNormalization`。两种都能正常训练；选一个，然后保持一致。下面是一个完整可运行的模型，用的是更简单的“激活折进 Dense”写法：

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::sequential::Sequential;
use rustyml::neural_network::optimizers::Adam;
use rustyml::neural_network::losses::MeanSquaredError;
use ndarray::Array;

fn main() {
    // BatchNormalization 形状 [6, 8] 里的 6 不受校验，真正被校验的只有末尾的 8。
    let x = Array::ones((6, 4)).into_dyn();
    let y = Array::ones((6, 1)).into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(4, 8, Activation::ReLU).unwrap())
        .add(BatchNormalization::new(vec![6, 8], 0.9, 1e-5).unwrap())
        .add(Dropout::new(0.3, vec![6, 8]).unwrap())
        .add(Dense::new(8, 1, Activation::Linear).unwrap())
        .compile(
            Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    // fit() 走训练路径（batch 统计量、更新滑动统计量、dropout 开启）；
    // predict() 走求值路径（滑动统计量、dropout 为恒等）。
    model.fit(&x, &y, 3).unwrap();
    println!("prediction shape: {:?}", model.predict(&x).unwrap().shape());
}
```

注意 `input_shape` 的第一维只是记下一个 batch 大小，并不会被强制执行：一个为 `[6, 8]` 声明的 `BatchNormalization` 接受任意大小的 batch，所以 `fit_with_batches` 用任何 `batch_size` 都能训练，包括数据集除不尽时剩下的那个偏短的末尾批次。真正被强制执行的是秩和每一条逐样本的轴，所以 `[n, 16]` 的输入——或者秩不对的输入——仍然是 `Error::ShapeMismatch`。这也意味着 `vec![]` 通配并不是让某个层挺过小批量训练的手段；只有当逐样本形状本身会变时才用得上它。你也可以用 `set_weights(gamma, beta, running_mean, running_var)` 直接注入已知权重（形状不匹配会返回 `NnError::WeightShape`），加载模型时正是靠这个来恢复它的推理统计量——见下一节以及[权重保存与加载](./3.9._权重保存与加载.md)。

## 3.8.7. LayerNormalization

`LayerNormalization::new(input_shape, epsilon)` 在*每个样本内部*跨特征做归一化，没有 batch 耦合，也没有滑动统计量——这正是它成为循环模型、以及一切 batch 小、可变或大小为 1 的场景下首选归一化方式的原因。当 batch norm 的统计量在寥寥几个样本上变得嘈杂或失去意义时，layer norm 毫不受影响，因为每个样本各自独立。它的 `forward` 输出在训练和推理下相同（`predict` 等于 `forward`），只有反向传播受模式控制。

默认它归一化最后一个（特征）维度。`with_normalized_axis(...)` 可以改变这一点，它接收一个 `LayerNormalizationAxis`：`Default`（最后一个轴）、`Custom(axis)`（另指一个单独的轴）、或 `Multiple(vec![...])`（一次性在多个轴上联合归一化，Keras 风格，此时统计量横跨这些轴组合出的元素，`gamma`/`beta` 变成它们乘积长度的一维）。改动轴会把 `gamma`/`beta` 调整到匹配的大小，所以要在赋权重之前调用它。空的、重复的或越界的轴列表会被拒绝；非末尾的 `Custom` 轴或需要重排的 `Multiple` 列表会被正确处理，只是走一条较慢的跨步路径。

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    let input = Array::from_shape_vec((2, 4), vec![1.0, 3.0, 5.0, 7.0, 2.0, -2.0, 0.0, 4.0])
        .unwrap()
        .into_dyn();

    // 默认：每一行（最后一个轴）被归一化到均值 0、方差 1。
    let mut ln = LayerNormalization::new(vec![2, 4], 1e-5).unwrap();
    let out = ln.forward(&input).unwrap();

    // Custom(0)：改为沿每一列（跨 batch 轴）向下归一化。
    let mut ln_cols = LayerNormalization::new(vec![2, 4], 1e-5)
        .unwrap()
        .with_normalized_axis(LayerNormalizationAxis::Custom(0))
        .unwrap();
    let out_cols = ln_cols.forward(&input).unwrap();

    println!("row-norm {:?}, col-norm {:?}", out.shape(), out_cols.shape());

    // 统计量来自当前输入，所以 predict() 精确重现 forward()。
    assert_eq!(ln.predict(&input).unwrap(), out);
}
```

## 3.8.8. GroupNormalization 与 InstanceNormalization

这两个填补了中间地带：卷积模型里 batch 太小、batch norm 不可靠的场合——检测与分割骨干网络，以及生成模型。`GroupNormalization::new(input_shape, num_groups, epsilon)` 把通道切成 `num_groups` 个连续的组，在单个样本的每个组内做归一化；只有一个组时它就是覆盖全部通道的 layer norm，组数等于通道数时它就是 instance norm。`InstanceNormalization::new(input_shape, epsilon)` 单独归一化每个 `(sample, channel)` 平面，这是风格迁移的标准选择，因为它剥掉了每个实例内部的对比度，同时不动 batch 之间的关系。两者都要求秩 ≥ 3，通道轴跟其他所有空间层一样取最末轴，而且跟 layer norm 一样不带滑动统计量，在前向方向上与模式无关。它们的逐组均值和方差来自**单遍**扫描：两个累加器一起累计「相对于取自数据的某个值的偏差」之和，于是方差不需要第二遍走样本就能算出，也避开了均值远大于离散度时朴素的 `E[x²] − E[x]²` 会遭遇的灾难性抵消。

instance norm 说白了就是 `num_groups` 等于通道数的 group norm，crate 也正是这么实现的，所以当两者配置成对应关系时，输出完全相同：

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;
use ndarray::Array;

fn main() {
    // [batch=1, positions=4, channels=4]
    let input = Array::from_shape_vec((1, 4, 4), (0..16).map(|v| v as f32).collect::<Vec<_>>())
        .unwrap()
        .into_dyn();

    // InstanceNorm 独立归一化每个 (sample, channel) 平面……
    let mut inn = InstanceNormalization::new(vec![1, 4, 4], 1e-5).unwrap();
    let out_in = inn.forward(&input).unwrap();

    // ……这恰好等于每通道一个组的 GroupNorm。
    let mut gn = GroupNormalization::new(vec![1, 4, 4], 4, 1e-5).unwrap();
    let out_gn = gn.forward(&input).unwrap();

    let max_diff = out_in
        .iter()
        .zip(out_gn.iter())
        .map(|(a, b)| (a - b).abs())
        .fold(0.0_f32, f32::max);
    println!("max |InstanceNorm - GroupNorm(groups=channels)| = {max_diff}");
    assert!(max_diff < 1e-6);
}
```

有一条整除规则要记住：`num_groups` 必须整除通道数，而 crate 是在 `forward` 时检查（不是在构造函数里），所以一个不匹配的 `GroupNormalization` 能顺利构造，却会在第一次前向时以 `Error::InvalidParameter` 失败。`num_groups == 0`、`channel_axis == 0`、越界的轴，以及非正的 `epsilon`，都在构造时就被拦下。两个层都接受 `set_weights(gamma, beta)`。

## 3.8.9. 播种、确定性与保存内容

两个横切的性质给整幅图景收尾。其一是随机性：只有 dropout 和高斯这几个层会抽随机数，各自从自己的 `StdRng` 里抽，种子经由 crate 的全局种子机制设定——`new` 用全局种子或系统熵播种，`with_random_state(seed)` 把它固定住。归一化层则完全确定。就连这些层内部用的并行/串行阈值也是逐位不变的（并行路径产出的结果跟串行路径一致），所以开启多线程从不改变你的数字；那只是个性能旋钮，见[性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)。要把一切一起播种，走[可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)。

其二是持久化，这里有一处不对称，值得在保存模型前先吃透。dropout 和噪声层不持有可训练参数——它们序列化为空，而且它们的 RNG 状态*不*会被保存，这没什么害处，反正它们在推理时就是恒等映射。`LayerNormalization`、`GroupNormalization` 和 `InstanceNormalization` 只序列化各自的 `gamma` 和 `beta`，这已经完整，因为它们会从每个输入重新计算统计量。`BatchNormalization` 是例外：它的权重记录里带着 `gamma`、`beta`，**还有** `running_mean` 和 `running_var`。这些滑动统计量正是推理所用的东西，所以一旦丢掉，加载后的模型就会拿垃圾去做归一化；正因为它们被持久化，一个存下来再重新加载的 batch-norm 模型，预测结果跟原来的一模一样。这趟往返的机制见[权重保存与加载](./3.9._权重保存与加载.md)和[深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)。
