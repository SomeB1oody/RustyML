# 3.4. 优化器

RustyML 中的优化器就是把梯度变成参数更新的那个对象。当某一层的 `backward` 为每个可训练张量算好并暂存梯度后，优化器逐个遍历这些张量，把每一个都往下坡方向推。你在对 [`Sequential`](./3.1._Sequential模型.md) 模型调用 `compile` 时选定它，同时还要指定一个[损失函数](./3.3._损失函数.md)；此后 `fit` 就会替你驱动整个过程。

一共有五个：[`SGD`](https://docs.rs/rustyml)、[`Adam`](https://docs.rs/rustyml)、[`AdamW`](https://docs.rs/rustyml)、[`RMSprop`](https://docs.rs/rustyml)、[`AdaGrad`](https://docs.rs/rustyml)，全部位于 `rustyml::neural_network::optimizers`，并通过 prelude 重新导出。每个构造函数都返回 `Result<Self, Error>`，因为它会先校验超参数，所以下面的示例里每个构造调用都以 `.unwrap()`（或真正的错误处理）收尾。如果你用过 Keras 或 PyTorch，这些算法和你熟悉的完全一致；区别在于构造函数用的是位置参数且必须传全（没有关键字默认值），而且梯度裁剪和 weight decay 是内建在优化器里的，不是挂在训练循环上的附加件。

## 3.4.1. 优化器接口与更新的流动方式

每个优化器都实现 `Optimizer` trait，它的五个方法你都用得上：三个由训练循环替你调用，另外 `learning_rate`/`set_learning_rate` 这一对由调度逻辑自己读写（见 3.4.8）：

```rust,ignore
pub trait Optimizer {
    fn step(&mut self);                                         // 每个 batch 调用一次
    fn update(&mut self, layer: &mut dyn Layer, grad_scale: f32); // 每一层调用一次
    fn clip_norm(&self) -> Option<f32>;                        // 裁剪阈值，没有则返回 None
    fn learning_rate(&self) -> f32;                            // 当前步长
    fn set_learning_rate(&mut self, learning_rate: f32);       // 用于调度的钩子
}
```

训练循环在碰任何一层之前，每个 batch 恰好调用一次 `step`，然后每一层调用一次 `update`。`step` 是有状态优化器推进自身“时间”概念的地方：Adam 和 AdamW 在这里递增用于偏差校正的时间步；SGD、RMSprop 和 AdaGrad 只用它来倒回一个内部游标。正是这种拆分，决定了 Adam 每个 *batch* 推进一次时间步，而不是每 *层* 推进一次——手写循环如果按每个参数调用一次更新，就会悄悄踩到这个细节。

`update` 会收到一个 `grad_scale` 系数，由循环根据 `clip_norm`（见下文）算出；不裁剪时它是 `1.0`。在内部，优化器通过 `layer.parameters()` 向层索取参数，拿到的是每个可训练张量对应的扁平 `ParamGrad`——一个可变的 `value` 切片、与之匹配的 `grad` 切片，外加一个 `decays: bool` 标志。weight decay 靠这个标志才不至于乱来：权重矩阵和卷积/循环核带 `decays = true`，而偏置以及归一化的 `gamma`/`beta` 带 `decays = false`，**永远**不会被 decay，无论你把 `weight_decay` 设成多少。这些你都不用管；层负责设标志，优化器负责尊重它。

因为参数以扁平的 `&mut [f32]` 切片暴露出来，单个逐元素内核就能处理任意形状的张量，而且一旦某个张量的元素数越过阈值，每个内核都会透明地切到 Rayon 并行路径（见 [7.3](../Chapter-07/7.3._性能调优与并行.md)）。有一个后果值得记牢：优化器的逐参数状态是按层交出每个张量时的*位置*来索引的，所以参数顺序必须在各步之间保持稳定（事实上它是稳定的），而一个优化器实例只属于一个模型——不要共享它。

## 3.4.2. SGD

```rust,ignore
SGD::new(learning_rate, momentum, nesterov, weight_decay) // 除 nesterov: bool 外全为 f32
```

朴素的随机梯度下降，可选动量、Nesterov 加速和解耦的 weight decay。当 `momentum = 0.0` 时，更新就是教科书里那个：

```text
param -= lr * grad
```

把 `momentum > 0.0` 打开，就会累积一个逐参数的速度缓冲，还可以叠加 Nesterov 前瞻：

```text
v    = momentum * v + grad
step = grad + momentum * v   (nesterov = true)   or   v   (nesterov = false)
param -= lr * step
```

`0.9` 是惯用的动量值；只有动量非零时 `nesterov` 才有意义。这里的 `weight_decay` 是**解耦**的（SGDW 形式）：在梯度步之前，权重张量按 `param *= (1 - lr * weight_decay)` 收缩，与梯度无关。这和 AdamW 用的是同一种解耦，只不过施加在 SGD 上。

```rust
use rustyml::prelude::*;
use rustyml::neural_network::sequential::Sequential;
use ndarray::Array;

fn main() {
    // 内联小回归：y = 2*x
    let x = Array::from_shape_vec((4, 1), vec![0.5_f32, 1.0, 1.5, 2.0])
        .unwrap()
        .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![1.0_f32, 2.0, 3.0, 4.0])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(1, 1, Activation::Linear).unwrap())
        // learning_rate, momentum, nesterov, weight_decay
        .compile(SGD::new(0.05, 0.9, true, 0.0).unwrap(), MeanSquaredError::new());

    let before = model.predict(&x).unwrap();
    model.fit(&x, &y, 10).unwrap();
    let after = model.predict(&x).unwrap();
    println!("shapes: {:?} -> {:?}", before.shape(), after.shape());
}
```

当你想要精细控制和可预测的行为时，就用 SGD（配动量）：它的动力学被研究得很透彻，单个滑动平均开销很小，而且 SGD+动量至今仍是衡量自适应方法泛化能力的标杆。代价是对学习率敏感——太大就发散，太小就爬得慢——而这恰恰是 Adam 帮你抹平的那个旋钮。

## 3.4.3. Adam

```rust,ignore
Adam::new(learning_rate, beta1, beta2, epsilon, weight_decay) // 全为 f32
```

Adam 为每个参数维护两个滑动平均——一阶矩 `m`（梯度均值）和二阶矩 `v`（梯度平方的均值）——并用它们给每个参数各自的自适应步长。逐元素运行的完整更新如下：

```text
t += 1                                  (advanced once per batch, in step())
m = beta1*m + (1 - beta1)*grad
v = beta2*v + (1 - beta2)*grad^2
m_hat = m / (1 - beta1^t)               <- bias correction
v_hat = v / (1 - beta2^t)               <- bias correction
param -= lr * m_hat / (sqrt(v_hat) + epsilon)
```

偏差校正是大家最容易一笔带过的部分。`m` 和 `v` 从零开始，所以头几步它们会偏向零——而且偏得厉害，因为 `beta2 = 0.999` 意味着在 `t = 1` 时 `v` 几乎没离开零。除以 `(1 - beta^t)` 把它们重新缩放回来：`t = 1` 时分母 `1 - beta1` 正好抵消 `m` 里的 `(1 - beta1)` 因子，还原出原始梯度；随着 `t` 增大，`beta^t -> 0`，校正逐渐退化成空操作。这就是时间步在 `step` 里（每个 batch 一次）而不是在 `update` 里推进的原因：用全批量的 [`fit`](./3.1._Sequential模型.md) 时，`t` 等于 epoch 数；用 `fit_with_batches` 时，它按每个 mini-batch 推进。时间步会饱和而不会溢出，所以极长的训练也始终良好定义。

有一处看着像不一致、实则是刻意为之的细节：Adam 把 `epsilon` 加在平方根**外面**，而 RMSprop 和 AdaGrad（3.4.5 与 3.4.6）把它加在根号**里面**。Keras 自己也是这么分裂的——它的 `Adam` 在开根之后加 epsilon，它的 `RMSprop` 和 `Adagrad` 则在开根之前加——RustyML 选择逐个优化器地对齐 Keras，而不是强行把这三者统一成同一种写法。后果是 `epsilon` 在各个优化器里并非按同一个尺度度量，所以在优化器之间搬运这个取值之前，先读 RMSprop 那一节里关于尺度的说明。

Adam 的 `weight_decay` 是**经典的耦合 L2 正则化**：`weight_decay * param` 在矩更新*之前*就被折进梯度，所以这个惩罚项会流经 `m` 和 `v`，并被自适应的 `1 / (sqrt(v_hat) + epsilon)` 分母重新缩放。这种耦合通常不是你想要的（见下面的 AdamW）；当 `weight_decay = 0.0` 时这一点无关紧要，此时 Adam 和 AdamW 逐字节完全相同。在这里保留耦合是对 Keras 3 的一次刻意偏离：Keras 的优化器基类对所有优化器一律施加*解耦*的 decay，于是它的 `Adam(weight_decay=x)` 和 `AdamW(weight_decay=x)` 在数值上是同一个东西；RustyML 转而与 PyTorch 保持一致，那里 `torch.optim.Adam(weight_decay=)` 是耦合的而 `AdamW` 的不是，这样两个名字才真正各有所指。

```rust
use rustyml::prelude::*;
use rustyml::neural_network::sequential::Sequential;
use ndarray::Array;

fn main() {
    // 内联小回归：y = x0 + 2*x1
    let x = Array::from_shape_vec((4, 2), vec![0.0_f32, 1.0, 1.0, 0.0, 1.0, 1.0, 2.0, 1.0])
        .unwrap()
        .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![2.0_f32, 1.0, 3.0, 4.0])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(2, 8, Activation::ReLU).unwrap())
        .add(Dense::new(8, 1, Activation::Linear).unwrap())
        // learning_rate, beta1, beta2, epsilon, weight_decay
        .compile(Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(), MeanSquaredError::new());

    model.fit(&x, &y, 50).unwrap();

    let preds = model.predict(&x).unwrap();
    println!("prediction shape: {:?}", preds.shape());
}
```

`Adam::new(0.001, 0.9, 0.999, 1e-8, 0.0)` 就是默认答案。要是拿不准该用哪个优化器，就用它：它对学习率很宽容，在杂乱的损失曲面上收敛快，几乎不用调参就能跑起来。

## 3.4.4. AdamW

```rust,ignore
AdamW::new(learning_rate, beta1, beta2, epsilon, weight_decay) // 与 Adam 签名完全相同
```

AdamW 跑的矩运算和偏差校正与 Adam 一模一样。唯一的差别在于 weight decay 从哪里进入，而这个差别一旦你把 decay 打开就变得举足轻重。AdamW 是**解耦**的（Loshchilov–Hutter 形式）：权重直接收缩，`param *= (1 - lr * weight_decay)`，发生在一次普通 Adam 步*之前*，decay 从不触碰 `m` 或 `v`，也从不被自适应分母除。

这为什么不是表面上的区别，道理如下。在 Adam 的耦合方案里，`weight_decay * param` 这一项会随二阶矩 `v` 一起传播，于是见过大梯度的参数会得到大的 `v`、大的分母，因此实际 decay *更少*，反而不如一个安静的参数。你的正则化强度最终和每个权重的梯度历史缠在一起——这与“weight decay”本该表达的均匀收缩恰好相反。AdamW 斩断了这层关系：每个权重都按同样的 `(1 - lr * weight_decay)` 因子 decay，与它的梯度无关。这就是 AdamW 泛化更好、并成为训练任何你真正在乎正则化的模型时标准选择的原因。

实用准则：**只要你想在自适应优化器上用非零的 weight decay，就用 `AdamW`，而不是 `Adam` 的 `weight_decay`。** 完全不做正则化时，用朴素的 `Adam`（`weight_decay = 0.0`）。当 `weight_decay = 0.0` 时两者是同一个算法，所以除了习惯之外没有任何理由偏向 `Adam`。

```rust
use rustyml::prelude::*;
use rustyml::neural_network::sequential::Sequential;
use ndarray::Array;

fn main() {
    let x = Array::from_shape_vec(
        (4, 3),
        vec![0.0_f32, 1.0, 2.0, 1.0, 0.0, 1.0, 2.0, 1.0, 0.0, 1.0, 1.0, 1.0],
    )
    .unwrap()
    .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![1.0_f32, 0.5, 0.5, 0.75])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(3, 16, Activation::ReLU).unwrap())
        .add(Dense::new(16, 1, Activation::Linear).unwrap())
        // 解耦的 weight_decay = 0.01
        .compile(
            AdamW::new(0.01, 0.9, 0.999, 1e-8, 0.01).unwrap(),
            MeanSquaredError::new(),
        );

    model.fit(&x, &y, 30).unwrap();
    println!("trained: {:?}", model.predict(&x).unwrap().shape());
}
```

## 3.4.5. RMSprop

```rust,ignore
RMSprop::new(learning_rate, rho, epsilon, weight_decay) // 全为 f32
```

注意拼写：类型名是 `RMSprop`（小写 `p`）。它为每个参数维护一个梯度平方的滑动平均，并用它的平方根来归一化每一步：

```text
cache = rho*cache + (1 - rho)*grad^2
param -= lr * grad / sqrt(cache + epsilon)
```

`rho`（梯度平方的衰减率，惯用 `0.9`）是 RMSprop 对 AdaGrad 致命缺陷的回应。因为 `cache` 是指数滑动平均而不是累加和，它会遗忘旧梯度、永不无界增长，所以有效步长会稳定下来，而不是衰减到零。可以把 RMSprop 看成没有一阶矩的 Adam：有逐参数的自适应缩放，但没有动量、也没有偏差校正。它的 `weight_decay` 是解耦的（AdamW 风格），在自适应步之前施加于权重张量。RMSprop 对循环网络和非平稳目标是个不错的选择，不过在大多数问题上 Adam 都能把它涵盖。

注意 `epsilon` 加在根号**里面**，与 Keras 一致（`sqrt(velocity + epsilon)`），而这个位置不是写法上的无关差异——它决定了 epsilon 按什么单位度量。`cache` 累积的是梯度的*平方*，所以加在开根之前的 epsilon 活在 `grad^2` 的尺度上，加在开根之后的（上面 Adam 的形式，以及 PyTorch 的 RMSprop）则活在 `grad` 的尺度上；两者大致按 `eps_inside = eps_outside^2` 对应。Keras 默认放在根号内的 `1e-7`，与放在根号外的 `3.2e-4` 是同一个保护力度，所以直接把另一种形式下的取值搬过来，无论往哪个方向搬都会差好几个数量级。下面的 AdaGrad 用的同样是根号内的形式。

## 3.4.6. AdaGrad

```rust,ignore
AdaGrad::new(learning_rate, epsilon, weight_decay) // 全为 f32；注意：没有 rho/beta
```

AdaGrad 累加梯度平方，并且从不遗忘：

```text
accumulator += grad^2
param -= lr * grad / sqrt(accumulator + epsilon)
```

`accumulator` 是一个单调增长的累加和，所以 `sqrt(accumulator)` 只增不减，有效学习率 `lr / sqrt(accumulator + epsilon)` 单调地衰减向零。这是 AdaGrad 的标志性性质，而它是把双刃剑。对凸问题和稀疏特征，它是优点：很少出现的参数保持大步长，频繁更新的参数则自动退火，衰减到零还带来干净的收敛保证。对训练很多步的深度网络，它是缺陷：步长一直缩到学习实际停滞，而这正是 RMSprop 的衰减因子和 Adam 的二阶矩平均要解决的问题。这里的 `learning_rate` 真的是一个*初始*速率（通常 `0.01`）；它是上限，累加器只会把它往下拉。它的 `epsilon` 和 RMSprop 一样落在根号内，因此也处在梯度平方的尺度上。weight decay 和其他几个一样，是解耦的、且只作用于权重。

## 3.4.7. 参数校验

每个构造函数在返回之前都会校验，所以一个坏的超参数会在构造时就以 `Error::InvalidParameter` 大声失败，而不是在训练三个 epoch 之后才冒出 NaN。下面是直接取自校验逻辑的规则：

| 参数 | 可接受的取值 | 适用于 |
| --- | --- | --- |
| `learning_rate` | 正且有限（`> 0`） | 全部五个 |
| `momentum` | 非负且有限（`>= 0`） | SGD |
| `nesterov` | 任意 `bool`（从不校验） | SGD |
| `beta1`、`beta2` | 在 `[0, 1)` 内且有限 | Adam、AdamW |
| `rho` | 在 `[0, 1)` 内且有限 | RMSprop |
| `epsilon` | 正且有限（`> 0`） | Adam、AdamW、RMSprop、AdaGrad |
| `weight_decay` | 非负且有限（`>= 0`） | 全部五个 |
| `clip_norm` | 正且有限（`> 0`） | 全部五个（通过 `with_clip_norm`） |

衰减率的区间是特意设成半开的：`beta1 = 0.0` 和 `rho = 0.0` 会被接受（下界闭合），但 `1.0` 会被拒绝（上界开），因为 `1.0` 的衰减会冻结滑动平均，永远吸纳不进新梯度。SGD 没有 `epsilon`，因为它从不除以自适应分母。注意 `0.0` 对 `momentum` 和 `weight_decay` 是合法的——这正是你关掉这两个特性的方式——但对 `learning_rate` 和 `epsilon` 非法。另外，`epsilon` 对四个自适应优化器的校验规则完全相同，但它的*含义*并不相同：RMSprop 和 AdaGrad 把它加在平方根内（梯度平方尺度），Adam 和 AdamW 把它加在平方根外（梯度尺度），所以在一边合理的取值，换到另一边大致要取它的平方或平方根。

```rust
use rustyml::neural_network::optimizers::{AdaGrad, Adam, AdamW, RMSprop, SGD};
use rustyml::error::Error;

fn main() {
    // learning_rate 必须为正且有限
    assert!(matches!(
        SGD::new(0.0, 0.0, false, 0.0),
        Err(Error::InvalidParameter { .. })
    ));
    // beta1 必须在 [0, 1) 内：1.0 超出范围
    assert!(matches!(
        Adam::new(0.001, 1.0, 0.999, 1e-8, 0.0),
        Err(Error::InvalidParameter { .. })
    ));
    // epsilon 必须为正且有限
    assert!(matches!(
        RMSprop::new(0.01, 0.9, 0.0, 0.0),
        Err(Error::InvalidParameter { .. })
    ));
    // weight_decay 必须非负且有限
    assert!(matches!(
        AdaGrad::new(0.01, 1e-8, -0.1),
        Err(Error::InvalidParameter { .. })
    ));
    // clip_norm 必须为正且有限
    assert!(matches!(
        AdamW::new(0.001, 0.9, 0.999, 1e-8, 0.0)
            .unwrap()
            .with_clip_norm(0.0),
        Err(Error::InvalidParameter { .. })
    ));

    // 一个完全合法的配置，启用裁剪
    let opt = Adam::new(0.001, 0.9, 0.999, 1e-8, 0.0).unwrap();
    let _clipped = opt.with_clip_norm(1.0).unwrap();
    println!("validation checks passed");
}
```

## 3.4.8. 梯度裁剪与学习率调度

梯度裁剪默认关闭，通过五个优化器上都有的消耗型 builder `with_clip_norm` 按需开启。它是**按全局范数裁剪**，不是逐元素截断：训练循环把模型中*每个*张量的梯度平方求和，取全局 L2 范数，如果它超过你的阈值，就在更新前用同一个系数 `max_norm / global_norm` 去缩放每一个梯度。同一个统一系数意味着下降方向被精确保留；逐元素截断则会把方向掰弯。一个非有限的全局范数会被特意留着不缩放，这样真正的发散仍会以 NaN 的形式浮现，而不是被悄悄掩盖。这是驯服大而有限的梯度（RNN、深层堆叠）的推荐做法——反向传播本身不做任何截断。

学习率调度走一对读写方法，`learning_rate` 与 `set_learning_rate`，在模型上暴露为 `Sequential::learning_rate`——返回 `Option<f32>`，`compile` 之前是 `None`——和 `Sequential::set_learning_rate`。在 epoch 或 batch 之间调用 setter 来重新调整步长；关键是它会保留全部累积状态——Adam 的矩、SGD 的速度、RMSprop 的 cache——所以你是在重新调同一个优化器，而不是重置它。这里没有内建的调度器对象；调度策略就是你自己写的一个普通循环，而 getter 的意义就在于让这个循环不必再自己存一份学习率的副本——只要别处动过优化器，那份副本立刻就过期了。读回来的永远是最后一次写进去的值：和构造函数不同，`set_learning_rate` 不做任何校验，所以零或负的学习率会被原样存下、原样读回，而不会被拒绝。

```rust
use rustyml::prelude::*;
use rustyml::neural_network::sequential::Sequential;
use ndarray::Array;

fn main() {
    let x = Array::from_shape_vec((4, 2), vec![0.0_f32, 1.0, 1.0, 0.0, 1.0, 1.0, 2.0, 1.0])
        .unwrap()
        .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![2.0_f32, 1.0, 3.0, 4.0])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(2, 8, Activation::ReLU).unwrap())
        .add(Dense::new(8, 1, Activation::Linear).unwrap())
        .compile(
            Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0)
                .unwrap()
                .with_clip_norm(1.0) // 把全局梯度范数裁剪到 1.0
                .unwrap(),
            MeanSquaredError::new(),
        );

    // 手动阶梯衰减：每个 block 把 LR 减半；优化器状态跨 block 保留
    for _ in 0..3 {
        model.fit(&x, &y, 10).unwrap();
        // 学习率存在优化器里，读回来即可，不必自己另存一份
        let lr = model.learning_rate().unwrap();
        model.set_learning_rate(lr * 0.5);
    }

    assert_eq!(model.learning_rate(), Some(0.01_f32 / 8.0));
}
```

## 3.4.9. 逐层状态、内存与持久化

每个优化器惰性地分配状态：每个参数张量一个缓冲，大小按该张量而定，在第一次触及它的 `update` 时创建。这些缓冲按层交出参数的顺序索引；如果某个位置上张量的长度变了，对应缓冲就会被重置以匹配。这就是为什么两层收敛测试要检验跨层的缓冲分配是否正确——状态必须和它所影随的参数对齐。

内存开销就是这些缓冲的数量和大小：

| 优化器 | 逐参数状态 | 相对参数的额外内存 |
| --- | --- | --- |
| SGD，`momentum = 0.0` | 无 | 0x |
| SGD，`momentum > 0.0` | 速度 | 1x |
| RMSprop | 梯度平方 cache | 1x |
| AdaGrad | 梯度平方累加器 | 1x |
| Adam、AdamW | 一阶矩 `m` + 二阶矩 `v` | 2x |

对一个有 `P` 个 `f32` 权重的模型，Adam 和 AdamW 在参数及其梯度之外还要背上大约 `2 * 4 * P` 字节的优化器状态——这是自适应的代价，也是一个用 SGD 训练正常的模型在 Adam 下可能内存爆掉的原因。朴素 SGD 什么都不背，这在预算紧张时偶尔会成为决定性因素。

这些状态完全存在于优化器实例里，**不会**被持久化。`Sequential::save_to_path` 只序列化层的结构和权重；优化器和损失函数被明确排除在外，所以 `load_from_path` 之后你必须重新 `compile` 一个新优化器，它的矩、速度和时间步都从零开始。因此重新加载权重并续训会重启 Adam 的偏差校正预热——通常无伤大雅，但如果你在训练中途做检查点就值得知道。完整的持久化说明见 [3.9. 权重保存与加载](./3.9._权重保存与加载.md) 和 [7.2. 深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)。

## 3.4.10. 如何选择优化器

一句话版本：**从 Adam 开始**（`0.001, 0.9, 0.999, 1e-8, 0.0`）。它对学习率最不挑剔，几乎能让任何模型训练起来，而这正是你还在摸索架构时想要的。

当你想要精细控制、又愿意去调学习率时，就用**带动量的 SGD**（`momentum = 0.9`、`nesterov = true`）——它的泛化是参考标准，状态开销小，行为透明。只要目标是正则化，就用**带非零 `weight_decay` 的 AdamW**；它的解耦 decay 是正则化自适应优化器的正确方式，任何开启 decay 的场合它都应当优先于 `Adam` 的耦合 `weight_decay`。**RMSprop** 对循环和非平稳问题是个稳妥的后备，而 **AdaGrad** 在凸的、稀疏特征的问题上大放异彩，那里衰减的步长是资产而非负担——但别在长时间的深度网络训练里用 AdaGrad，同样的衰减会把学习拖停。

调参时还有一个贯穿始终的细节：有效学习率和你损失函数的平均约定纠缠在一起。在逐元素损失（MSE、MAE、二元交叉熵）和逐预测位置损失（分类交叉熵）之间切换，会改变梯度的量级，从而改变步长——见 [3.3. 损失函数](./3.3._损失函数.md) 里关于平均的说明。换了损失，无论你选的是哪个优化器，多半都得重新调学习率。
