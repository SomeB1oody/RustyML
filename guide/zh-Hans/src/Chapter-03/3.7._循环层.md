# 3.7. 循环层

RustyML 提供 3 种循环层：`SimpleRNN`、`LSTM`、`GRU`。它们都位于 `rustyml::neural_network::layers::recurrent`，并通过 prelude 重新导出。三者共用同一套约定：每个层都接收一个三维序列张量，沿时间轴跑一遍递归，返回最后的隐藏状态或者全部隐藏状态。

如果你熟悉 Keras，这些层带有 `return_sequences` 和 `go_backwards` 两个开关，默认值一样是 false。单独看，每个开关的含义都和 Keras 一致。**但两个一起用就不一致了。**两个都打开时，层按处理顺序返回状态，于是第 0 槽装的是**最后一个**输入时间步产生的状态，而 Keras 会把这个序列翻回输入顺序。3.7.1 节讲这两个开关，[3.7.9](#379-一个双向模型) 讲这一对该怎么处理。它们不带 `return_state`，没有 `bidirectional` 包装，也没有 cell 内 dropout。

## 3.7.1. 输入/输出约定

每个循环层都要求一个三维输入张量，形状为 `(batch_size, timesteps, features)`，默认输出则是二维的 `(batch_size, units)`。`features` 轴就是 build 定下来的宽度。本页在下面的权重形状公式里把它写作 `input_dim`，它来自到达这个层的形状的最后一根轴，而不是来自任何一个参数。`units` 就是你设定的隐藏层宽度。递归会把时间步轴吃掉，所以默认情况下它不会出现在输出里，只有最后一个隐藏状态 `h_T` 会留下来。

```rust
use ndarray::Array;
use rustyml::neural_network::Shape;
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::recurrent::SimpleRNN;
use rustyml::neural_network::traits::UnaryLayer;
use rustyml::neural_network::Ctx;

fn main() {
    // units = 3 个隐藏神经元。每步的特征数由 build 提供。
    let mut rnn = SimpleRNN::new(3, Tanh::new()).unwrap();
    rnn.build(&Shape::with_free_batch(&[2, 5, 4])).unwrap();

    // (batch = 2, timesteps = 5, features = 4)
    let x = Array::zeros((2, 5, 4)).into_dyn();

    // 推理上下文只跑递归，不为反向传播记录任何东西
    let mut ctx = Ctx::inference();
    let out = rnn.forward(&x, &mut ctx).unwrap();

    // 时间步轴消失了：只有最后一个隐藏状态留了下来。
    println!("output shape: {:?}", out.shape()); // [2, 3] == (batch, units)
}
```

```text
output shape: [2, 3]
```

这 3 种层共用同一个构造函数签名：`new(units, activation) -> Result<Self, Error>`。每步的特征数不是一个参数：`Layer::build` 从到达这个层的形状的最后一根轴读出它，并在那时确定输入 kernel 的尺寸。激活参数的类型是 `impl Into<Activation>`，你可以传一个 `Activation` 枚举变体，比如 `Activation::Tanh`，也可以传某个轻量的层包装，比如 `Tanh::new()`、`ReLU::new()`、`Sigmoid::new()`、`Linear::new()`、`Softmax::new()`。每一种包装都会转换成同一个枚举。`Softmax::new()` 带的是默认轴 `-1`，而 `Softmax::new().with_axis(..)` 得到的层在这里会被拒绝，因为嵌入式的 softmax 只接受这个默认值。完整的激活函数目录见 [3.2. 全连接层与激活函数](./3.2._全连接层与激活函数.md)。

`units` 为 0 时，`new` 返回 `Error::InvalidParameter`。RustyML 没有 `return_state` 选项，没有 `bidirectional` 包装，也没有 cell 内 dropout。每个层都使用同一套稠密实现。

有 2 个 builder 方法可以改变递归吐出什么、以及朝哪个方向跑。每个方法都消费并返回 `self`，因此可以直接链在构造函数后面，两者的默认值都是 false：

| Builder | 默认值 | 输出形状 | 效果 |
| --- | --- | --- | --- |
| `with_return_sequences(true)` | false | `(batch, timesteps, units)` | 保留每一步的状态，而不是只保留最后一个状态 |
| `with_go_backwards(true)` | false | 不变 | 从最后一个时间步向第一个时间步读输入 |

`with_return_sequences(true)` 保留时间轴。这根轴上第 `k` 个槽位装的是第 `k` 步之后的状态，所以最后一个槽位正好就是同一个层在开关关闭时返回的东西。此时反向传播期待一个同样是三维形状的梯度。`LSTM` 的细胞状态在两种设置下都留在层内部。

`with_go_backwards(true)` 只反转读取顺序。处理的第 0 步消费的是输入的第 `timesteps - 1` 个时间步。层不会把输出再翻回输入顺序，所以返回序列的第 0 个槽位装的是来自最后一个输入时间步的状态。这个开关不改变任何形状。需要输出回到输入顺序时，请自己把序列翻回来。

这 2 个开关互相独立。下面这段程序在同一份输入上跑了全部 3 种有用的设置：

```rust
use ndarray::Array;
use rustyml::neural_network::Shape;
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::UnaryLayer;
use rustyml::neural_network::Ctx;

fn main() {
    // 2 条序列，5 个时间步，4 个特征。
    let x = Array::from_shape_fn((2, 5, 4), |(n, t, f)| (n * 20 + t * 4 + f) as f32 * 0.01)
        .into_dyn();

    // 1 个推理上下文服务这 3 遍传播，因为它什么都不记录。
    let mut ctx = Ctx::inference();

    // 默认只返回最后一个隐藏状态。
    let mut last_layer = SimpleRNN::new(3, Tanh::new()).unwrap().with_random_state(1);
    last_layer.build(&Shape::with_free_batch(&[2, 5, 4])).unwrap();
    let last = last_layer.forward(&x, &mut ctx).unwrap();
    assert_eq!(last.shape(), &[2, 3]);

    // return_sequences 保留时间轴，所以输出是三维的。
    let mut sequence_layer = SimpleRNN::new(3, Tanh::new())
        .unwrap()
        .with_random_state(1)
        .with_return_sequences(true);
    sequence_layer.build(&Shape::with_free_batch(&[2, 5, 4])).unwrap();
    let sequence = sequence_layer.forward(&x, &mut ctx).unwrap();
    assert_eq!(sequence.shape(), &[2, 5, 3]);

    // 序列的最后一个槽位正好就是上面那个二维输出。
    for n in 0..2 {
        for u in 0..3 {
            assert!((sequence[[n, 4, u]] - last[[n, u]]).abs() < 1e-6);
        }
    }

    // go_backwards 从最后一步向第一步读输入。输出仍按处理顺序排列，
    // 所以第 0 个槽位装的是来自输入第 4 步的状态。
    let mut reversed_layer = SimpleRNN::new(3, Tanh::new())
        .unwrap()
        .with_random_state(1)
        .with_return_sequences(true)
        .with_go_backwards(true);
    reversed_layer.build(&Shape::with_free_batch(&[2, 5, 4])).unwrap();
    let reversed = reversed_layer.forward(&x, &mut ctx).unwrap();
    assert_eq!(reversed.shape(), &[2, 5, 3]);
    assert!((reversed[[0, 0, 0]] - sequence[[0, 0, 0]]).abs() > 1e-6);

    println!("last {:?}, sequence {:?}", last.shape(), sequence.shape());
}
```

二维或四维输入是硬错误，不会被悄悄 reshape：只要输入不是三维，`forward` 就返回 `Error::InvalidInput`。`forward` 和 `backward` 都接收 `&self` 和一个 `&mut Ctx`，训练时的一遍会把前向激活值寄存进这个上下文。所以在 `forward` 之前调用 `backward` 会返回 `Error::NeuralNetwork(NnError::ForwardPassNotRun("SimpleRNN"))`（对 LSTM、GRU 则是 `"LSTM"`、`"GRU"`）。这些错误变体如何配合，见 [1.6. 错误处理](../Chapter-01/1.6._错误处理.md)。

`Ctx::training()` 和 `Ctx::inference()` 决定一遍传播的模式，本页的层自己都不持有训练标志。手动驱动 1 个层的调用方改用 `forward_mut`，它先用张量把层构建起来，再把这一遍走完。`SequentialBuilder::build` 已经把模型里的每个层都构建好了，所以模型从不需要这个入口。

RustyML 和 Keras 有一处不同：`activation` 参数只控制候选值或输出那一处非线性，不涉及门。在 `SimpleRNN` 里，这个激活作用于每一个隐藏状态；在 `LSTM` 和 `GRU` 里，它作用于候选值，在 LSTM 里还会作用于输出门之前的细胞状态。

门本身永远使用 sigmoid。RustyML 不像 Keras 那样提供独立的 `recurrent_activation` 选项，门的非线性是固定的。Tanh 是默认的激活函数，也是几乎所有已发表架构采用的选择。

## 3.7.2. SimpleRNN 及门控单元存在的理由

`SimpleRNN` 就是教科书里的 Elman 递归：从全零隐藏状态出发，每个时间步用 2 个权重矩阵和 1 个偏置，把当前输入和上一步的隐藏状态混合起来：

```text
h_0 = 0
h_t = activation( x_t @ W + h_{t-1} @ U + b )     for t = 1..T
output = h_T
```

这里 `W` 是输入核 `(input_dim, units)`，`U` 是递归核 `(units, units)`，`b` 是偏置 `(1, units)`，`@` 是沿 batch 维度进行的矩阵乘法。

RustyML 用 Xavier/Glorot 均匀分布初始化 `W`，用正交矩阵（Gram-Schmidt）初始化 `U`。正交递归核是刻意为之，它让状态转移在初始化时保持范数不变，这是延缓下文要讲的梯度消失问题的一种省事办法。

这个问题就是梯度消失，以及它的对立面梯度爆炸。从 `h_T` 反向传播到 `h_1`，每一步都要把上游梯度乘上一个新的雅可比矩阵，大致是 `grad_{t-1} = (activation'(h_t) * grad_t) @ U^T`。把 `T` 步这样的运算串起来，相当于给一个矩阵求 `T` 次幂：如果它的有效量级小于 1，梯度就会指数衰减，网络学不到往前超过几步的依赖关系；如果量级大于 1，梯度反而会爆炸。

正交的 `U` 让 `U^T` 这个因子保持范数不变，`tanh' <= 1` 又把乘积控制在有界范围内。即便如此，这个乘积在长序列上依然会趋向于零。这正是 `SimpleRNN` 只能应付短序列（至多几十步）、碰到长程依赖就失效的原因，也是 LSTM 和 GRU 存在的原因。

## 3.7.3. LSTM：一条加性的记忆高速路

LSTM 增加了第二个状态：细胞状态 `c_t`，它的更新是加性的。LSTM 用 3 个 sigmoid 门来决定写入什么、保留什么、读出什么。RustyML 把 4 个权重块并排融合存放，列的顺序和 Keras 一致，`[input | forget | cell | output]`，记作 `[i | f | g | o]`：

```text
i_t = sigmoid( x_t @ W_i + h_{t-1} @ U_i + b_i )     输入门（写入多少候选值）
f_t = sigmoid( x_t @ W_f + h_{t-1} @ U_f + b_f )     遗忘门（保留多少旧细胞状态）
g_t = act(     x_t @ W_g + h_{t-1} @ U_g + b_g )     候选值（"cell gate"）
o_t = sigmoid( x_t @ W_o + h_{t-1} @ U_o + b_o )     输出门（暴露多少细胞状态）
c_t = f_t * c_{t-1} + i_t * g_t                      细胞状态（加性更新）
h_t = o_t * act(c_t)                                 隐藏状态
```

这里 `*` 是逐元素乘法，`act` 是可配置的激活函数（默认 Tanh），同时作用于候选值和细胞状态。关键的一行是 `c_t = f_t * c_{t-1} + i_t * g_t`：它对 `c_{t-1}` 的梯度就是 `f_t`，一次逐元素乘法，没有反复的矩阵乘法。

当遗忘门打开，也就是 `f` 接近 1 时，细胞状态几乎无损地把梯度往回传，是一条近乎恒等的高速路，加性项则不断汇入这条路。记忆之所以留得住、梯度之所以流得动，是因为主干路径是加法，而不是反复的矩阵相乘。

RustyML 把**遗忘门的偏置初始化为 1.0**，其余偏置全部为零，这给这条记忆高速路一个先发优势。在训练把门调整成形之前，`f` 就已经偏向打开，于是细胞状态连同它的梯度，从第一个 epoch 起就能存活下来。集成测试 `lstm_forget_bias_is_one_not_zero` 就是用来检验这一行为的。LSTM 的参数量相当于 4 个门：`param_count = 4 * (input_dim * units + units * units + units)`。

## 3.7.4. GRU：同一思路，门更少

GRU 保留了 LSTM 的加性混合思路，把输入门和遗忘门合并成一个**更新**门，并去掉了独立的细胞状态，所以只需要 3 个权重块而不是 4 个。RustyML 把它们融合存放，顺序是 `[update | reset | candidate]`，记作 `[z | r | h]`，这个顺序和 Keras 一致：

```text
z_t = sigmoid( x_t @ W_z + h_{t-1} @ U_z + b_z )          更新门
r_t = sigmoid( x_t @ W_r + h_{t-1} @ U_r + b_r )          重置门
n_t = act( x_t @ W_h + (r_t * h_{t-1}) @ U_h + b_h )      候选值
h_t = z_t * h_{t-1} + (1 - z_t) * n_t                     隐藏状态
```

更新门 `z_t` 做的是一次凸混合。当 `z` 接近 1 时，层会把上一步的隐藏状态原封不动地拷过来，这是一条梯度高速路，和关闭的 LSTM 遗忘门效果一样。当 `z` 接近 0 时，层会用新的候选值替换掉上一步的状态。

这是 Keras 的约定。有些资料用的是它的补，从那类资料里搬过来的 `z` 需要翻转。测试 `gru_update_gate_one_keeps_previous_hidden` 和 `gru_update_gate_zero_takes_the_candidate` 分别检验这两个极端，测试 `gru_fused_kernel_first_block_is_the_update_gate` 则检验列的顺序。

要留意重置门作用的确切位置：RustyML 在候选值的递归矩阵乘法**之前**就算好了 `r_t * h_{t-1}`，即 `(r_t * h_{t-1}) @ U_h`。这对应 Cho 等人最初的公式，也就是 Keras 的 `reset_after=False`，而不是 CuDNN 的 `reset_after=True` 变体（后者在矩阵乘法之后才施加重置，并且每个门需要 2 套偏置）。这里每个门只有一套偏置。

GRU 的 `param_count = 3 * (input_dim * units + units * units + units)`，是同等宽度 LSTM 的四分之三。实践中 GRU 训练略快，在很多任务上和 LSTM 打平；当任务需要一段长而精准可控的记忆时，LSTM 有时表现更好。两者的输入核都用 Xavier/Glorot 初始化，用的是每个门各自的扇入 `input_dim + units`，而不是融合后的宽度；每个门的递归块都各自初始化成一个独立的正交矩阵。

## 3.7.5. 权重、形状，以及手动设置

可训练张量及其形状：

| 层 | kernel | recurrent_kernel | bias | 融合的列块 |
|---|---|---|---|---|
| SimpleRNN | `(input_dim, units)` | `(units, units)` | `(1, units)` | 无 |
| LSTM | `(input_dim, 4 * units)` | `(units, 4 * units)` | `(1, 4 * units)` | `[i \| f \| g \| o]` |
| GRU | `(input_dim, 3 * units)` | `(units, 3 * units)` | `(1, 3 * units)` | `[z \| r \| h]` |

把每个门融合进一个矩阵不只是好看：它让输入投影和递归投影在每个时间步都能跑成一个大 GEMM，而不是每个门各跑一个，这在缓存和 SIMD 上带来实打实的收益。你可以用 `LayerBase` trait 里的 `weights()` 检视这些实时数组。这 3 个层都给它们取 Keras 的名字 `kernel`、`recurrent_kernel` 和 `bias`，每一条都带着一个借用的视图：

```rust
use rustyml::neural_network::Shape;
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::recurrent::LSTM;
use rustyml::neural_network::traits::{LayerBase, UnaryLayer};

fn main() {
    // units = 8，每步 4 个特征由 build 定下来。
    let mut lstm = LSTM::new(8, Tanh::new()).unwrap().with_random_state(42);
    lstm.build(&Shape::with_free_batch(&[2, 5, 4])).unwrap();

    // 4 个门并排融合在一起：宽度 == 4 * units。
    for entry in lstm.weights() {
        println!("{:<16} {:?}", entry.name, entry.value.shape());
    }
}
```

```text
kernel           [4, 32]
recurrent_kernel [8, 32]
bias             [1, 32]
```

想要可复现的初始化，调用 `with_random_state(seed)`：在未构建的层上它只记下种子，由 build 按固定顺序把它花在核与递归核的采样上。遗忘门偏置为 1.0 的规则依然生效。不传种子的话，权重就从全局种子或系统熵取种。见 [7.1. 可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)。

要手动装入权重，比如从别的框架移植过来，或者对一段精确的递归做单元测试，每个层都提供 `set_weights(kernel, recurrent_kernel, bias)`，直接接收融合后的矩阵。LSTM 和 GRU 还额外提供 `set_gate_weights(...)`，它按门接收一组 `(kernel, recurrent_kernel, bias)` 三元组，并替你拼接成融合布局。

按门传参的顺序，LSTM 是 `(input, forget, cell, output)`，共 12 个数组；GRU 是 `(reset, update, candidate)`，共 9 个数组。任何对不上的形状都会返回 `Error::NeuralNetwork(NnError::WeightShape { .. })`。保存或加载整个模型时，这些数组会原样序列化，每一个都沿用它在这里的名字。所以位于模型第 2 个位置的循环层写出的是 `2.kernel`、`2.recurrent_kernel` 和 `2.bias`。见 [3.9. 权重保存与加载](./3.9._权重保存与加载.md)。

## 3.7.6. BPTT 与开销模型

这 3 个层其实是同一个层配上不同的单元。一份实现持有构建、批量化的输入投影、沿时间轴的遍历、缓存，以及下面讲的那些归约；单元只持有一个时间步的算术，而这也是把 3 者区分开来的唯一部分。

训练用的是随时间反向传播（BPTT），而且是**完整展开**，没有截断窗口。训练时的一遍会把反向传播需要的一切都寄存进上下文：每个层都寄存进入每个时间步的状态，`SimpleRNN` 和 `GRU` 是隐藏状态，`LSTM` 则是隐藏状态加细胞状态；随后每个单元再寄存只有它自己会读的东西。`SimpleRNN` 不再多存任何东西；`LSTM` 寄存 `activation(c_t)` 以及每个时间步的 4 个门激活值；`GRU` 寄存重置门、更新门、候选值，以及 `r_t * h_{t-1}` 这个乘积。

推理时的一遍这些一概不记录，所以它比训练时的一遍更省。内存开销随 `timesteps` 线性增长：长序列吃的是内存，不只是时间。无论哪种模式，层自身都不持有这些值，所以一个构建好的模型可以同时服务多个线程。

`backward` 反向遍历时间步。它要求的上游梯度就是前向传播吐出来的那个形状：默认是 `(batch, units)`，在 `return_sequences` 下则是 `(batch, timesteps, units)`。每一步，`backward` 都会算出该时间步的预激活梯度，把 `grad_h`（LSTM 还有 `grad_c`）串回上一步，这部分天生**沿时间串行**。

接着 `backward` 把权重梯度的归约批量化：把逐时间步的 `dz` 在 `(batch, timesteps)` 上折叠起来，kernel 和 bias 梯度各自从一个大 GEMM 里算出。递归核的梯度则是：投影了同一个数组的那一组门列块用 1 个 GEMM。`SimpleRNN` 和 `LSTM` 把上一步的隐藏状态投影进每一个门，所以它们只有 1 组，需要 1 个 GEMM；`GRU` 把上一步的隐藏状态投影进更新和重置这 2 个列块，把 `r_t * h_{t-1}` 投影进候选列块，所以它有 2 组，需要 2 个 GEMM。这 3 个结果按 `kernel`、`recurrent_kernel`、`bias` 这几个名字进入上下文的梯度存储，`backward` 只返回输入梯度。存储会把落到同一个地址上的梯度累加起来，所以被图模型 2 个位置共用的层拿到的是总和。层内部**不做**裁剪；如果需要梯度裁剪，用一个提供该功能的优化器。见 [3.4. 优化器](./3.4._优化器.md)。

要记住的性能形态是：**沿时间轴串行，沿 batch 轴和融合的门轴并行**。输入投影 `x @ W` 不依赖递归，RustyML 会一次性把它算完，作为一个跨所有时间步的批量 GEMM。只有 `h_{t-1} @ U` 这一项必须一步一步来，而其中每一步本身又是一个 batch 并行的 GEMM。

GRU 在这上面还能再省一点：它把重置门和更新门的递归投影融合成一个 GEMM，因为两者都要读 `h_{t-1}`。只有候选值的递归投影仍然单独计算，因为它的输入 `r_t * h_{t-1}` 依赖刚算好的重置门。

每一次矩阵乘法都交给 gemmkit 后端（见 [6.2. 矩阵乘法](../Chapter-06/6.2._矩阵乘法.md)）。gemmkit 会根据工作量自行决定并行规模：宽层和大 batch 会自动获得线程并行，小层则保持串行以避免额外开销。一个时间步里融合的门投影，总会在计算乘积的同一趟里施加偏置。只有 `SimpleRNN` 搭配 `ReLU` 时，激活函数才会融合进这一趟里，`LSTM`、`GRU`，以及其他任何激活函数都不会融合。

实用的结论是：更多序列，也就是更大的 batch，能很好地并行；更多时间步则不行，因为那个轴是一条串行的依赖链。线程池的各项设置见 [7.3. 性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)。

## 3.7.7. 堆叠与构建模型

循环层默认只返回最后一个隐藏状态，一个二维的 `(batch, units)` 张量。你**不能**把这个输出直接喂给另一个循环层：循环层要的是三维的 `(batch, timesteps, features)` 输入，面对二维张量只会返回 `Error::InvalidInput`。

在下层加上 `with_return_sequences(true)` 就解决了这个问题。那一层于是吐出 `(batch, timesteps, units)`，正好是下一层要读的秩，而 build 会把这个 `units` 串成下一层的特征宽度。一个堆叠里，除最后一层之外的每一层都要打开这个开关。下面这段程序在下一个例子所用的同一个任务上堆了 2 个 LSTM 层：

```rust
use ndarray::Array;
use rustyml::prelude::*;

fn main() {
    // 4 条序列，3 个时间步，1 个特征。目标 = 这 3 个标量之和。
    let x = Array::from_shape_vec(
        (4, 3, 1),
        vec![0.1, 0.2, 0.1, 0.3, 0.1, 0.2, 0.0, 0.2, 0.2, 0.2, 0.2, 0.1],
    )
    .unwrap()
    .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![0.4, 0.6, 0.4, 0.5])
        .unwrap()
        .into_dyn();

    let mut model = SequentialBuilder::new()
        // (batch, 3, 1) -> (batch, 3, 8)：时间轴保留了下来。
        .add(
            LSTM::new(8, Tanh::new())
                .unwrap()
                .with_random_state(42)
                .with_return_sequences(true),
        )
        // (batch, 3, 8) -> (batch, 8)：第二层把时间轴吃掉。
        .add(LSTM::new(8, Tanh::new()).unwrap().with_random_state(43))
        .add(Dense::new(1, Linear::new()).unwrap())
        .build(&Shape::with_free_batch(x.shape()))
        .unwrap();
    model.compile(
        Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
        MeanSquaredError::new(),
    );

    model.fit(&x, &y, 200).unwrap();
    let pred = model.predict(&x).unwrap();
    assert_eq!(pred.shape(), &[4, 1]);
    println!("prediction shape: {:?}", pred.shape());
}
```

`RepeatVector` 覆盖的是另一种写法：下层保持默认设置，只返回 1 个状态。它把 `(batch, units)` 的状态变成 `(batch, n, units)` 的序列，第二个循环层就能读了。这 `n` 步里每一步装的都是同一个向量，所以第二层看到的是一个常量上下文，而不是第一层逐时间步的状态。这就是 encoder-decoder 的写法，用一个固定的上下文去引导 decoder，也正是两条序列长度不同时该用的写法。层本身见 [3.5. 卷积层](./3.5._卷积层.md) 的 3.5.8 节。

标准的写法是：拿一个循环层当序列编码器，后面接一个稠密头，把最终状态映射到目标上。这样组合起来很干净：循环层把 `(batch, timesteps, features)` 变成 `(batch, units)`，`Dense` 要的恰好就是这个二维形状。

下面的示例学的是一个真实的序列任务：预测一条长度为 3 的标量序列之和。它用 `LSTM` 编码器、一个 `Dense` 读出层、`Adam`、均方误差搭起来，能在几百个全批量 epoch 内收敛（回想 [3.1. Sequential模型](./3.1._Sequential模型.md) 中提到，`fit` 每个 epoch 只走一步全批量梯度）：

```rust
use ndarray::Array;
use rustyml::prelude::*;

fn main() {
    // 4 条序列，3 个时间步，1 个特征。目标 = 3 个标量之和。
    let x = Array::from_shape_vec(
        (4, 3, 1),
        vec![
            0.1, 0.2, 0.1, // 和为 0.4
            0.3, 0.1, 0.2, // 和为 0.6
            0.0, 0.2, 0.2, // 和为 0.4
            0.2, 0.2, 0.1, // 和为 0.5
        ],
    )
    .unwrap()
    .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![0.4, 0.6, 0.4, 0.5])
        .unwrap()
        .into_dyn();

    let mut model = SequentialBuilder::new()
        // 循环特征提取器：(batch, 3, 1) -> (batch, 16)
        .add(LSTM::new(16, Tanh::new()).unwrap().with_random_state(42))
        // 把最后的隐藏状态读出成单个标量。
        .add(Dense::new(1, Linear::new()).unwrap())
        .build(&Shape::with_free_batch(x.shape()))
        .unwrap();
    model.compile(
        Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
        MeanSquaredError::new(),
    );

    model.fit(&x, &y, 300).unwrap();

    let pred = model.predict(&x).unwrap();
    println!("target      : {:?}", y.as_slice().unwrap());
    println!("prediction  : {:?}", pred.as_slice().unwrap());
}
```

300 个 epoch 之后，4 个预测值都落在 `[0.4, 0.6, 0.4, 0.5]` 附近的几个百分点以内。LSTM 学会了累加这条序列，稠密头再把累加结果读出来。把 `LSTM` 换成 `GRU` 或 `SimpleRNN`，同一套代码照样能编译、能训练：在这条短序列上，3 种层都会收敛，这恰恰说明门控单元在梯度消失上的优势，只有在长序列上才会显现出来。

`model.summary()` 会把每个循环层的输出形状打印成 `(None, units)`，在 `return_sequences` 下则打印成 `(None, timesteps, units)`，其中 `timesteps` 就是 build 串进来的那个长度。如果你对着一根自由的时间轴构建模型，这根轴也会打印成 `None`。数据集只要比玩具规模大一些，就应该用 `fit_with_batches` 代替 `fit`，这样每个 epoch 会走好几步小批量，并重新洗牌数据。

## 3.7.8. Embedding：从索引到向量

本页的每一个层读的都是浮点张量，而文本并不是这种形态。分词器给你的是 `[7, 42, 3]` 这样的词索引，索引是一个名字，不是可以相加的量。`Embedding` 就是这座桥：它持有一张可训练的表，词表里每一项占一行，然后把每个索引替换成对应的那一行。

`Embedding::new(input_dim, output_dim)` 决定表的形状，而且它**两个**参数都保留着。`input_dim` 是词表大小，不是任何张量的一根轴，因此可用的最大索引是 `input_dim - 1`。这也正是输入的形状在这里定不下任何东西的原因，以及这个构造函数一个参数都没丢的原因。`output_dim` 是单个向量的宽度。该层把这个宽度作为新的末轴追加上去，所以输出的秩总是比输入的秩多 1。

| 输入形状 | 输出形状 | 典型用途 |
| --- | --- | --- |
| `[N]` | `[N, output_dim]` | 每个样本 1 个索引 |
| `[N, T]` | `[N, T, output_dim]` | 一批长度为 `T` 的 token 序列 |
| `[N, T, K]` | `[N, T, K, output_dim]` | 一批 token 网格 |

这里真正要紧的是中间那一行：它恰好就是 [3.7.1](#371-输入输出约定) 里那条 `(batch_size, timesteps, features)` 约定，因此 `Embedding` 可以直接喂给循环层，中间不需要任何 reshape。

`Tensor` 装的是 `f32`，所以索引是以浮点值的形式送进来的。该层先把每个值向 0 截断，再做检查：`2.0` 和 `2.9` 都选中第 2 行，`-0.5` 选中第 0 行。这与 Keras 转成整数时用的规则一致。落在 `0..input_dim` 之外的索引，以及任何非有限值，都会返回一个点名了该值的 `Error::InvalidInput`。

Keras 把这 2 种情况交给后端处理。越界索引会给出 `NaN`，负索引则会绕回表的末尾。

这张表是唯一的参数，所以 `param_count()` 报告的是 `input_dim * output_dim`。它从 `[-0.05, 0.05]` 上的均匀分布起步，这是 Keras 给这个层的默认值，而不是 `Dense` 用的 Xavier/Glorot 规则。调用 `.with_random_state(seed)` 可以让这次抽样可复现。这个层给表取的是 Keras 的名字 `embeddings`：用 `weight("embeddings")` 读表，用 `set_weights(table)` 写表。两者都用 `(input_dim, output_dim)` 这个形状。

反向传播会把上游梯度加进每个索引选中的那一行。被 2 个位置选中的行会拿到两者之和，而没有被任何索引选中的行，梯度恰好保持为 0。梯度仍然按整张表稠密存储，所以无论 batch 里装了什么，1 步优化的代价都是 `input_dim * output_dim`。动量项或权重衰减同样会移动梯度为 0 的行，因为这 2 条规则作用的是参数本身。Keras 在它的稠密更新路径上也是同样的行为。

下面的例子是标准文本流水线的缩微版。它对一条 4 个 token 的序列做分类，把 `Embedding`、`LSTM` 和 `Dense` 叠在一起：

```rust
use ndarray::Array;
use rustyml::prelude::*;

fn main() {
    // 4 个句子，每句 4 个 token 索引，取自一个 10 词的词表
    let x = Array::from_shape_vec(
        (4, 4),
        vec![
            1.0, 2.0, 3.0, 4.0, // 以 token 1 开头
            5.0, 6.0, 7.0, 8.0, // 以 token 5 开头
            1.0, 2.0, 7.0, 8.0, // 以 token 1 开头
            5.0, 6.0, 3.0, 4.0, // 以 token 5 开头
        ],
    )
    .unwrap()
    .into_dyn();
    // 句子以 token 1 开头时标签为 1，以 token 5 开头时标签为 0
    let y = Array::from_shape_vec((4, 1), vec![1.0, 0.0, 1.0, 0.0])
        .unwrap()
        .into_dyn();

    let mut model = SequentialBuilder::new()
        // 索引转向量：(batch, 4) -> (batch, 4, 8)
        .add(Embedding::new(10, 8).unwrap().with_random_state(42))
        // 序列编码器：(batch, 4, 8) -> (batch, 16)
        .add(LSTM::new(16, Tanh::new()).unwrap().with_random_state(7))
        // 把最后的隐状态读成 1 个概率
        .add(Dense::new(1, Sigmoid::new()).unwrap().with_random_state(3))
        .build(&Shape::with_free_batch(x.shape()))
        .unwrap();
    model.compile(
        Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
        BinaryCrossEntropy::new(),
    );

    model.summary();
    model.fit(&x, &y, 200).unwrap();

    let pred = model.predict(&x).unwrap();
    println!("target     : {:?}", y.as_slice().unwrap());
    println!("prediction : {:?}", pred.as_slice().unwrap());
}
```

200 个 epoch 之后，4 个预测值与 `[1.0, 0.0, 1.0, 0.0]` 的差距都在千分之一以内。`model.summary()` 会把 embedding 的输出形状打印成 `(None, 4, 8)`，而且不需要任何一次前向传播：build 已经把索引批次的 `(None, 4)` 形状交给了这个层，`compute_output_shape` 再把向量宽度追加上去。

有一个 Keras 参数在这里没有对应物。`mask_zero` 把索引 0 标记为 padding，并为后面的层构造一个掩码。RustyML 不传播任何掩码，所以这个开关不会改变任何东西；与其接受了再忽略，不如干脆不提供。请把序列补齐到固定长度，让模型自己学到那个 padding 索引不携带信息。

## 3.7.9. 一个双向模型

没有 `Bidirectional` 包装层。图模型用零件拼出一个来，零件是 2 个循环层、1 个 `Reverse` 和 1 个合并层：

```rust,ignore
let input = builder.input(Shape::known(&[batch, steps, features]));
let forward = builder.add(LSTM::new(8, Activation::Tanh)?.with_return_sequences(true), &[input]);
let backward = builder.add(
    LSTM::new(8, Activation::Tanh)?
        .with_return_sequences(true)
        .with_go_backwards(true),
    &[input],
);
let aligned = builder.add(Reverse::new(1), &[backward]);
let merged = builder.add(Concatenate::new(-1), &[forward, aligned]);
```

**这个 `Reverse` 不是可选的。**反向分支按处理顺序吐出状态，所以它的第 `k` 槽装的是输入时间步 `steps - 1 - k` 的状态，而前向分支的第 `k` 槽装的是时间步 `k`。不加反转就合并，等于在每个位置上都把不匹配的时间步配到一起，而且没有任何东西会报告这件事。`Reverse::new(1)` 把这个分支翻回输入顺序，之后反向分支的第 0 槽装的就是消费了输入时间步 0 的那个状态，也正是前向分支在那个位置上装的东西。见 [3.5. 卷积层](./3.5._卷积层.md) 的 3.5.8 节。

如果 `return_sequences` 保持 false，就不需要反转，而且 `Reverse` 会拒绝那个 rank-2 输入，因为这时分支每个样本只返回 1 个状态，那个状态本来就已经消费到输入时间步 0 了。

**给两个分支不同的种子。**它们是两个独立的层、各有各的权重，而用同一个种子构建的 2 个层会抽出完全相同的权重。

**不要让两个分支共用 1 个层。**图允许若干个节点调用同 1 个层，那是真正的权重共享，但 `go_backwards` 是层的一个字段，不是调用的参数。共用的层因此在两个节点上跑的是**同一个方向**，第二个分支根本不携带任何反向信息。模型照样构建、照样预测、照样训练，而且什么都不报。

**批次里有 padding 时要当心。**这个 crate 不带 mask。位于序列尾部的 padding 在反转后的分支里位于头部，于是反向的递归是从 padding 开始跑的。长度不齐的批次，请自己按样本把值翻好再喂给模型。
