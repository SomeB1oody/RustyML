# 3.7. 循环层

RustyML 提供三种循环层——`SimpleRNN`、`LSTM`、`GRU`——它们都位于 `rustyml::neural_network::layers::recurrent`，并通过 prelude 重新导出。三者共用同一套约定：接收一个三维序列张量，沿时间轴从左到右跑一遍递归，返回最后的隐藏状态。从 Keras 过来的话，可以把它们理解成把 `return_sequences=False` 焊死的 `SimpleRNN`/`LSTM`/`GRU`——这个“焊死”对你如何堆叠它们有实打实的影响，所以在动手搭深层循环网络之前，先读 [3.7.7 节](#377-堆叠与构建模型)。

## 3.7.1. 输入/输出约定

每个循环层都要求一个三维输入张量，布局为 `(batch_size, timesteps, features)`，输出则是二维的 `(batch_size, units)`。`features` 轴必须等于你传给构造函数的 `input_dim`；`units` 就是你指定的隐藏层宽度。递归会把时间步轴吃掉，它不出现在输出里——只有最后一个隐藏状态 `h_T` 活下来。

```rust
use ndarray::Array;
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::recurrent::SimpleRNN;
use rustyml::neural_network::traits::Layer;

fn main() {
    // input_dim = 4 个每步特征，units = 3 个隐藏神经元
    let rnn = SimpleRNN::new(4, 3, Tanh::new()).unwrap();

    // (batch = 2, timesteps = 5, features = 4)
    let x = Array::zeros((2, 5, 4)).into_dyn();

    // predict 只跑递归，不记录反向传播所需的缓存
    let out = rnn.predict(&x).unwrap();

    // 时间步轴消失了：只有最后一个隐藏状态留了下来。
    println!("output shape: {:?}", out.shape()); // [2, 3] == (batch, units)
}
```

```text
output shape: [2, 3]
```

三种层的构造函数完全一致：`new(input_dim, units, activation) -> Result<Self, Error>`。激活参数的类型是 `impl Into<Activation>`，所以你既可以传一个 `Activation` 枚举变体（`Activation::Tanh`），也可以传某个轻量的层包装（`Tanh::new()`、`ReLU::new()`、`Sigmoid::new()`、`Linear::new()`、`Softmax::new()`）——它们都会转成同一个枚举。完整的激活函数目录见 [3.2. 全连接层与激活函数](./3.2._全连接层与激活函数.md)。`input_dim` 或 `units` 为 0 时，`new` 返回 `Error::InvalidParameter`。这里**没有** `return_sequences`、`return_state`、`bidirectional`，也没有 cell 内 dropout 选项；层永远返回最后的状态，永远沿时间正向推进，永远走同一套稠密实现。

喂进来的不是三维张量，就是硬错误，而不是悄悄 reshape：二维或四维输入会让 `forward`/`predict` 返回 `Error::InvalidInput`。因为层会缓存前向激活值供反向传播使用，在 `forward` 之前调用 `backward` 会返回 `Error::NeuralNetwork(NnError::ForwardPassNotRun("SimpleRNN"))`（或 `"LSTM"`/`"GRU"`）。这些错误变体之间如何配合，见 [1.6. 错误处理](../Chapter-01/1.6._错误处理.md)。

有一个细节最好早点记牢，因为它和 Keras 不一样：`activation` 参数只控制*候选值/输出*那一处非线性。在 `SimpleRNN` 里，它作用于每一个隐藏状态。在 `LSTM` 和 `GRU` 里，它作用于候选值（对 LSTM 还作用于输出门之前的细胞状态）——但门本身**永远**是 sigmoid。RustyML 不暴露 Keras 那个独立的 `recurrent_activation`；门的非线性是固定的。Tanh 是合理的默认值，也是几乎每一个已发表架构采用的选择。

## 3.7.2. SimpleRNN 及门控单元存在的理由

`SimpleRNN` 就是教科书里的 Elman 递归。从全零隐藏状态出发，每个时间步用两个权重矩阵和一个偏置，把当前输入和上一步的隐藏状态混在一起：

```text
h_0 = 0
h_t = activation( x_t @ W + h_{t-1} @ U + b )     for t = 1..T
output = h_T
```

其中 `W` 是输入核 `(input_dim, units)`，`U` 是递归核 `(units, units)`，`b` 是偏置 `(1, units)`，`@` 是沿 batch 维度进行的矩阵乘法。`W` 用 Xavier/Glorot 均匀分布初始化，`U` 用正交初始化（Gram-Schmidt）；正交递归核是刻意为之——它让状态转移在初始化时保持范数不变，这是延缓本节要讲的那个问题的最省事办法。

这个问题就是梯度消失（以及梯度爆炸）。从 `h_T` 反向传播到 `h_1`，每一步都要把上游梯度乘上一个新鲜的雅可比矩阵：大致是 `grad_{t-1} = (activation'(h_t) ⊙ grad_t) @ Uᵀ`。把 `T` 个这样的因子串起来，相当于给一个矩阵求 `T` 次幂。如果它的有效量级小于 1，梯度就指数衰减，网络学不到往前超过区区几步的依赖关系；大于 1 就会炸掉。正交的 `U` 把 `Uᵀ` 这个因子钉成范数不变，`tanh' ≤ 1` 又把整体压在有界范围内，可乘积在长序列上依旧会趋向于零。这正是 `SimpleRNN` 应付短序列（几十步）没问题、碰上长程依赖却毫无用处的原因——也是 LSTM 和 GRU 存在的原因。

## 3.7.3. LSTM：一条加性的记忆高速路

LSTM 加了第二个状态——细胞状态 `c_t`——它的更新是*加性*的，并用三个 sigmoid 门来决定写入什么、保留什么、读出什么。RustyML 把四个权重块并排融合存放，列的顺序沿用 Keras 的 `[input | forget | cell | output]`，记作 `[i | f | g | o]`：

```text
i_t = sigmoid( x_t @ W_i + h_{t-1} @ U_i + b_i )     输入门（写入多少候选值）
f_t = sigmoid( x_t @ W_f + h_{t-1} @ U_f + b_f )     遗忘门（保留多少旧细胞状态）
g_t = act(     x_t @ W_g + h_{t-1} @ U_g + b_g )     候选值（"cell gate"）
o_t = sigmoid( x_t @ W_o + h_{t-1} @ U_o + b_o )     输出门（暴露多少细胞状态）
c_t = f_t * c_{t-1} + i_t * g_t                      细胞状态（加性更新）
h_t = o_t * act(c_t)                                 隐藏状态
```

`*` 是逐元素乘法，`act` 是可配置的激活函数（默认 Tanh，同时作用于候选值和细胞状态）。真正关键的是 `c_t = f_t * c_{t-1} + i_t * g_t` 这一行。它对 `c_{t-1}` 的梯度就是 `f_t`——一次逐元素乘法，没有反复的矩阵乘法。当遗忘门打开（`f ≈ 1`）时，细胞状态几乎不衰减地把梯度往回传，是一条近乎恒等的高速路，加性项则源源不断地汇入这条路。全部诀窍就在这里：记忆之所以留得住、梯度之所以流得动，是因为主干路径是加法，而不是反复的矩阵相乘。

为了让这条高速路一起步就有加速度，RustyML 把**遗忘门的偏置初始化成 1.0**（其余偏置全为零）。在训练把门调整成形之前，`f` 一开始就偏向打开，于是细胞状态——连同它的梯度——从第一个 epoch 起就能存活。集成测试 `lstm_forget_bias_is_one_not_zero` 存在的意义，正是为了把这个行为钉死。LSTM 的参数量是四个门的份量：`param_count = 4 * (input_dim * units + units * units + units)`。

## 3.7.4. GRU：同一思路，门更少

GRU 保留了加性混合的直觉，但把 LSTM 的输入门和遗忘门合并成一个**更新**门，并砍掉了独立的细胞状态，所以它只需要三个权重块而非四个，融合存放的顺序是 `[reset | update | candidate]` = `[r | z | h]`：

```text
r_t = sigmoid( x_t @ W_r + h_{t-1} @ U_r + b_r )          重置门
z_t = sigmoid( x_t @ W_z + h_{t-1} @ U_z + b_z )          更新门
n_t = act( x_t @ W_h + (r_t * h_{t-1}) @ U_h + b_h )      候选值
h_t = (1 - z_t) * h_{t-1} + z_t * n_t                     隐藏状态
```

更新门 `z_t` 做的是凸混合：`z ≈ 0` 把上一步的隐藏状态原封不动地拷过来（一条梯度高速路，和打开的 LSTM 遗忘门一模一样），`z ≈ 1` 则用新鲜的候选值把它换掉。测试 `gru_update_gate_zero_leaves_hidden_unchanged` 和 `gru_update_gate_one_replaces_hidden_with_candidate` 正好卡住这两个极端。要留意重置门作用的*位置*：RustyML 在候选值的递归矩阵乘法**之前**就算好 `r_t * h_{t-1}`（`(r_t * h_{t-1}) @ U_h`），这是 Cho 等人最初的公式——对应 Keras 的 `reset_after=False`，而不是 CuDNN 那个 `reset_after=True` 变体（后者在矩阵乘法之后才施加重置，并带两套偏置）。这里每个门只有一套偏置。

GRU 的 `param_count = 3 * (input_dim * units + units * units + units)`——是同等宽度 LSTM 的四分之三。实践中 GRU 训练略快，在很多任务上和 LSTM 打平；当需要一段长而精准可控的记忆时，LSTM 有时能略胜一筹。两者的输入核都用 Xavier/Glorot 初始化（用的是每个门各自的扇入 `input_dim + units`，而不是融合后的宽度），每个门的递归块则各自初始化成一个独立的正交矩阵。

## 3.7.5. 权重、形状，以及手动设置

可训练张量及其形状：

| 层 | kernel | recurrent_kernel | bias | 融合的列块 |
|---|---|---|---|---|
| SimpleRNN | `(input_dim, units)` | `(units, units)` | `(1, units)` | 无 |
| LSTM | `(input_dim, 4 * units)` | `(units, 4 * units)` | `(1, 4 * units)` | `[i \| f \| g \| o]` |
| GRU | `(input_dim, 3 * units)` | `(units, 3 * units)` | `(1, 3 * units)` | `[r \| z \| h]` |

把每个门融进一个矩阵不是花架子——它让输入投影和递归投影在每个时间步都跑成一个大 GEMM，而不是每个门各跑一个，这在缓存和 SIMD 上是实打实的收益。你可以用 `get_weights()` 检视这些实时数组，它返回一个 `LayerWeight::{SimpleRNN,LSTM,GRU}`，里面带着借用的 `kernel`/`recurrent_kernel`/`bias` 字段：

```rust
use rustyml::neural_network::layers::activation::Tanh;
use rustyml::neural_network::layers::layer_weight::LayerWeight;
use rustyml::neural_network::layers::recurrent::LSTM;
use rustyml::neural_network::traits::Layer;

fn main() {
    // input_dim = 4，units = 8。with_random_state 让初始化可复现。
    let lstm = LSTM::new(4, 8, Tanh::new()).unwrap().with_random_state(42);

    match lstm.get_weights() {
        LayerWeight::LSTM(w) => {
            // 4 个门并排融合在一起：宽度 == 4 * units。
            println!("kernel           {:?}", w.kernel.shape()); // [4, 32]
            println!("recurrent_kernel {:?}", w.recurrent_kernel.shape()); // [8, 32]
            println!("bias             {:?}", w.bias.shape()); // [1, 32]
        }
        _ => unreachable!(),
    }
}
```

```text
kernel           [4, 32]
recurrent_kernel [8, 32]
bias             [1, 32]
```

想要可复现的初始化，`with_random_state(seed)` 会用确定的方式重跑核与递归核的采样（遗忘门偏置为 1.0 的规则依旧生效）；不带它，权重则从全局种子或系统熵取种。见 [7.1. 可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)。

想手动装入权重——从别的框架移植，或是对一段精确的递归做单元测试——每个层都有 `set_weights(kernel, recurrent_kernel, bias)`，接收融合后的矩阵；LSTM/GRU 还额外提供 `set_gate_weights(...)`，它*按门*接收一组 `(kernel, recurrent_kernel, bias)` 三元组，并替你拼接成融合布局。按门传参的顺序，LSTM 是 `(input, forget, cell, output)`（十二个数组），GRU 是 `(reset, update, candidate)`（九个数组）。任何对不上的形状都会返回 `Error::NeuralNetwork(NnError::WeightShape { .. })`。保存或加载整个模型时，这些数组会原样序列化；见 [3.9. 权重保存与加载](./3.9._权重保存与加载.md)。

## 3.7.6. BPTT 与开销模型

训练用的是随时间反向传播（BPTT），而且是**完整展开**——没有截断窗口。前向传播时，层会把反向传播需要的一切都缓存下来：`SimpleRNN` 存每一个隐藏状态（前面补上 `h_0 = 0`）；`LSTM` 额外存细胞状态、`activation(c_t)`，以及每个时间步的四个门激活值；`GRU` 存重置门/更新门、候选值，还有 `r_t * h_{t-1}` 这个乘积。`predict` 给这些缓存传 `None`，跳过记录（以及那些克隆），这就是推理为什么比训练时的 `forward` 更省的原因。于是内存开销随 `timesteps` 线性增长——长序列吃的是内存，而不只是时间。

`backward` 反向遍历时间步。它要求一个二维的上游梯度 `(batch, units)`——也就是损失对最终隐藏状态的梯度——因为层对外吐出来的只有这个最终状态。每一步它算出该时间步的预激活梯度，把 `grad_h`（LSTM 还有 `grad_c`）串回上一步；这部分天生**沿时间串行**。接着它把权重梯度的归约批量化：逐时间步的 `dz` 在 `(batch, timesteps)` 上折叠，kernel/递归/bias 三个梯度各自从一个大 GEMM 里掉出来。梯度以替换语义存储，并且层内部**不做**裁剪——需要梯度裁剪的话，用一个提供裁剪功能的优化器（见 [3.4. 优化器](./3.4._优化器.md)）。

要记住的性能形态是：**沿时间轴串行，沿 batch 轴（以及融合的门轴）并行**。输入投影 `x @ W` 不依赖递归，所以一开始就作为一个跨所有时间步的批量 GEMM 一次算完。只有 `h_{t-1} @ U` 这一项必须一步一步来，而其中每一步本身又是一个 batch 并行的 GEMM。GRU 在这上面又多榨了一点：它把重置门和更新门的递归投影融成一个 GEMM（两者都读 `h_{t-1}`）；只有候选值的递归投影仍然单独算，因为它的输入 `r_t * h_{t-1}` 依赖刚算好的重置门。每一次矩阵乘法都走 `gemm_par_auto`，也就是本 crate 那个按规模自适应的并行 GEMM（[6.2. 矩阵乘法](../Chapter-06/6.2._矩阵乘法.md)），于是宽层和大 batch 自动吃到线程并行，小的则保持串行以免白搭开销。实用的结论是：往循环层里塞更多序列（batch）能很好地并行；塞更多时间步则不行——那个轴是一条串行的依赖链。线程池的各个旋钮见 [7.3. 性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)。

## 3.7.7. 堆叠与构建模型

循环层只返回最后一个隐藏状态——一个二维的 `(batch, units)` 张量——所以你**不能**把它的输出直接喂给另一个循环层：后者要的是三维的 `(batch, timesteps, features)` 输入，面对二维张量只会甩回 `Error::InvalidInput`。没有 `return_sequences` 选项，就没办法吐出一条逐时间步的序列，于是 Keras 意义上那种循环层的深层堆叠，在这里根本写不出来。这是一个需要提前规划的实打实的限制，不是可以糊弄过去的细节。

所以地道的写法是：拿一个循环层当序列编码器，后面接一个稠密头，把最终状态映射到你的目标上。这样组合起来很干净：循环层把 `(batch, timesteps, features)` 变成 `(batch, units)`，`Dense` 要的恰好就是这个二维形状。下面的示例学的是一个真正的序列任务——预测一条长度为 3 的标量序列之和——用 `LSTM` 编码器、一个 `Dense` 读出层、`Adam` 和均方误差搭起来。它在几百个全批量 epoch 内收敛（回想 [3.1. Sequential模型](./3.1._Sequential模型.md) 里说过，`fit` 每个 epoch 只走一步全批量梯度）：

```rust
use ndarray::Array;
use rustyml::neural_network::sequential::Sequential;
use rustyml::prelude::*;

fn main() {
    // 4 条序列，3 个时间步，1 个特征。目标 = 3 个标量之和。
    let x = Array::from_shape_vec(
        (4, 3, 1),
        vec![
            0.1, 0.2, 0.1, // 和为 0.4
            0.3, 0.1, 0.2, // 和为 0.6
            0.0, 0.2, 0.2, // 和为 0.4
            0.2, 0.2, 0.1, // 和为 0.5
        ],
    )
    .unwrap()
    .into_dyn();
    let y = Array::from_shape_vec((4, 1), vec![0.4, 0.6, 0.4, 0.5])
        .unwrap()
        .into_dyn();

    let mut model = Sequential::new();
    model
        // 循环特征提取器：(batch, 3, 1) -> (batch, 16)
        .add(LSTM::new(1, 16, Tanh::new()).unwrap().with_random_state(42))
        // 把最后的隐藏状态读出成单个标量。
        .add(Dense::new(16, 1, Linear::new()).unwrap())
        .compile(
            Adam::new(0.01, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    model.fit(&x, &y, 300).unwrap();

    let pred = model.predict(&x).unwrap();
    println!("target      : {:?}", y.as_slice().unwrap());
    println!("prediction  : {:?}", pred.as_slice().unwrap());
}
```

300 个 epoch 之后，四个预测值都落在 `[0.4, 0.6, 0.4, 0.5]` 附近几个百分点以内——LSTM 学会了累加这条序列，稠密头再把累加结果读出来。把 `LSTM` 换成 `GRU` 或 `SimpleRNN`，同一套骨架照样能编译、能训练；在这条短到不能再短的序列上，三者都会收敛，而这恰恰说明门控单元在梯度消失上的优势要等序列变长了才显现出来。`model.summary()` 会把每个循环层的输出形状打印成 `(None, units)`，其中 `None` 代表动态的 batch 维度。数据集只要比玩具规模大一点，就优先用 `fit_with_batches` 而不是 `fit`，这样每个 epoch 会走好几步小批量并重新洗牌。
