# 3.5. 卷积层

RustyML 提供五种卷积层——`Conv1D`、`Conv2D`、`Conv3D`、`DepthwiseConv2D` 和 `SeparableConv2D`——它们都位于 `rustyml::neural_network::layers`，并由 layers 的 glob 导入统一重新导出。这五种层共享同一套设计：层结构体持有权重、偏置、激活函数以及前向/反向传播的缓存，普通卷积的实际数值运算则交给一个维度泛型的引擎完成。如果你用过 Keras，这里的布局和权重形状就是你已经熟悉的那一套——张量是 channels-last，kernel 的抽头排在最前——所以真正容易一开始踩坑的是另一点：你要把完整的输入形状传进构造函数，让层能提前确定权重尺寸，而不是等第一个 batch 到来时才惰性推断。本页覆盖这些布局、构造函数与填充语义、驱动标准卷积的 im2col + GEMM 引擎、深度可分离卷积的分解及其开销计算，以及它暴露的错误类型。

## 3.5.1. 张量布局与层家族

这里的每一种卷积都是 channels-last：空间轴跟在 batch 轴之后，通道轴排在最末。`Conv2D` 读入 `[batch, height, width, channels]`，输出 `[batch, out_height, out_width, filters]`。这就是 Keras/TensorFlow 的 `NHWC` 约定，所以为 Keras 准备的张量拿过来不需要任何置换；如果你用 `ndarray` 手工构造输入，记得把通道放在最后一个轴。权重张量用的也是 Keras 的 kernel 形状：先是 kernel 的各个抽头，然后是输入通道，最后是 filters。

这不只是接口上的选择。通道轴在最内层时，「一个 kernel 抽头在一个输出位置上」对应的是 `Cin` 个**连续**的 float——正是这一点让下面的引擎能用整段拷贝而不是逐标量 gather 来搭 im2col 矩阵，也让扁平的权重矩阵不经任何置换就能对齐上去。

| 层 | 输入张量 | 权重张量 | 偏置 | 输出张量 |
| --- | --- | --- | --- | --- |
| `Conv1D` | `[N, Cin, L]` | `[F, Cin, k]` | `[1, F]` | `[N, F, L']` |
| `Conv2D` | `[N, Cin, H, W]` | `[F, Cin, kh, kw]` | `[1, F]` | `[N, F, H', W']` |
| `Conv3D` | `[N, Cin, D, H, W]` | `[F, Cin, kd, kh, kw]` | `[1, F]` | `[N, F, D', H', W']` |
| `DepthwiseConv2D` | `[N, C, H, W]` | `[C, 1, kh, kw]` | `[C]` | `[N, C, H', W']` |
| `SeparableConv2D` | `[N, Cin, H, W]` | depthwise `[dm, Cin, kh, kw]`，pointwise `[F, Cin·dm, 1, 1]` | `[1, F]` | `[N, F, H', W']` |

其中两行值得停下来看看。`DepthwiseConv2D` 把 filter 数量锁定为输入通道数，每个通道携带一个 `kh×kw` 的 kernel，所以它的权重张量有一个大小为 1 的通道轴，偏置是一个普通的一维 `Array1`——这是整个家族里唯一偏置形状不是 `[1, F]` 的层。`SeparableConv2D` 持有两个权重张量，因为它把两个卷积融进了一层；细节见 3.5.4。

前向计算是互相关（cross-correlation），与 Keras 和 PyTorch 的约定一致——kernel 不做翻转——偏置在最后加上，每个 filter 加一次，发生在乘累加之后。权重按 Xavier/Glorot 均匀分布的边界初始化，偏置从零开始。下面在层这一级手动设置权重跑一次前向，直观地展示布局和 Valid 填充下的输出尺寸：

```rust
use ndarray::{Array, Array1, Array4};
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;

fn main() {
    // channels-last：[batch, height, width, channels]。
    let mut layer = Conv2D::new(1, (2, 2), vec![1, 4, 4, 1], (1, 1), Activation::Linear).unwrap();

    // 权重是 [filters, channels, kernel_h, kernel_w]；偏置是 [1, filters]。
    let weights = Array4::from_elem((2, 2, 1, 1), 1.0f32);
    let bias = Array1::zeros(1);
    layer.set_weights(weights, bias).unwrap();

    let pixels: Vec<f32> = (1..=16).map(|v| v as f32).collect();
    let x = Array::from_shape_vec((1, 4, 4, 1), pixels).unwrap().into_dyn();

    let out = layer.forward(&x).unwrap();
    // Valid 填充：每个空间轴 (4 - 2)/1 + 1 = 3 -> [1, 1, 3, 3]。
    assert_eq!(out.shape(), &[1, 3, 3, 1]);
    // 全 1 的 2x2 核就是窗口求和：第一个窗口是 1 + 2 + 5 + 6 = 14。
    assert_eq!(out[[0, 0, 0, 0]], 14.0);
    println!("output shape: {:?}", out.shape());
}
```

## 3.5.2. 构造函数、填充与输出形状

构造函数按位置接收超参数，kernel/stride 参数的形状随秩变化：`Conv1D` 用标量的 `kernel_size` 和 `stride`，而 2-D 与 3-D 的层用元组。`SeparableConv2D` 在激活函数之前插入一个 `depth_multiplier` 参数。

```rust,ignore
Conv1D::new(filters, kernel_size: usize, input_shape: Vec<usize>, stride: usize, activation) -> Result<Conv1D, Error>
Conv2D::new(filters, kernel_size: (usize, usize), input_shape: Vec<usize>, strides: (usize, usize), activation) -> Result<Conv2D, Error>
Conv3D::new(filters, kernel_size: (usize, usize, usize), input_shape: Vec<usize>, strides: (usize, usize, usize), activation) -> Result<Conv3D, Error>
DepthwiseConv2D::new(kernel_size: (usize, usize), input_shape: Vec<usize>, strides: (usize, usize), activation) -> Result<DepthwiseConv2D, Error>
DepthwiseConv2D::with_depth_multiplier(self, depth_multiplier: usize) -> Result<DepthwiseConv2D, Error>   // builder，默认 1
SeparableConv2D::new(filters, kernel_size: (usize, usize), input_shape: Vec<usize>, strides: (usize, usize), depth_multiplier: usize, activation) -> Result<SeparableConv2D, Error>
```

`activation` 的类型是 `impl Into<Activation>`，所以你既可以传一个 `Activation` 枚举变体（`Activation::ReLU`、`Activation::Sigmoid`、`Activation::Tanh`、`Activation::Softmax`、`Activation::Linear`），也可以传一个独立的激活层，比如 `ReLU::new()`。你传入的 `input_shape` 是包含 batch 维度在内的完整期望输入；真正决定权重尺寸的只有 `input_shape[1..]`（通道与各个空间尺寸），所以你写的 batch 值只起说明作用。激活函数集合的详细介绍见 [3.2. 全连接层与激活函数](./3.2._全连接层与激活函数.md)。

三个 builder 方法可以进一步调整已构造的层，每个都消费并返回 `self`，因此可以链式调用：`with_padding(PaddingType)` 切换填充模式，`with_random_state(u64)` 用一个种子确定性地重跑 Xavier 初始化（在设置自定义权重或训练之前调用它——见 [7.1. 可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)），`set_weights(...)` 则装入你自己控制的权重和偏置。`set_weights` 会用层的期望形状校验每一个数组；注意 `DepthwiseConv2D::set_weights` 接收的偏置是 `Array1`，而 `SeparableConv2D::set_weights` 接收三个数组——depthwise 权重、pointwise 权重，然后是偏置。

填充由 `PaddingType` 枚举控制，它有两个变体：`Valid`（默认）和 `Same`，输出尺寸由它决定：

- `Valid` 不做任何填充，只在 kernel 完全覆盖的位置计算：每个空间轴 `out = (in - k) / stride + 1`（整数向下取整）。它要求每个输入轴都不小于 kernel 尺寸。
- `Same` 在边界补零，使得 `out = ceil(in / stride)`。当 `stride == 1` 时空间尺寸原样保留；stride 更大时，输出等于输入长度除以 stride 再向上取整。总填充量在两侧拆分，多出来的一格放在尾部（`pad_before = pad_total / 2`），与 TensorFlow 的 `SAME` 一致。

几组算好的数字能把这件事说清楚。一个 `[N, 1, 8, 8]` 输入经过 `3×3` 的 kernel：Valid、stride 1 得到 `(8-3)/1+1 = 6`，也就是 `[N, F, 6, 6]`；Same、stride 1 得到 `8`，即 `[N, F, 8, 8]`；Same、stride 2 得到 `ceil(8/2) = 4`。一个 `Conv1D` 处理长度 6、kernel 3、stride 2、Valid，得到 `(6-3)/2+1 = 2`。`Conv3D` 在深度、高度、宽度上各自独立套用同一条规则。`model.summary()` 会打印这些算出来的输出形状和每一层的参数量，让你在训练之前就能核对一个网络栈（[3.1. Sequential 模型](./3.1._Sequential模型.md)一页完整介绍了 `summary`）。

## 3.5.3. im2col + GEMM 引擎

`Conv1D`、`Conv2D` 和 `Conv3D` 并不各自维护一套循环嵌套。普通卷积在任何秩上都是同一个操作——变的只是空间轴的数量——所以三者都把前向和反向的数值计算交给 `convolution_engine.rs` 里的同一份实现，它对空间秩 `R = ndim - 2` 泛型。层这层包装保留公开 API、权重存储、激活函数和缓存；引擎负责真正的算术。

引擎的做法是 im2col 加 GEMM，和主流框架用的是同一套策略。前向时，它把每个输出窗口收集成一列，拼成一个 `[Cin·k_plane, out_plane]` 矩阵，其行与展平后的权重矩阵 `[F, Cin·k_plane]` 对齐，随后一次矩阵乘法产出 `[F, out_plane]`，再按 filter 加上偏置。用一次矩阵乘法换掉六层深的循环嵌套，正是让这个层能依托 crate 内部调优过的 GEMM（见 [6.2. 矩阵乘法](../Chapter-06/6.2._矩阵乘法.md)）、而不必退回朴素三重循环的关键。反向时，每个 batch 元素跑两次 GEMM——一次算权重梯度，一次算输入梯度的列，后者再散射回（col2im）输入梯度张量。

是否并行由估算的 FLOPs 决定，而不是元素个数，因为 `7×7×512` 和 `3×3×3` 这两种卷积即便输出元素数相同，开销也天差地别。前向的判据是把 `2 · batch · F · out_plane · Cin·k` 与 `CONV_PARALLEL_MIN_FLOPS`（默认 4,000,000，可通过 `rustyml::tuning` 在运行时调节）作比较。低于阈值就串行执行；高于阈值，前向便按 `(batch 元素, 输出位置块)` 划分任务并行，于是即便 `batch == 1`，单张大图也能占满每一个核——每个任务构建自己的 im2col 块，并 GEMM 到互不相交的输出区域。反向按 batch 元素并行，并按 batch 顺序归约权重和偏置的部分和，从而保证同一台机器上多次运行结果逐位可复现；它还让每个元素的 GEMM 走一个开关：当 batch 太短、填不满线程池时保持这些 GEMM 并行，一旦 batch 本身就已占满线程池就把它们切成串行，这样各个 batch 任务就不会各自在 GEMM 内部再 fork 一次 rayon。实际结论是：并行路径给出的数值与串行路径完全一致，你几乎不需要动这个阈值——但如果你分析某个负载恰好卡在阈值之下，[7.3. 性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)会讲怎么调整它。

## 3.5.4. 深度卷积与可分离卷积

标准卷积一次就同时在通道和空间两个维度上做混合：每个输出通道都是所有输入通道、所有 kernel 抽头上的加权和。参数正是藏在这种耦合里——权重张量的规模是 `F · Cin · kh · kw`。深度可分离卷积把这个操作拆成两个更便宜的阶段：先是一个 depthwise 卷积，独立地过滤每个输入通道（只做空间混合，不做跨通道混合），再接一个 pointwise 的 `1×1` 卷积，把通道重新组合（只做跨通道混合，没有空间范围）。这就是 MobileNet/Xception 的思路，RustyML 把这两半都暴露了出来。

`DepthwiseConv2D` 就是单独的第一个阶段。它的 `filters` 参数必须等于输入通道数——构造函数会用 `InvalidParameter` 拒绝其他任何值——因为它每个通道恰好携带一个 `kh×kw` 的 kernel，每个输入通道产出一个输出通道。它不做任何通道重组，所以单靠自己无法改变通道数；实践中它几乎总是在下游搭配一个 `1×1` 卷积。这里要注意和 Keras 的区别：Keras 的 `DepthwiseConv2D` 有 `depth_multiplier`，而 RustyML 的 `DepthwiseConv2D` 没有——如果你想让每个通道有不止一个 filter，就用 `SeparableConv2D`，它持有 `depth_multiplier` 参数，会先把中间通道数扩展到 `Cin · depth_multiplier`，再由 pointwise 阶段把它收缩到 `filters`。

参数量的算账才是重点所在。对 `Cin` 个输入通道、`F` 个输出 filter、`kh×kw` 的 kernel：

- 标准 `Conv2D`：`F · Cin · kh · kw + F`。
- `DepthwiseConv2D`：`C · kh · kw + C`（此时 `F = C`）。
- `SeparableConv2D`：`dm · Cin · kh · kw`（depthwise）`+ F · Cin · dm`（pointwise）`+ F`（偏置）。

忽略偏置，可分离与标准的参数比是 `1/F + 1/(kh·kw)`，所以 filter 数越多、kernel 面积越大，省下的就越多。由于每个参数在每个输出位置上都对应一次乘累加，这个比值同时也是计算量（FLOP）之比。具体地，把一个作用于 3 通道、64 filter 的 `3×3` 卷积换掉：标准层有 `64·3·3·3 + 64 = 1792` 个参数，等价的可分离版本有 `27 + 192 + 64 = 283` 个——少了大约 6.3 倍——而一个只做 depthwise、作用于这 3 个通道的层只有 `30` 个。下面这段程序把三者都建出来并核对参数量：

```rust
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;

fn count(p: TrainingParameters) -> usize {
    match p {
        TrainingParameters::Trainable(n) | TrainingParameters::NonTrainable(n) => n,
        TrainingParameters::NoTrainable => 0,
    }
}

fn main() {
    let input_shape = vec![1, 32, 32, 3]; // [batch, channels, H, W]

    // 作用于 3 个输入通道、64 filter 的标准 3x3 卷积。
    let standard =
        Conv2D::new(64, (3, 3), input_shape.clone(), (1, 1), Activation::ReLU).unwrap();

    // 等价的可分离版本：depthwise（depth_multiplier = 1）后接一个到 64 filter 的 pointwise 1x1。
    let separable =
        SeparableConv2D::new(64, (3, 3), input_shape.clone(), (1, 1), 1, Activation::ReLU).unwrap();

    // 只做 depthwise：保持 filters == channels（这里是 3），不做跨通道混合。
    let depthwise = DepthwiseConv2D::new((3, 3), input_shape, (1, 1), Activation::ReLU).unwrap();

    println!("standard  Conv2D params: {}", count(standard.param_count()));
    println!("separable Conv2D params: {}", count(separable.param_count()));
    println!("depthwise Conv2D params: {}", count(depthwise.param_count()));

    assert_eq!(count(standard.param_count()), 1792); // 64*3*3*3 + 64
    assert_eq!(count(separable.param_count()), 283); // 27 + 192 + 64
    assert_eq!(count(depthwise.param_count()), 30); // 3*3*3 + 3
}
```

当通道数很高、你又想削减参数和计算量时——比如很宽的特征图，或者一个打算跑在普通硬件上的模型——就该考虑它们，同时接受一个建模上的取舍：在相同的 `F` 和 kernel 下，这种分解形式的表达能力严格弱于完整卷积。它们的引擎和标准层不同：`DepthwiseConv2D` 用的是直接的循环嵌套（各通道相互独立，im2col 省不了多少），按 `(batch 元素, 通道)` 并行，判据是 `NAIVE_CONV_PARALLEL_MIN_FLOPS`（默认 1,000,000）。`SeparableConv2D` 的 depthwise 阶段走同一条朴素路径，pointwise 的 `1×1` 阶段则重新交给共享的 im2col + GEMM 引擎，因为 `1×1` 卷积恰好就是一次逐位置的跨通道矩阵乘法。

## 3.5.5. 搭建一个小型 CNN

卷积输出的是 3/4/5 阶张量，但 `Dense` 分类头要的是 2 阶的 `[batch, features]` 矩阵。`Flatten` 就是这座桥：`Flatten::new(input_shape: Vec<usize>)` 构造一个无参数的层，把 `[batch, ...]` reshape 成 `[batch, 其余维度的乘积]`，前向时接受 3-D、4-D 或 5-D 输入。你把进入它的张量形状——也就是卷积的输出形状——交给它，它就算出展平后的特征数。下面是一个完整的网络栈：一个 `Conv2D` 作用于合成的单通道 `8×8`「图像」，展平后送入一个 `Dense` 回归头，通过 [Sequential 模型](./3.1._Sequential模型.md)训练几个 epoch。

```rust
use ndarray::{Array2, Array4};
use rustyml::neural_network::layers::*;
use rustyml::neural_network::losses::*;
use rustyml::neural_network::optimizers::*;
use rustyml::neural_network::sequential::Sequential;

fn main() {
    // 合成「图像」：6 个样本，1 个通道，8x8。
    let mut x = Array4::<f32>::zeros((6, 1, 8, 8));
    for n in 0..6 {
        for i in 0..8 {
            for j in 0..8 {
                x[[n, 0, i, j]] = ((n + i + j) as f32 * 0.1).sin();
            }
        }
    }
    let x = x.into_dyn();

    // 每个样本 3 个回归目标。
    let y = Array2::<f32>::from_shape_fn((6, 3), |(n, k)| (n as f32) * 0.01 + (k as f32) * 0.1)
        .into_dyn();

    let mut model = Sequential::new();
    model
        // [6, 1, 8, 8] -> Conv2D(4 filters, 3x3, Valid) -> [6, 4, 6, 6]
        .add(
            Conv2D::new(4, (3, 3), vec![6, 1, 8, 8], (1, 1), Activation::ReLU)
                .unwrap()
                .with_random_state(42),
        )
        // [6, 4, 6, 6] -> Flatten -> [6, 144]
        .add(Flatten::new(vec![6, 4, 6, 6]).unwrap())
        // [6, 144] -> Dense -> [6, 3]
        .add(Dense::new(4 * 6 * 6, 3, Activation::Linear).unwrap().with_random_state(7))
        .compile(SGD::new(0.01, 0.0, false, 0.0).unwrap(), MeanSquaredError::new());

    model.summary();
    model.fit(&x, &y, 3).unwrap();

    let pred = model.predict(&x).unwrap();
    assert_eq!(pred.shape(), &[6, 3]);
    println!("prediction shape: {:?}", pred.shape());
}
```

`Dense` 的输入维度不是猜出来的——它就是展平后的特征数 `4 · 6 · 6 = 144`，可以直接从卷积的输出形状读出来。写错了，`Dense` 层的矩阵乘法就会拒绝这个 batch。`summary()` 会打印每个阶段的形状和参数预算，这是发现分类头尺寸写错的最快办法：

```text
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━┓
┃ Layer (type)                    ┃ Output Shape           ┃       Param # ┃
┡━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━┩
│ conv2d (Conv2D)                 │ (6, 4, 6, 6)           │            40 │
│ flatten (Flatten)               │ (None, 144)            │             0 │
│ dense (Dense)                   │ (None, 3)              │           435 │
└─────────────────────────────────┴────────────────────────┴───────────────┘
```

如果想在进入 dense 头之前先缩小空间尺寸，就在卷积和 flatten 之间插入一个[池化层](./3.6._池化层.md)；训练好的网络栈可以用 [3.9. 权重保存与加载](./3.9._权重保存与加载.md)里的工具持久化。

## 3.5.6. 错误与规避方法

卷积层的校验很严格，遇到不合法的配置会返回带类型的错误，而不是 panic。常见情形及其对应的变体：

| 情形 | 错误 |
| --- | --- |
| `filters`、某个 kernel 维度或某个 stride 为 `0` | `Error::InvalidParameter` |
| `depth_multiplier == 0`（`SeparableConv2D`） | `Error::InvalidParameter` |
| `DepthwiseConv2D` 的 `filters != channels` | `Error::InvalidParameter` |
| `input_shape` 秩不对、通道数为零，或小于 kernel（构造时） | `Error::InvalidInput` |
| `forward` 收到秩不对的张量 | `Error::InvalidInput` |
| Valid 卷积在运行时空间维小于 kernel | `Error::InvalidInput` |
| `DepthwiseConv2D` 运行时通道数 `!= filters` | `Error::DimensionMismatch` |
| `set_weights` 形状不匹配 | `Error::NeuralNetwork(NnError::WeightShape)` |
| 在 `forward` 之前调用 `backward` | `Error::NeuralNetwork(NnError::ForwardPassNotRun)` |

其中两点值得强调。第一，「Valid 填充下 kernel 比输入大」在构造时（对照声明的 `input_shape`）和前向时（对照实际张量）都会被拦下——引擎以 `usize` 计算 `in - k`，与其让它下溢，不如直接返回 `InvalidInput`。第二，通道数不匹配只有在 `DepthwiseConv2D` 上才是可恢复错误，它会显式检查运行时通道数并返回 `DimensionMismatch`。标准的 `Conv1D`/`Conv2D`/`Conv3D` 层根据声明的 `input_shape` 里的通道数确定权重矩阵尺寸，之后不会在每次前向时重新校验，所以你必须喂进当初声明的那个通道数；把声明的通道数当成一份契约。下面这段程序把这些可恢复的路径都跑了一遍：

```rust
use ndarray::Array;
use rustyml::error::Error;
use rustyml::neural_network::layers::*;
use rustyml::neural_network::traits::Layer;

fn main() {
    // 1. Valid 填充下 kernel 比声明的输入大：构造时就被拒绝。
    let too_big = Conv2D::new(1, (3, 3), vec![1, 2, 2, 1], (1, 1), Activation::Linear);
    assert!(matches!(too_big, Err(Error::InvalidInput(_))));

    // 2. DepthwiseConv2D 要求 filters == 输入通道数。
    let bad_dm = DepthwiseConv2D::new((2, 2), vec![1, 4, 4, 2], (1, 1), Activation::Linear)
        .unwrap()
        .with_depth_multiplier(0);
    assert!(matches!(bad_dm, Err(Error::InvalidParameter { .. })));

    // 3. 运行时张量比 kernel 小：Valid 的几何计算返回错误，而不是 panic。
    let mut conv = Conv2D::new(1, (3, 3), vec![1, 5, 5, 1], (1, 1), Activation::Linear).unwrap();
    let small = Array::ones((1, 2, 5, 1)).into_dyn(); // 高度 2 < kernel 3
    assert!(matches!(conv.forward(&small), Err(Error::InvalidInput(_))));

    // 4. DepthwiseConv2D 把运行时通道数不匹配转成可恢复错误。
    let mut dw =
        DepthwiseConv2D::new((2, 2), vec![1, 4, 4, 2], (1, 1), Activation::Linear).unwrap();
    let wrong_channels = Array::ones((1, 4, 4, 3)).into_dyn(); // 3 个通道，层期望 2 个
    assert!(matches!(
        dw.forward(&wrong_channels),
        Err(Error::DimensionMismatch { .. })
    ));

    println!("all error paths behaved as documented");
}
```

`ForwardPassNotRun` 这道防线最容易在训练途中让人措手不及：反向要读 `forward` 写下的缓存，所以在一个刚建好的层上调用 `backward`——或者连着调两次、中间没有插入一次 `forward`——都会返回这个变体，而不是去读陈旧的状态。在 `Sequential` 内部，这个顺序会替你安排妥当；只有当你手动驱动各个层时才会碰到它。完整的错误分类以及这些变体背后的智能构造函数，见 [1.6. 错误处理](../Chapter-01/1.6._错误处理.md)。
