# 2.10. 主成分分析

主成分分析在特征空间里找出一组正交单位方向——主轴——并按重要性排序：第一条抓住数据中最大的方差，第二条在与第一条正交的前提下抓住剩余方差里最大的一份，依此类推。把数据投影到前 `k` 条主轴上，就得到保留方差最多的 `k` 维线性子空间；而这个子空间恰好也是让重建平方误差最小的那一个。这两种视角其实是一回事（保留的方差最大 = 丢弃的信息最少），整套直觉尽在于此，也正因如此，压缩、去噪、给高维数据画图时，PCA 往往是第一个被想到的手段。

RustyML 的 `PCA` 对标 `sklearn.decomposition.PCA`：在特征矩阵上 fit，用 `transform` 得到得分，用 `inverse_transform` 变回原空间。从 scikit-learn 过来的人会碰到三处意外，本页把这三点都讲透。第一，它只做中心化、绝不做缩放，所以你喂进去的数值本身有多讲究，比在一条替你自动标准化的流水线里更要紧。第二，求解器这个旋钮是名为 `SVDSolver` 的枚举，提供三种具体策略，选哪一种取决于你有多少特征、想要多少主成分。第三，底层每一步分解都是手写的纯 Rust——没有 LAPACK，没有 BLAS——这也让求解器之间的取舍是实打实的，而非纸上谈兵。

## 2.10.1. 你要打交道的接口

所有东西都在 `rustyml::machine_learning::decomposition::{PCA, SVDSolver}` 之下，两者也都通过 [Prelude](../Chapter-01/1.5._Prelude与模块导入.md) 重新导出。这个模型是无监督的：它吃进一个 `f64` 特征矩阵，行是样本、列是特征，全程不涉及任何标签。

```rust,ignore
// 构造——n_components 必须 > 0，这里会检查
PCA::new(n_components: usize) -> Result<PCA, Error>
PCA::default()                                         // n_components = 2，Full 求解器
pca.with_svd_solver(solver: SVDSolver) -> PCA          // builder，消费 self 并返回

// 学习与投影——fit 接收 &mut self
pca.fit(&x)                -> Result<&mut PCA, Error>
pca.transform(&x)          -> Result<Array2<f64>, Error>   // (n_samples, n_components)
pca.fit_transform(&x)      -> Result<Array2<f64>, Error>
pca.inverse_transform(&scores) -> Result<Array2<f64>, Error> // (n_samples, n_features)

// 拟合后的状态——每个 getter 在 fit 前都是 None，fit 后是 Some(&…)
pca.get_mean()                     -> Option<&Array1<f64>>   // 每个特征的中心化均值
pca.get_components()               -> Option<&Array2<f64>>   // (n_components, n_features)，行即主轴
pca.get_explained_variance()       -> Option<&Array1<f64>>
pca.get_explained_variance_ratio() -> Option<&Array1<f64>>
pca.get_singular_values()          -> Option<&Array1<f64>>
pca.get_n_components() -> usize
pca.get_svd_solver()   -> SVDSolver
pca.get_n_samples()    -> Option<usize>
pca.get_n_features()   -> Option<usize>
```

构造函数只校验 `n_components > 0`；更严的那条界限 `n_components <= min(n_samples, n_features)` 要等到 `fit` 时才检查，因为它取决于数据本身。这些 getter 还兼任“模型拟合了没有”的探针：在一次成功的 `fit` 把值填进去之前，它们统统返回 `None`。`get_components` 把主轴作为 `(n_components, n_features)` 矩阵的**行**返回——这正是 scikit-learn 的 `components_` 布局，于是 `transform` 不过是中心化数据乘 `components.T`，`inverse_transform` 则是得分乘 `components`。

下面是在一个极小的二维数据集上跑完整流程，只保留一个主成分：

```rust
use ndarray::array;
use rustyml::machine_learning::decomposition::PCA;

fn main() {
    let x = array![
        [2.5, 2.4],
        [0.5, 0.7],
        [2.2, 2.9],
        [1.9, 2.2],
        [3.1, 3.0],
        [2.3, 2.7],
    ];

    // fit_transform 需要 &mut self；它就是先 fit 再对同一份数据 transform。
    let mut pca = PCA::new(1).unwrap();
    let scores = pca.fit_transform(&x).unwrap();

    println!("scores shape: {:?}", scores.shape()); // [6, 1]
    println!("mean:         {:?}", pca.get_mean().unwrap());
    println!("component:    {:?}", pca.get_components().unwrap());
    println!("variance:     {:?}", pca.get_explained_variance().unwrap());
    println!("ratio:        {:?}", pca.get_explained_variance_ratio().unwrap());
    println!("singular:     {:?}", pca.get_singular_values().unwrap());
}
```

`fit_transform(&x)` 并不是一条会给出不同结果的融合捷径——它字面上就是对同一个矩阵先调 `fit` 再调 `transform`，和你手动分两步做完全一样。真正需要分两步的场景，是把*另一个*矩阵（新样本）投影到一个已经拟合好的模型上。由于 `fit` 返回 `&mut Self`，你也可以直接链式调用一个 getter，不过常规做法还是通过 `get_*` 方法把状态读回来。

## 2.10.2. 只做中心化，不做缩放

在分解任何东西之前，`fit` 会先减去每个特征的均值，并把它存进 `get_mean()`。这是它做的*唯一*一步预处理。它不除以标准差、不做白化，也不碰各列的量纲。`transform` 复用训练时存下的均值来中心化新样本，`inverse_transform` 再把它加回去——所以均值是拟合模型实打实的一部分，而不是每次调用时临时算的。

这是把 PCA 用歪的头号原因。方差不具备尺度不变性：同一个特征，用毫米度量时的方差是用米度量时的一千倍，而 PCA 会心安理得地把第一主成分整个让给那一列。解法是在 fit *之前*先标准化特征，把每一列拉到单位方差，让 PCA 站在同一起跑线上比较它们。这时该请出 [`standardize`](../Chapter-04/4.2._标准化与归一化.md) 并传入 `StandardizationAxis::Column`，前后差别一目了然：

```rust
use ndarray::array;
use rustyml::machine_learning::decomposition::PCA;
use rustyml::utils::standardize::{standardize, StandardizationAxis};

fn main() {
    // 特征 0 的量纲极小，特征 1 的量纲极大。信息量相同，
    // 方差却天差地别。
    let x = array![
        [0.1, 1000.0],
        [0.2, 1005.0],
        [0.3, 1002.0],
        [0.4,  998.0],
        [0.5, 1010.0],
    ];

    let mut raw = PCA::new(2).unwrap();
    raw.fit(&x).unwrap();
    println!("raw ratios:          {:?}", raw.get_explained_variance_ratio().unwrap());

    let xs = standardize(&x, StandardizationAxis::Column).unwrap();
    let mut scaled = PCA::new(2).unwrap();
    scaled.fit(&xs).unwrap();
    println!("standardized ratios: {:?}", scaled.get_explained_variance_ratio().unwrap());
}
```

在原始数据上，第一个比值几乎就是 `1.0`——第 1 列的数值跨度淹没了一切，PC1 也几乎正好指向它。按列标准化之后，两个特征的贡献变得旗鼓相当，比值也反映出真实的相关结构。你*该不该*标准化是一个建模决策（如果特征本就处在同一个有意义的量纲下——比如像素强度——那么只做中心化才是诚实的选择），但无论如何都要有意识地去决定，因为 rustyml 不会替你拿主意。这就是统计文献里“对协方差做 PCA”和“对相关矩阵做 PCA”的分野：先标准化，正是对相关矩阵做 PCA。

## 2.10.3. 选择求解器，以及背后的纯 Rust 机制

`SVDSolver` 决定主成分怎么算。这名字有点名不副实——三个变体里只有一个真的会构造 SVD——但接口是统一的：无论选哪个，你拿到的主成分行、可解释方差、奇异值都一样，只是走了一条成本和精度各异的不同路线。

```rust,ignore
pub enum SVDSolver {
    Full,             // 默认：对协方差矩阵做精确的特征分解
    Randomized(u64),  // 随机化范围查找；u64 为随机草图的种子
    PowerIteration,   // 用带收缩的幂迭代提取前 k 个特征对
}
```

| 变体 | 计算方式 | 适用场景 |
| --- | --- | --- |
| `Full`（默认） | 构建 `d x d` 协方差 `XᵀX/(n-1)`，并对其做精确特征分解（Householder 三对角化 + 隐式位移 QL）。 | 中小规模数据——样本和特征大致都在 10,000 以下。精度接近机器精度；稳妥的默认选择。 |
| `Randomized(seed)` | 把 `X` 草绘到一个 `k` 宽的随机子空间，跑几轮子空间迭代，再在降维后的空间里做一次小规模 SVD。全程不实体化 `d x d` 协方差。 | 又大又宽的数据（10,000+ 特征），看重速度、又能接受一点点近似误差。`seed` 让随机草图可复现。 |
| `PowerIteration` | 先构建协方差，再用带 Hotelling 收缩的幂迭代只提取前 `k` 个特征对，而不做完整的特征分解。 | 你只需要少数几个主成分（`k` 远小于 `d`），又想跳过完整的 `O(d³)` 特征求解。 |

这套成本账值得记牢，因为 benchmark 探的正是它。`Full` 和 `PowerIteration` 都要构建稠密的 `d x d` 协方差，所以两者都得付出 `O(n·d²)` 的构建开销和 `O(d²)` 的存储开销；分岔在下一步——`Full` 做一次完整的 `O(d³)` 特征分解，`PowerIteration` 则给每个特征对分配有限次矩阵-向量乘法来提取它，并在找下一个之前把当前这个收缩掉，恰好在 `k << d` 时赢在算力上。`Randomized` 是唯一压根不碰 `d x d` 矩阵的：它的工作集是 `n x k` 的草图和 `k x d` 的降维投影，因此在 `d` 真正很大时最省内存。小问题上三者能吻合到好几位有效数字；只有当矩阵变大，近似求解器才在速度或漂移上显出差别。

```rust
use ndarray::array;
use rustyml::machine_learning::decomposition::{PCA, SVDSolver};

fn main() {
    let x = array![
        [2.5, 2.4],
        [0.5, 0.7],
        [2.2, 2.9],
        [1.9, 2.2],
        [3.1, 3.0],
        [2.3, 2.7],
        [2.0, 1.6],
        [1.0, 1.1],
    ];

    for solver in [SVDSolver::Full, SVDSolver::Randomized(42), SVDSolver::PowerIteration] {
        let mut pca = PCA::new(1).unwrap().with_svd_solver(solver);
        pca.fit(&x).unwrap();
        let sigma = pca.get_singular_values().unwrap();
        println!("{:?}: sigma_1 = {:.6}", solver, sigma[0]);
    }
}
```

关于那些*没有*暴露出来的旋钮，有两点得如实交代。`PowerIteration` 不暴露迭代次数和容差——它内部每个主成分最多跑 1000 次迭代、特征值容差为 `1e-6`、种子固定，这些都无法通过公开 API 调节。`Randomized` 只暴露种子；过采样量和子空间迭代次数都是写死的。所以 PCA 的全部配置面就是 `n_components` 加上 `with_svd_solver`——刻意做得很小。这一切都跑在 crate 自研的 `machine_learning::linalg` 模块上，它直接在 `ndarray` 数组上重新实现了对称特征分解、SVD（单边 Jacobi）和 QR（改进的 Gram-Schmidt），因此没有 LAPACK 依赖要装、要链接、要 vendor。这与 crate 其余部分[纯 Rust 数值工具](../Chapter-06/6.0._数学工具.md)的立场一脉相承，底层的协方差与投影乘法则走并行的 [`gemm`](../Chapter-06/6.2._矩阵乘法.md) 后端。

## 2.10.4. 解读方差，选定 `n_components`

fit 之后，有三个向量刻画方差如何分布在保留的各条主轴上。`get_singular_values` 按降序返回中心化数据的奇异值 `σ_i`。`get_explained_variance` 返回 `σ_i² / (n − 1)`，也就是每个主成分方向上、以数据本身量纲计的真实方差。`get_explained_variance_ratio` 把它们各自除以中心化数据的**总**方差——那条完整的迹，对*所有*特征求和，而非只对你保留的那些——于是每一项都是该主成分占总体方差的比例。这个分母的取法很关键：如果保留的主成分比特征少，这些比值加起来会小于一，差的那部分正是你丢弃的方差。

正是这条性质，让比值成为选 `n_components` 的趁手工具。标准套路是碎石图 / 累积法则：先做一次满秩分解，读出累积比值，再保留能越过你在意的方差目标（90%、95%、99%）所需的最少主轴数。

```rust
use ndarray::array;
use rustyml::machine_learning::decomposition::PCA;

fn main() {
    // 8 个样本，3 个特征；特征 2 几乎是特征 0 的线性回声，
    // 所以数据实际上是低秩的。
    let x = array![
        [1.0, 0.2, 1.19],
        [2.0, 0.1, 2.09],
        [3.0, 0.4, 3.38],
        [4.0, 0.2, 4.19],
        [5.0, 0.5, 5.48],
        [6.0, 0.3, 6.29],
        [7.0, 0.1, 7.09],
        [8.0, 0.6, 8.58],
    ];

    // 先做满秩分解（n_components = min(n_samples, n_features) = 3），
    // 再决定实际保留几条主轴。
    let mut pca = PCA::new(3).unwrap();
    pca.fit(&x).unwrap();

    let ratio = pca.get_explained_variance_ratio().unwrap();
    let mut cumulative = 0.0;
    for (i, r) in ratio.iter().enumerate() {
        cumulative += r;
        println!("PC{}: individual = {:.4}, cumulative = {:.4}", i + 1, r, cumulative);
    }

    // 累积比值越过 95% 的最小 k。
    let mut acc = 0.0;
    let mut k = ratio.len();
    for (i, r) in ratio.iter().enumerate() {
        acc += r;
        if acc >= 0.95 {
            k = i + 1;
            break;
        }
    }
    println!("keep {} component(s) to retain >= 95% variance", k);
}
```

这里有个细节值得点出：你满秩 fit 一次是为了*读*出谱，若想要更小的投影，就用选定的 `k` 再 fit 一次——重新 fit 在这里很便宜，能给你一个 `transform` 恰好输出 `k` 列的模型。如果在你的数据上重新 fit 很贵，那么注意：满秩 fit 的前 `k` 个主成分行，与 `k` 成分 fit 得到的是同一批主轴（差别至多是下文的符号约定），所以可以切片而不必重 fit。别拿单个孤立的比值去定 `k`；累积曲线才能告诉你收益在哪里趋平。

## 2.10.5. 重建与 `inverse_transform`

`inverse_transform` 把得分映射回特征空间：`reconstructed = scores · components + mean`。当你保留全部 `min(n_samples, n_features)` 个主成分时，这是一次无损往返（至多有浮点误差）；保留得更少时，重建就是你的数据在保留子空间上的正交投影，残差则是活在被丢弃主轴上的方差。度量这份残差，是给“压缩到底花了我多少代价”标上数字的最干净办法。

```rust
use ndarray::array;
use rustyml::machine_learning::decomposition::PCA;

fn main() {
    let x = array![
        [1.0, 0.2, 1.19],
        [2.0, 0.1, 2.09],
        [3.0, 0.4, 3.38],
        [4.0, 0.2, 4.19],
        [5.0, 0.5, 5.48],
        [6.0, 0.3, 6.29],
    ];

    // 只保留一条主轴，再往返回到原始的三维特征空间。
    let mut pca = PCA::new(1).unwrap();
    pca.fit(&x).unwrap();

    let scores = pca.transform(&x).unwrap();                     // (6, 1)
    let reconstructed = pca.inverse_transform(&scores).unwrap(); // (6, 3)

    // 残差的 Frobenius 范数 = 随 PC2、PC3 一起被丢掉的方差。
    let err: f64 = (&reconstructed - &x).iter().map(|d| d * d).sum::<f64>().sqrt();
    println!("scores shape:         {:?}", scores.shape());
    println!("reconstruction shape: {:?}", reconstructed.shape());
    println!("reconstruction error: {:.6}", err);
}
```

留意形状约定，因为它和 `transform` 正好相反。`transform` 要 `n_features` 列、给出 `n_components`；`inverse_transform` 要 `n_components` 列、给出 `n_features`。喂给它一个列数不是 `n_components` 的矩阵，你会拿到 `Error::DimensionMismatch`，而不是悄无声息的广播。由于符号修正（下一节）会把一整条主轴连同它的得分一起翻转，重建对它是不变的——不论某条主轴有没有被取反，乘积 `scores · components` 都一样——所以你完全不必担心一次符号翻转会毁掉一趟往返。

## 2.10.6. 确定性：符号约定与随机种子

特征向量和奇异向量只在相差一个符号的意义下唯一：`−v` 和 `v` 张成同一条主轴。scikit-learn 用户对此不陌生——这正是 PC 符号有时会在不同运行或不同库版本间翻转的原因。RustyML 在分解之后把符号钉死：必要时对每个主成分行取反，使其绝对值最大的载荷非负。结果就是，在同一份数据上，三种求解器、以及任意一种的重复运行，对每一条主轴的朝向都达成一致——符号是稳定的，你什么都不用做，`fit` 就可复现。

两点推论。其一，这套具体的符号约定是 rustyml 自己的——它取决于主成分向量本身，而非像 scikit-learn 的 `svd_flip` 那样取决于 `U` 因子——所以同一份数据下，某个主成分的符号可能和 scikit-learn 打印出来的不同。这纯属外观差异；主轴、它解释的方差、每一次重建都完全相同。其二，运行间唯一真正的变动来源是 `SVDSolver::Randomized`，它的随机草图由你传入的 `u64` 播种：同一个种子给出逐比特一致的输出，不同种子给出略有差异的近似子空间。`Full` 和 `PowerIteration` 完全不带外部随机性（`PowerIteration` 用一个固定值在内部给自己的起始向量播种）。如果你在意整条流水线的精确可复现性，参见[可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)；这里唯一的杠杆就是 `Randomized` 的种子。

拟合好的 `PCA` 用 `save_to_path` / `load_from_path` 序列化，二者把整个模型——均值、主成分、方差、奇异值——以紧凑的 [postcard](https://docs.rs/postcard) 二进制写入和读出。文件扩展名随便取（不管你叫它什么，字节都是 postcard），重新加载的模型 transform 出来与原模型完全一致：

```rust,ignore
pca.save_to_path("pca_model.bin")?;
let loaded = PCA::load_from_path("pca_model.bin")?;
let scores = loaded.transform(&x_new)?; // 与保存前的模型完全一致
```

其中的机制——版本兼容的考量、二进制格式何时适合长期持久化——在[深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)里有讲。

## 2.10.7. 错误与边界情况

PCA 校验得很严，会返回带类型的[错误](../Chapter-01/1.6._错误处理.md)而不是 panic，所以这些示例里的 `.unwrap()` 只是图简洁，并非生产环境的推荐做法。你实际会撞上的几条路径：

| 情形 | 错误变体 |
| --- | --- |
| `PCA::new(0)` | `Error::InvalidParameter` |
| `fit` 时 `n_components > min(n_samples, n_features)` | `Error::InvalidParameter` |
| `fit` 时特征矩阵为空 | `Error::EmptyInput` |
| `fit` 时样本少于 2 个 | `Error::InvalidInput` |
| 输入含 `NaN` / `Inf`（fit 或 transform） | `Error::NonFinite` |
| `fit` 之前调用 `transform` / `inverse_transform` | `Error::NotFitted` |
| `transform` 传入的特征数不对 | `Error::DimensionMismatch` |
| `inverse_transform` 传入的得分列数不对 | `Error::DimensionMismatch` |

两个样本的下限并非随意定的：方差需要 `n − 1` 作分母，单独一行就没什么可分解的。`n_components` 的上限 `min(n_samples, n_features)` 是秩的界——你没法提取出比数据所张成的还要多的正交方向，要得更多是参数错误，而不是悄悄截断的结果。注意这条是对着*数据*检查的，所以同一个 `PCA::new(5)` 实例，在 100×20 矩阵上能成功，在 3×4 矩阵上就会失败。

PCA 生来就是线性的——它只能找出你的特征的线性组合方向，所以盘踞在弯曲流形上的结构对它而言是隐形的。当碎石图怎么都不肯趋平、重建在每个 `k` 上都很差时，往往就是该转向非线性方法的信号：[核主成分分析](./2.11._核主成分分析.md)把同一套方差最大化的思路搬进核特征空间，[t-SNE](./2.12._t-SNE.md)则是把非线性邻域结构做二维可视化的工具。如果你的目标是分开*带标签*的类别、而非捕捉原始方差，那么它的有监督对应物是[线性判别分析](./2.6._线性判别分析.md)，它朝着类别可分的方向投影，而不是朝着总体散布。
