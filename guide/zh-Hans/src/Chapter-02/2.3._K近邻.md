# 2.3. K近邻

K 近邻（KNN）是训练时做得最少、预测时做得最多的算法。RustyML 把它实现为 `KNN<T>`——一个泛型分类器，标签类型 `T` 只要能哈希、能比较就行。从 scikit-learn 的 `KNeighborsClassifier` 过来的人几乎可以原样套用心智模型，但有几处是 RustyML 特有的：标签类型是泛型的（不限于整数）；距离度量是单一的 `DistanceCalculationMetric` 枚举，与 [DBSCAN](./2.8._DBSCAN.md) 和聚类指标共用；平局的打破完全确定，由标签首次出现的顺序决定；并行预测另有一个独立的入口。本页带你走一遍真实的 API，以及这些 API 背后的设计取舍。

## 2.3.1. 惰性学习：开销落在哪里

KNN 是这个 crate 里最纯粹的惰性学习器。它的 `fit` 几乎不做任何学习：校验输入，拷贝训练特征矩阵，把标签编码成紧凑的 `usize` 索引好让投票退化成廉价的整数运算，然后返回。它不会像[逻辑回归](./2.2._逻辑回归.md)或[决策树](./2.4._决策树.md)那样，把知识压进权重或一棵划分树里。真正的活儿全部推迟到 `predict`。

这种推迟是有实打实代价的。既然没有训练好的模型可查，给一个查询点分类就得逐一量它到训练样本的距离，留下最小的 k 个。走暴力路径时，`n_test` 个查询对 `n_train` 行、`d` 维的训练数据，距离阶段是 `O(n_train * n_test * d)`，再加上每个查询 `O(n_train)` 的部分选择——通过 `select_nth_unstable` 做 Quickselect，而不是整整 `O(n_train log n_train)` 的排序——把最近的 k 个挑出来。内存是 `O(n_train * d)`：整个训练集在模型的整个生命周期里都常驻内存，因为它*就是*模型本身。这是你为一个没有训练阶段、对决策边界形状不作任何假设的非参数分类器所付的代价。

由此直接引出两个后果。其一，预测延迟随训练集规模增长，几千行时飞快的 KNN，到了几十万行就成了瓶颈。其二，准确率的一切都在查询时由几何关系拍板，这也是距离度量和特征缩放（见下文）在这里比在几乎任何其他模型里都更要紧的原因。

## 2.3.2. 构造一个分类器

构造函数只吃一个 `k`。其余一切都有默认值，通过链式 builder 方法来设置：

```rust,ignore
// 核心接口（来自 src/machine_learning/neighbors/knn.rs）
pub fn new(k: usize) -> Result<Self, Error>;                       // k == 0 时返回 Err
pub fn with_weighting_strategy(self, s: WeightingStrategy) -> Self;
pub fn with_metric(self, m: DistanceCalculationMetric) -> Result<Self, Error>; // 校验闵可夫斯基的 p

pub fn fit<S1, S2>(&mut self, x: &ArrayBase<S1, Ix2>, y: &ArrayBase<S2, Ix1>)
    -> Result<&mut Self, Error>;
pub fn predict<S>(&self, x: &ArrayBase<S, Ix2>) -> Result<Array1<T>, Error>;
pub fn predict_parallel<S>(&self, x: &ArrayBase<S, Ix2>) -> Result<Array1<T>, Error>; // T: Sync + Send
pub fn fit_predict<S1, S2>(&mut self, x: &..., y: &...) -> Result<Array1<T>, Error>;
```

`new` 是构造过程中人人都会碰到、且唯一可能失败的一环：`k == 0` 时它返回 `Error::InvalidParameter`。`with_metric` 也可能失败，但仅仅因为它要校验闵可夫斯基的阶（下一节细讲）；`with_weighting_strategy` 不会失败，直接返回 `Self`。于是一条写全的 builder 链会终结在 metric 的 `?` 或 `.unwrap()` 上，这也和整个测试套件里采用的顺序一致。

给模型定参数的两个枚举：

| 参数 | 类型 | 变体 | 默认值 |
| --- | --- | --- | --- |
| 加权方式 | `WeightingStrategy` | `Uniform`、`Distance` | `Uniform` |
| 距离度量 | `DistanceCalculationMetric` | `Euclidean`、`Manhattan`、`Minkowski(f64)` | `Euclidean` |

`KNN::<T>::default()` 给你 `k = 5`、`Uniform` 加权、`Euclidean` 距离——和调用 `new(5)` 之后什么都不动得到的默认值完全一样。想读回存下来的配置，用 `get_k`、`get_weighting_strategy`、`get_metric` 和 `get_x_train`（它返回 `Option<&Array2<f64>>`，`fit` 之前是 `None`）。

标签类型 `T` 是货真价实的泛型：任何满足 `Clone + Hash + Eq` 的类型都行，所以整数类别码、`String` 标签，或者你自己的枚举都没问题。`fit` 按首次出现的顺序把见到的标签编码成索引，并存下反向映射；`predict` 再解码回原始的 `T`，喂进去 `Array1<String>`，出来的就是 `Array1<String>`。注意这只是个分类器——crate 里没有 KNN *回归器*。如果需要按邻居取平均的回归，得你自己在[第 6.1 节](../Chapter-06/6.1._距离度量.md)的距离原语之上搭一个。

第一个端到端的例子，顺序和并行两个入口都用上：

```rust
use ndarray::array;
use rustyml::machine_learning::{DistanceCalculationMetric, KNN, WeightingStrategy};

fn main() {
    let x_train = array![
        [1.0, 2.0],
        [2.0, 3.0],
        [3.0, 4.0],
        [6.0, 6.0],
        [7.0, 7.0],
        [8.0, 8.0],
    ];
    let y_train = array![0, 0, 0, 1, 1, 1];

    let mut knn = KNN::new(3)
        .unwrap()
        .with_weighting_strategy(WeightingStrategy::Uniform)
        .with_metric(DistanceCalculationMetric::Euclidean)
        .unwrap();

    knn.fit(&x_train, &y_train).unwrap();

    let x_test = array![[1.5, 2.5], [7.5, 7.0]];
    let seq = knn.predict(&x_test).unwrap();
    let par = knn.predict_parallel(&x_test).unwrap();

    assert_eq!(seq, par); // 确定性的：两条路径结果完全一致
    println!("k = {}", knn.get_k());
    println!("predictions: {:?}", seq);
}
```

`fit` 会拦下那些否则会在预测时以 panic 形式冒出来的错误。零行的 `x` 返回 `Error::EmptyInput`；`x` 里含 NaN 或无穷返回 `Error::NonFinite`；`y.len()` 与 `x.nrows()` 不一致返回 `Error::DimensionMismatch`；训练样本数少于 `k` 返回 `Error::InvalidInput`——你没法从 3 个点里要 5 个邻居。`predict` 和 `predict_parallel` 在此之外还会：`fit` 之前调用返回 `Error::NotFitted`，另加 `EmptyInput`、`DimensionMismatch`（查询矩阵与训练数据的特征数对不上）以及查询矩阵的 `NonFinite`。完整的 `Error` 枚举见[错误处理](../Chapter-01/1.6._错误处理.md)。

`fit_predict` 是个便捷方法，先 fit，再在*同一份*训练矩阵上 predict。`k = 1` 时它原样返回训练标签，因为每个点的最近邻就是它自己，距离为零——拿来做完整性检查有用，拿来估准确率没用。想要真正的泛化能力估计，用[训练集与测试集划分](../Chapter-04/4.1._训练集与测试集划分.md)留出一部分数据，再用[分类指标](../Chapter-05/5.2._分类指标.md)打分。

## 2.3.3. 距离度量与闵可夫斯基阶

距离度量决定了“最近”到底是什么意思，RustyML 用一个贯穿全库共用的枚举暴露了三种。`Euclidean`（L2）是走直线的默认选项。`Manhattan`（L1）把各坐标差的绝对值加起来，适合特征是量纲各异的独立轴、或者你想对某个离群坐标保持稳健的场合。`Minkowski(p)` 把两者一并推广：`p = 1` 精确退化为 Manhattan，`p = 2` 精确退化为 Euclidean（测试套件在同一份数据上断言了这两个等式），介于其间或更大的 `p` 则对单位球的几何形状做内插和外推。

`with_metric` 会校验闵可夫斯基阶，`p < 1` 或 `p` 非有限时返回 `Error::InvalidParameter`。这是个实打实的约束，不是风格洁癖：阶小于 1 会破坏三角不等式，结果就不再是一个度量，也会让后文那棵 kd-tree 索引的剪枝逻辑失效。裸的距离函数 `minkowski_distance_row` 在 `p < 1` 时会直接 *panic*；走 `with_metric` 这条路能把它转成一个你可以处理的、可恢复的 `Err`。传 `Minkowski(2.0)` 合法，数值上与 `Euclidean` 完全相同，但想要 L2 时优先用 `Euclidean` 变体——它能走一条矩阵乘法的快速路径（见 2.3.7 节），通用的闵可夫斯基代码没有这条路。

```rust
use ndarray::array;
use rustyml::machine_learning::{DistanceCalculationMetric, KNN, WeightingStrategy};

fn main() {
    let x_train = array![[3.0, 0.0], [0.0, 4.0]];
    let y_train = array![0, 1];

    let mut knn = KNN::new(1)
        .unwrap()
        .with_weighting_strategy(WeightingStrategy::Uniform)
        .with_metric(DistanceCalculationMetric::Minkowski(3.0))
        .unwrap();
    knn.fit(&x_train, &y_train).unwrap();

    // L3 下：dist((0,3),(3,0)) = 54^(1/3) ~= 3.78 > dist((0,3),(0,4)) = 1
    let x_test = array![[0.0, 3.0]];
    println!("{:?}", knn.predict(&x_test).unwrap()); // 最近的是 (0,4) -> class 1
}
```

这套度量抽象的更深入讲解——包括让空间索引省掉最后一步开方的“可比距离”技巧——见[第 6.1 节 距离度量](../Chapter-06/6.1._距离度量.md)。

## 2.3.4. 加权策略与平局打破

k 个邻居找齐之后，`WeightingStrategy` 决定它们的标签如何汇成一个预测。

`Uniform` 是朴素的多数投票：k 个邻居每人给自己的类别投一票，票最多的类别胜出。`Distance` 给每个邻居按 `1.0 / distance` 加权，于是距离近一半的邻居分量重一倍。当 `k` 大到邻居集会伸进真正不相似的点里时，就该用距离加权——远处的点仍然投票，但影响力衰减——它也让结果对 `k` 具体取值的敏感度变得平缓。

距离加权有一个实现里显式处理的边界情况：查询点正好和某个训练点重合时距离为零，而 `1.0 / 0.0` 是无穷。代码没有让这个无穷扩散开去，而是先检查有没有精确匹配。只要 k 个邻居里有任何一个距离恰为 `0.0`，就只让这些精确匹配的邻居按票数投票，其余一律忽略。这让一次精确命中表现得像一次查表，而这几乎总是你想要的结果。

```rust
use ndarray::array;
use rustyml::machine_learning::{DistanceCalculationMetric, KNN, WeightingStrategy};

fn main() {
    let x_train = array![[0.0, 0.0], [10.0, 0.0]];
    let y_train = array![0, 1];

    let mut knn = KNN::new(2)
        .unwrap()
        .with_weighting_strategy(WeightingStrategy::Distance)
        .with_metric(DistanceCalculationMetric::Euclidean)
        .unwrap();
    knn.fit(&x_train, &y_train).unwrap();

    // 两个点始终都在 k=2 的邻居集里；更近的那个赢下加权投票。
    let x_test = array![[1.0, 0.0], [9.0, 0.0]];
    println!("weighted: {:?}", knn.predict(&x_test).unwrap()); // [0, 1]

    // 精确匹配短路了 1/0 的问题：按票数投票，而非权重。
    let x_exact = array![[0.0, 0.0]];
    println!("exact:    {:?}", knn.predict(&x_exact).unwrap()); // [0]
}
```

平局的打破，是 RustyML 有意为之、并且写进文档的一个选择，它不同于你可能预期的那种“随便挑一个”。当两个类别打平——`Uniform` 下票数相等，或 `Distance` 下加权和相等——胜出的是*编码索引最小*的那个类别。关键在于，这个索引不是最小的标签值，而是按 `fit` 期间标签首次出现的顺序分配的。如果你的训练目标里标签 `7` 先出现、`3` 后出现，那么 `7` 编码为索引 0，平局时压过 `3`。结论是：平局的打破是**确定且可复现的**，但具体结果取决于训练行的顺序，所以重排数据有可能翻转一个平局的预测。也正是这份确定性，让 `predict` 和 `predict_parallel` 能保证结果完全一致。

## 2.3.5. 如何选 k

`k` 是最能左右行为的那个旋钮，而且它就是一个直白的偏差-方差调节盘。`k` 小（极端是 `k = 1`）给出低偏差、高方差的分类器：决策边界紧贴数据，把每一道褶皱都跟出来，包括标错的点和噪声。`k` 大则在更宽的邻域上取平均，压低方差却抬高偏差——推得够远，模型就漂向永远预测全局最常见的类别，开始把那些小而真实的少数类区域抹平。常见的起点是取 `k` 接近训练集规模的平方根，再对着一份验证划分调；没有什么能替代实测。

那条经典建议——**二分类用奇数 `k`**——说的就是平局。有了 RustyML 确定的平局打破，偶数 `k` 永远不会报错——五五开会按首次出现的顺序裁决——但这种裁决会让人觉得随意，还依赖数据顺序，所以奇数 `k` 能让二分类的投票根本落不到平局上。（距离加权也基本绕开了这个问题，因为实数权重和恰好相等的概率很低。）另外别忘了 2.3.2 节那条硬下限：`fit` 会拒绝任何大于训练样本数的 `k`。

下面这个例子把方差讲实。往 class-0 的区域里丢进一个标错的点，再把一个查询点放到它紧挨着的位置。`k = 1` 时噪声胜出；`k = 3` 和 `k = 5` 时周围真正的 class-0 点把它票数压过去：

```rust
use ndarray::array;
use rustyml::machine_learning::{DistanceCalculationMetric, KNN, WeightingStrategy};

fn main() {
    // 两个干净的簇，外加一个标错的点在 (2.5, 0)：它落在
    // class-0 区域内，却带着 class-1 的标签。
    let x_train = array![
        [0.0, 0.0], [1.0, 0.0], [2.0, 0.0], [3.0, 0.0],     // class 0
        [10.0, 0.0], [11.0, 0.0], [12.0, 0.0], [13.0, 0.0], // class 1
        [2.5, 0.0],                                         // 噪声，class 1
    ];
    let y_train = array![0, 0, 0, 0, 1, 1, 1, 1, 1];

    let x_test = array![[2.4, 0.0]]; // 紧挨着那个噪声点

    for k in [1usize, 3, 5] {
        let mut knn = KNN::new(k)
            .unwrap()
            .with_weighting_strategy(WeightingStrategy::Uniform)
            .with_metric(DistanceCalculationMetric::Euclidean)
            .unwrap();
        knn.fit(&x_train, &y_train).unwrap();
        let pred = knn.predict(&x_test).unwrap();
        println!("k = {k}: prediction = {}", pred[0]);
    }
}
```

随着 `k` 增大，预测从噪声标签翻转到正确标签：

```text
k = 1: prediction = 1
k = 3: prediction = 0
k = 5: prediction = 0
```

`k = 1` 时对单个点的这种敏感，正是高方差的失效模式；增大 `k` 就是拿它换一条更平滑、偏差更高的边界。

## 2.3.6. 特征缩放不是可选项

这是最容易把人坑到的错误，所以单开一节。KNN 按原始距离给邻居排序，而这里每一种度量都是把各坐标的差累加起来。要是一个特征取值上千、另一个只在 `[0, 1]` 之间，大量程的特征就会主导距离，小的那个形同隐身——不管真正携带标签信息的是哪一个。线性模型还能给大尺度特征学一个小系数来补偿，KNN 却没有任何系数可用。你必须在 fit 之前自己把特征缩放好。

下面的例子把标签完全编码在一个小量程的列里，而一个大量程的列毫无信息量。用原始特征时，大量程的列说了算，预测错了；用训练集逐列的均值和标准差做标准化之后（对训练集和查询点同样应用），有信息量的那一列终于站上了同一起跑线，预测就对了：

```rust
use ndarray::{array, Axis};
use rustyml::machine_learning::KNN;

fn main() {
    // 第 0 列取值在千级，没有信息量；第 1 列取值在 {0, 10}，携带标签。
    let x_train = array![
        [1000.0, 0.0],  // class 0
        [3000.0, 0.0],  // class 0
        [1050.0, 10.0], // class 1
        [3050.0, 10.0], // class 1
    ];
    let y_train = array![0, 0, 1, 1];

    // 第 1 列 = 9.0 指向 class 1；第 0 列 = 1010.0 最接近某个 class-0 的行。
    let x_test = array![[1010.0, 9.0]];

    let mut raw = KNN::new(1).unwrap();
    raw.fit(&x_train, &y_train).unwrap();
    let raw_pred = raw.predict(&x_test).unwrap();

    // 用在训练集上算出的统计量做标准化，训练集和查询点都用它。
    let mean = x_train.mean_axis(Axis(0)).unwrap();
    let std = x_train.std_axis(Axis(0), 0.0);
    let x_train_s = (&x_train - &mean) / &std;
    let x_test_s = (&x_test - &mean) / &std;

    let mut scaled = KNN::new(1).unwrap();
    scaled.fit(&x_train_s, &y_train).unwrap();
    let scaled_pred = scaled.predict(&x_test_s).unwrap();

    println!("raw features:  {:?}", raw_pred);    // 被第 0 列主导 -> [0]
    println!("standardized:  {:?}", scaled_pred); // 尊重第 1 列  -> [1]
}
```

例子里手写缩放是为了自成一体，而且它在统计上做对了：均值和标准差只来自训练数据，再应用到查询点，绝不在测试集上重新估计。真实流水线里请用 crate 的 [`standardize`](../Chapter-04/4.2._标准化与归一化.md) 辅助函数（或 `normalize`），别自己手搓；并且记住，你在训练集上拟合出来的那个变换，必须原封不动地用到新数据上——在测试集上重新拟合会泄露信息。缩放到零均值、单位方差是常规选择；想把特征约束到固定区间时，min-max 归一化是另一个备选。

## 2.3.7. 顺序预测与并行预测、kd-tree，以及 Euclidean 快速路径

RustyML 给了你两个预测入口。`predict` 是顺序的，对任何标签类型都可用。`predict_parallel` 把逐查询的工作摊到一个 Rayon 线程池上，是大批量查询时该用的那个，代价是要求 `T: Sync + Send`。两者都会在查询开跑之前，单线程地一次性把要共享的索引建好；`predict_parallel` 之后再按测试行并行。因为平局打破是确定的，两条路径返回逐位相同的标签数组——测试套件在 `Uniform`、`Distance` 和大 `k` 各种配置下都断言了这一点，所以你可以用 `predict` 开发，为了吞吐量切到 `predict_parallel`，结果一个都不会变。

底下的搜索会走两条路之一。低维时——最多 8 个特征——`predict` 会在首次使用时对训练数据建一棵 **kd-tree** 并缓存下来，给出平均情况下胜过逐行扫描的邻居查找。超过 8 个特征，这棵树就剪不动枝了（维度灾难：几乎所有东西都大致等距），于是代码退回到**暴力扫描**，2.3.1 节那个 `O(n_train * n_test * d)` 的开销就完整地压上来。这个 8 特征的天花板是针对单一数据形态标定出来的，不是什么普适定律——数据成簇的程度和数据集大小都会挪动这个交叉点——但它就是当前实现采用的那个固定阈值。

暴力路径下的 Euclidean 情形有一项专门的优化。欧几里得距离的平方展开成 `||x||^2 + ||t||^2 - 2 * x . t`，于是逐对计算里唯一要算的项是点积 `x . t`，而这是一次矩阵乘法。RustyML 一次性预算好训练行的平方范数，在所有查询间共享，再交给 gemmkit 矩阵乘法后端算交叉项——并对计算分块，让大训练集也能常驻缓存，同时依据训练矩阵是否还装得进共享 L3，在"逐行 GEMV 群"和"分块 GEMM"两种走法之间切换。Manhattan 和 Minkowski 没有这种代数捷径，只能退回到直白的逐对度量扫描，这也是想要 L2 时优先选 `Euclidean` 变体的又一个理由。kd-tree 是惰性重建的，每次重新 `fit` 时都会丢弃，所以重新拟合过的模型绝不会给出过期的邻居。关于并行的触发门槛和调优的更全面讲解，见[性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)。

## 2.3.8. 持久化

当 `T` 满足 `Serialize + Deserialize` 时（`i32` 和 `String` 都满足），`KNN<T>` 可以用 `save_to_path` / `load_from_path` 序列化。不管你选什么文件扩展名，持久化写出的都是紧凑的 postcard 二进制格式，存的正是定义这个模型的那些东西：`k`、加权策略、度量、训练矩阵，以及标签编码。kd-tree *不*被序列化——它标了 `#[serde(skip)]`，在加载后的模型第一次 `predict` 时惰性重建——所以重新加载的分类器不必额外费什么手脚，就能给出和原模型完全一致的预测。

```rust
use ndarray::array;
use rustyml::machine_learning::{DistanceCalculationMetric, KNN};

fn main() {
    let x_train = array![
        [0.0, 0.0], [1.0, 0.0], [2.0, 0.0],
        [10.0, 0.0], [11.0, 0.0], [12.0, 0.0],
    ];
    let y_train = array![0, 0, 0, 1, 1, 1];

    let mut knn = KNN::new(3)
        .unwrap()
        .with_metric(DistanceCalculationMetric::Manhattan)
        .unwrap();
    knn.fit(&x_train, &y_train).unwrap();

    let path = "knn_model.bin";
    knn.save_to_path(path).unwrap();

    // 首次 predict 时惰性重建 kd-tree；k、度量和标签都已恢复。
    let loaded = KNN::<i32>::load_from_path(path).unwrap();

    let x_test = array![[0.5, 0.0], [11.5, 0.0]];
    assert_eq!(
        knn.predict(&x_test).unwrap(),
        loaded.predict(&x_test).unwrap()
    );
    println!("round-trip predictions match");

    std::fs::remove_file(path).unwrap();
}
```

因为 KNN 模型带着它的整个训练集，序列化文件会随 `n_train * d` 增长——这里的持久化是把你的数据加上一点元数据存下来，而不是存下几个学出来的参数。如果模型体积要紧，光这一点就足以让你考虑换一个参数化分类器。格式本身及其保证见[深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)。

补充一点完整性：`KNN<T>` 还实现了 crate 里来自 `machine_learning::traits` 的共享 `Fit` 和 `Predict` trait，其中 `Fit` 以 `(x, y)` 元组的形式接收训练数据。本页通篇展示的固有方法 `fit`/`predict`/`predict_parallel` 才是你平时会调用的；这两个 trait 存在，是为了让泛型代码能统一对待各种估计器。
