# 1.1. 认识RustyML

RustyML 是一个完全用 Rust 编写的机器学习与深度学习库。它覆盖数据科学项目所需的完整流程——数据预处理、特征工程、模型训练与评估——既有经典 estimator（线性模型、树、SVM、聚类、降维、异常检测），也有一套 Keras 风格的神经网络框架。这一页讲的是这个库*是什么*，以及它背后那些刻意为之的取舍；在指南后续章节带你逐个了解 API 之前，先让你清楚自己选的到底是什么。

本指南对应的版本是 `0.13`，尚未到 1.0：API 正在趋于稳定，但次要版本仍可能引入破坏性更改。所以在生产环境里请在 `Cargo.toml` 中锁定具体版本，别用 `*`。权威的 API 参考在 [docs.rs/rustyml](https://docs.rs/rustyml)，源码在 [github.com/SomeB1oody/RustyML](https://github.com/SomeB1oody/RustyML)。

## 1.1.1. 纯 Rust，端到端

这个项目最根本的约束是：运行路径上没有任何 C 或 C++ 代码——不链接 BLAS，没有 LAPACK，没有 CUDA，也没有藏在 FFI 边界之后的 Python 解释器。这和主流 Python 技术栈的构建方式恰好相反：NumPy 和 scikit-learn 包装的是编译好的 C 与 Fortran，PyTorch/TensorFlow 包装的是庞大的 C++/CUDA 运行时。这些库都很出色，但 FFI 接缝正是运维痛点扎堆的地方——版本必须严格对齐的共享库、ABI 不匹配、`manylinux` wheel 的碰运气，还有那些藏在你实际所写语言之下的内存安全 bug。

RustyML 把一切都收进了安全 Rust。estimator 需要的稠密线性代数——对称特征分解、SVD、thin QR，以及 PCA 和 Kernel PCA 背后那些迭代式的 top-`k` 特征求解器——全都在内部的 `linalg` 模块里手写实现，而不是从外部代数 crate 引入。（`nalgebra` 确实出现在仓库里，但只是一个 *dev-dependency*，用于在测试套件里拿参考实现来交叉验证这些手写的分解；它不会进入你发布的产物。）繁重的矩阵乘积则走纯 Rust 的 [`gemm`](https://docs.rs/gemm/) crate。结果就是，每一处可能失败的运算都是你能读、能单步、能推理的受检 Rust 代码，语言的内存安全保证一路贯彻到最底层的算术内核。

依赖面很小，而且和 crate 的其余部分一样全是纯 Rust：[`ndarray`](https://docs.rs/ndarray/) 提供张量，[`rayon`](https://docs.rs/rayon/) 提供数据并行，`gemm` 负责矩阵乘法，[`serde`](https://serde.rs/) 加 [`postcard`](https://docs.rs/postcard/) 做紧凑的二进制模型持久化，`ahash` 提供快速哈希，`thiserror` 定义错误类型，`ndarray-rand` 负责随机初始化，`indicatif` 则用于可选的进度条。

## 1.1.2. 并行与零成本抽象

RustyML 用 Rayon 并行化它的计算密集内核，但不会盲目地派发任务。小规模问题串行执行——尺寸低于某个界限时，线程交接的开销比算术本身省下的还多——每一类内核都有一个校准过的尺寸阈值，只有当并行确实划算时才切到并行路径。这些阈值并非写死的常量：crate 暴露了一个 `tuning` 门面，让你在运行时覆盖这些开关而无需重新编译。当你把同一个二进制部署到核心数差异很大的机器上时，这一点尤其关键。[性能调优与并行](../Chapter-07/7.3._性能调优与并行.md)会讲怎么测量和调整它们。

纯 Rust 设计有两个后果值得直说，因为它们恰恰是别的技术栈上坑人的地方。第一，并行归约是*确定性*的：分块折叠无论用多少线程都按固定顺序求和，所以结果不会随核心数增加而漂移。第二，性能可预测——没有垃圾回收带来的停顿，没有 JIT 预热，也没有全局解释器锁把你的线程串行化。再配上每个随机化组件都有一个全局种子（见[可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md)），一次运行在不同机器上都能复现。

“零成本抽象”这个说法在这里是实打实的，不是营销话术。共享的 estimator trait——`Fit`、`Predict`、`Transform`、`FitTransform`——对 ndarray 存储类型泛型，并在编译期单态化，所以写一段对“任意 estimator”泛型的代码，运行时开销和直接调用某个具体模型完全一样。每个模型也把同样的操作以普通固有方法的形式暴露出来（`model.fit(..)`、`model.predict(..)`）；trait 实现只是转发到它们，而 Rust 的方法解析优先命中固有方法。只有当你真的需要泛型时，才会去用这些 trait。

## 1.1.3. 模块地图

crate 划分成五个模块，每个都由一个 Cargo feature 控制，外加一个共享的 `prelude`。你只编译用得上的部分。`machine_learning`、`neural_network`、`utils` 和 `metrics` 都会自动带上 `math`，因为它们都建立在同一批数值原语之上。

| Feature / 模块 | 包含内容 |
|---|---|
| `machine_learning` | 经典 estimator：`LinearRegression`、`LogisticRegression`、`KNN`、`DecisionTree`（ID3 / C4.5 / CART）、`SVC`（核 SMO）、`LinearSVC`、`LDA`、`KMeans`、`DBSCAN`、`MeanShift`、`PCA`、`KernelPCA`、`TSNE`、`IsolationForest`，以及共享的 `Fit`/`Predict`/`Transform`/`FitTransform` trait |
| `neural_network` | 一个 Sequential 模型，加上各种层（`Dense`、卷积、池化、循环、dropout、归一化）、激活函数、优化器（`SGD`、`Adam`、`AdamW`、`RMSprop`、`AdaGrad`）和损失函数 |
| `utils` | 预处理（`standardize`、`normalize`、`to_categorical` 及其同类）与数据集划分（`train_test_split`、`train_test_split_stratified`） |
| `metrics` | 面向回归、分类（`ConfusionMatrix`、ROC AUC、log loss……）和聚类（ARI、silhouette……）的评估指标 |
| `math` | 无状态的数值原语：`gemm` 支持的矩阵乘积、确定性并行归约、成对距离，以及 `DistanceCalculationMetric` 调度器 |

两个组合 feature 覆盖了常见场景：`default` 打开 `machine_learning` + `neural_network`，`full` 打开全部。另有一个独立的 `show_progress` feature 用来加上训练进度条。完整的拆解，包括每个 feature 会解锁哪些错误和类型，都在[安装与 Feature 配置](./1.2._安装与Feature配置.md)里。

`math` 是其他模块所依托的地基，而它本身就完全可以单独使用——如果你要的只是快速、确定性的并行归约和矩阵乘积，那就只依赖 `math`。它也是这个 crate 错误策略里那条诚实的分界线：`math` 和 `metrics` 是叶子模块，遇到前置条件不满足（长度不匹配、输入为空）时直接 panic，而不返回 `Result`，以此保持极少的依赖。其余所有地方，可能失败的调用都返回 `Result`。`prelude` 会把每个启用模块中最常用的条目重新导出，并按领域拆分，让你能精确地只引入某一块；[Prelude 与模块导入](./1.5._Prelude与模块导入.md)是查阅它们各自把哪些东西带入作用域的参考。

## 1.1.4. 从 scikit-learn 和 Keras 过来

API 是刻意设计得让你眼熟的。经典 estimator 沿用 scikit-learn 的 `fit` / `predict` 形态，神经网络这边则照搬 Keras 的 `Sequential` → `add` → `compile` → `fit` → `predict` 流程。只要你写过其中任何一个，肌肉记忆都能迁移过来；变的地方在于你现在身处 Rust，数据是 `ndarray` 数组而非 NumPy，可能失败的调用返回 `Result` 而不是抛异常。

一个经典模型，从头到尾。注意构造函数返回 `Result`（它会预先校验超参数），`fit` 和 `predict` 也一样：

```rust
use rustyml::prelude::machine_learning::*;
use ndarray::array;

fn main() {
    // 依次为 fit_intercept、learning_rate、max_iterations、tolerance
    let mut model = LinearRegression::new(true, 0.01, 1000, 1e-6).unwrap();

    let x = array![[1.0, 2.0], [2.0, 3.0], [3.0, 4.0]];
    let y = array![6.0, 9.0, 12.0];

    model.fit(&x, &y).unwrap();
    let predictions = model.predict(&x).unwrap();
    println!("predictions: {:?}", predictions);
}
```

同样风格的一个神经网络。`Sequential::new()`，用 `add` 叠加层，用一个优化器和损失函数 `compile`，然后 `fit`。这里每个张量都是 `f32`；把 epoch 数量控制得小一些，示例就能很快跑完：

```rust
use rustyml::neural_network::sequential::Sequential;
use rustyml::prelude::neural_network::*;
use ndarray::Array;

fn main() {
    // 4 个样本，8 个输入特征，1 个输出
    let x = Array::ones((4, 8)).into_dyn();
    let y = Array::ones((4, 1)).into_dyn();

    let mut model = Sequential::new();
    model
        .add(Dense::new(8, 16, Activation::ReLU).unwrap())
        .add(Dense::new(16, 1, Activation::Linear).unwrap())
        .compile(
            Adam::new(0.001, 0.9, 0.999, 1e-8, 0.0).unwrap(),
            MeanSquaredError::new(),
        );

    model.summary(); // 打印网络结构，就像 Keras 一样
    model.fit(&x, &y, 5).unwrap();

    let predictions = model.predict(&x).unwrap();
    println!("prediction shape: {:?}", predictions.shape());
}
```

评估遵循和 scikit-learn 相同的约定——每个指标都按 `(y_true, y_pred)` 这个顺序接收参数：

```rust
use rustyml::metrics::*;
use ndarray::array;

fn main() {
    let y_true = array![1.0, 0.0, 0.0, 1.0, 1.0];
    let y_pred = array![1.0, 0.0, 1.0, 1.0, 0.0];

    let cm = ConfusionMatrix::new(&y_true.view(), &y_pred.view());
    println!("accuracy: {:.3}", cm.accuracy());
    println!("f1 score: {:.3}", cm.f1_score());
}
```

和 Python 的差异，正是你能从一门有类型、有检查的语言身上料到的那些，而它们是特性，不是阻力。错误即值：一个可能失败的调用交还给你的是一个结构化的 `Error`，你可以对它 `match`，而不是一段调用栈；于是“这个模型从没训练过”和“这两个形状对不上”是两种不同的、可捕获的结果——见[错误处理](./1.6._错误处理.md)。超参数在构造时就完成校验，非法的学习率会在 `new` 处失败，而不是在训练二十次迭代之后才悄悄产出 `NaN`。配置采用 builder 模式：许多 estimator 在 `new` 里接收核心参数，再通过链式的 `with_*` 方法叠加可选设置（例如 `LinearRegression::new(..)?.with_regularization(..)`）。而且你自始至终都和 `ndarray` 打交道；如果它对你是新东西，[使用 ndarray 准备数据](./1.3._使用ndarray准备数据.md)是入门坡道，[第一个端到端模型](./1.4._第一个端到端模型.md)则会搭起一个完整的项目。

## 1.1.5. 纯 Rust 在部署时给你带来什么

1.1.1 里那条约束的回报，要到你交付时才显现。一个 RustyML 程序编译成单个自包含的二进制。不用装 Python 运行时，不用复现 virtualenv，不用操心系统 BLAS 的版本对不对得上，也不用在目标主机上把 `LD_LIBRARY_PATH` 配好。你为要部署的架构交叉编译，然后拷一个文件过去就行。对容器而言，镜像就此塌缩成一个跑在极简基础镜像上的静态二进制；对边缘或嵌入式目标而言，它把解释器整个去掉了。

持久化也是为同一个故事而设计的。训练好的经典模型和神经网络权重通过 Serde 和 postcard，用 `save_to_path` / `load_from_path` 序列化为紧凑的二进制；于是你部署的产物就是一小块 blob，由生成它的那份纯 Rust 代码原样加载——没有格式桥接，另一端也没有框架运行时。[深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)会讲这个格式及其兼容规则。又因为没有 GC、没有解释器，延迟是可预测的：没有预热，没有 stop-the-world，把任务铺开到多个线程时也不会有 GIL 争用。

## 1.1.6. 关于适用范围的实话

RustyML 只跑在 CPU 上。它没有 GPU 或 CUDA 后端，纯 Rust 的设计里也没有这个计划；并行来自 Rayon 在 CPU 各核心间的调度。对大型卷积网络来说，这是一道实实在在的天花板——这套神经网络框架适合中小规模模型、教学、嵌入式推理，以及贴近经典机器学习的那类深度学习，而不适合训练大型视觉或语言模型，那些场景你会想要一整套 GPU 技术栈。

数值精度按领域固定，这种划分是刻意的。经典的 `machine_learning` 和 `utils` estimator 工作在 `f64` 特征矩阵上——你随手写的 `ndarray::array!` 字面量默认就是 `f64`，所以这一点通常察觉不到。神经网络栈工作在 `f32` 上：它的张量类型是 `Tensor = ArrayD<f32>`，选 `f32` 是因为它把内存吞吐减半，而且是深度学习的标准。实际影响是，你不能把一个 `f64` 数组直接塞给某个层；要在边界处转成 `f32`。（标签类型是经典这边 `f64` 规则的例外——`KNN` 对它的标签类型泛型，`LDA` 接收 `i32` 标签。）

这套神经网络框架不像 PyTorch 那样构建动态自动微分图。每个层各自实现自己的前向和反向传播，`Sequential` 把它们串起来；这让运行时保持精简、可预测，但也意味着你是从给定的层集合里做组合，而不是对任意表达式求导。最后，一切都在单机上运行——没有分布式训练——而且正如开头所说，1.0 之前的 API 在次要版本之间仍可能变动。
