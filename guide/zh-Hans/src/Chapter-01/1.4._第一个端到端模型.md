# 1.4. 第一个端到端模型

[1.3. 使用ndarray准备数据](./1.3._使用ndarray准备数据.md) 里的那些零件，在这一页拼成一个能跑的分类器。我们在代码里造一个很小的二分类数据集，划分、标准化，用 `LogisticRegression` 拟合，再用准确率和混淆矩阵打分，最后把训练好的模型序列化到磁盘、又读回来。下面每一处调用都在 RustyML 0.13 上、开启 `full` 与 `show_progress` feature 编译通过，所以这些签名就是你实际要敲的样子。

动手之前先纠正一个预期：RustyML 没有 `Pipeline` 对象，也没有 `StandardScaler` 那样带状态的转换器。如果你从 scikit-learn 过来，这个"缺失"是本页最需要先记住的一点。RustyML 给你的是一批锋利、独立的函数（`train_test_split`、`standardize`、`accuracy`），以及各自持有 `fit`/`predict`/`save_to_path` 的模型结构体。把它们串起来是你的活儿——这也意味着训练集和测试集之间那条防泄漏的界线同样得你自己来画，库不会替你画。这是贯穿整篇教程的主线。

## 1.4.1. 完整程序

整个程序放在一个文件里。先从头到尾读一遍，后面的小节会逐步拆解每一步，并说明跳过它会坏在哪里。

```rust
use ndarray::{Array1, Array2, Axis};
use rustyml::machine_learning::LogisticRegression;
use rustyml::metrics::{ConfusionMatrix, accuracy};
use rustyml::set_global_seed;
use rustyml::utils::train_test_split::train_test_split;

fn main() {
    // (1) 先把这个线程上所有带种子的组件都钉死。
    set_global_seed(42);

    // (2) 造一个合成的二分类数据集。两团点，其中特征 2 故意放在比特征 1
    // 大约 100 倍的尺度上，好让标准化真正起作用。
    let n_per_class = 30usize;
    let mut rows: Vec<f64> = Vec::with_capacity(2 * n_per_class * 2);
    let mut labels: Vec<f64> = Vec::with_capacity(2 * n_per_class);
    for i in 0..n_per_class {
        let a = (i % 6) as f64;
        let b = (i / 6) as f64;
        // 类别 0 中心在 -0.6 附近；类别 1 在 +0.6 附近，两者的散布有重叠。
        rows.push(-0.6 + 0.3 * a);
        rows.push((-0.6 + 0.3 * b) * 100.0);
        labels.push(0.0);
        rows.push(0.6 + 0.3 * a);
        rows.push((0.6 + 0.3 * b) * 100.0);
        labels.push(1.0);
    }
    let n = labels.len();
    let x: Array2<f64> = Array2::from_shape_vec((n, 2), rows).unwrap();
    let y: Array1<f64> = Array1::from(labels);

    // (3) 划分。x 和 y 会按值被消耗。
    let (x_train, x_test, y_train, y_test) =
        train_test_split(x, y, Some(0.25), Some(42)).unwrap();

    // (4) 标准化：统计量只从训练集算，同时应用到两个划分。
    let mean = x_train.mean_axis(Axis(0)).unwrap();
    let std = x_train.std_axis(Axis(0), 0.0);
    let x_train_std = (&x_train - &mean) / &std;
    let x_test_std = (&x_test - &mean) / &std;

    // (5) 训练。
    let mut model = LogisticRegression::new(true, 0.5, 1000, 1e-6).unwrap();
    model.fit(&x_train_std, &y_train).unwrap();

    // (6) 在留出的测试集上预测。
    let preds: Array1<i32> = model.predict(&x_test_std).unwrap();
    let preds_f64: Array1<f64> = preds.mapv(|v| v as f64);

    // (7) 评估。
    let acc = accuracy(&y_test, &preds_f64);
    let cm = ConfusionMatrix::new(&y_test, &preds_f64);
    let (tp, fp, tn, fn_) = cm.get_counts();
    println!("test accuracy = {:.3}", acc);
    println!("TP={tp} FP={fp} TN={tn} FN={fn_}");
    println!("{}", cm.summary());
    println!("iterations run: {:?}", model.get_actual_iterations());

    // (8) 持久化并重新加载。
    let path = "logreg_model.bin";
    model.save_to_path(path).unwrap();
    let loaded = LogisticRegression::load_from_path(path).unwrap();
    let preds_loaded = loaded.predict(&x_test_std).unwrap();
    assert_eq!(preds, preds_loaded);
    std::fs::remove_file(path).unwrap();
    println!("round-trip predictions identical: {}", preds == preds_loaded);
}
```

这些 `println!` 会打印一份小报告；具体计数取决于哪些行落进了测试集，所以下面这段只当版式看，别当成确切数字：

```text
test accuracy = 0.XXX
TP=.. FP=.. TN=.. FN=..
Confusion Matrix:
+-----------------+--------------------+--------------------+
|                 | Predicted Positive | Predicted Negative |
+-----------------+--------------------+--------------------+
| Actual Positive | TP: ..             | FN: ..             |
| Actual Negative | FP: ..             | TN: ..             |
+-----------------+--------------------+--------------------+
... derived metrics ...
iterations run: Some(..)
round-trip predictions identical: true
```

## 1.4.2. 为可复现性设置种子

`rustyml::set_global_seed(42)` 从 crate 根重新导出，只接收一个 `u64`。它设置一个线程局部的种子，同一线程上此后构造的每个未设种子（`random_state == None`）的组件，都会以它为源派生自己的 RNG。这就是 Keras 风格的全局种子模型，[7.1. 可复现性与随机种子](../Chapter-07/7.1._可复现性与随机种子.md) 有完整讲解。

对自己诚实点：在这条流水线里，它对数字没有任何影响。`LogisticRegression::fit` 就是普通的全批量梯度下降，毫无随机性——对同一份数据拟合两次，得到的权重逐位相同——`standardize` 同样是确定的。唯一带随机性的步骤是 `train_test_split` 内部的洗牌，而我给它显式传了 `Some(42)`；按种子解析规则，这会**完全忽略全局种子**，改用这个局部种子。所以这里的 `set_global_seed` 是个习惯，不是开关。一旦你换上一个未设种子、又确实会抽随机数的组件——`KMeans`、`SVC`、神经网络的权重初始化器——全局种子就成了你和"不可复现的结果"之间唯一的屏障。每个实验开头都把它设上，等你以后加进这类组件时就不必再惦记着补。

如果你希望全局种子连划分这一步也管上，就把 `random_state` 传 `None`，交给 `set_global_seed` 驱动。我用显式的 `Some(42)`，是因为它让划分本身就可复现、与调用顺序无关；当你把某一行代码复制到另一个程序里时，这是更稳妥的默认做法。

## 1.4.3. 数据集与标签约定

特征是形状为 `(n_samples, n_features)` 的 `Array2<f64>`，标签是 `Array1<f64>`。标签的元素类型不是随手定的。`LogisticRegression::fit` 要求 `y` 是一个 `f64` 数组，取值必须**恰好**是 `0.0` 或 `1.0`——其他任何值（`0.5`、`2.0`，乃至某些 SVM 教材里用的 `-1.0`/`+1.0` 约定）都会返回 `Error::InvalidInput`。`fit` 里没有内置的 `LabelEncoder` 步骤；如果你的标签是字符串或任意整数，得先自己转换（见 [4.3. 标签编码](../Chapter-04/4.3._标签编码.md)）。

我故意把特征 2 放在比特征 1 大约 100 倍的尺度上。这不是装样子——它正是标准化那一步存在的理由，也埋下了下面要讲的那种失败模式。

## 1.4.4. 划分数据

```rust,ignore
let (x_train, x_test, y_train, y_test) =
    train_test_split(x, y, Some(0.25), Some(42)).unwrap();
```

函数签名是 `train_test_split(x: Array2<f64>, y: Array1<A>, test_size: Option<f64>, random_state: Option<u64>) -> Result<TrainTestSplit<A>, Error>`，其中 `TrainTestSplit<A>` 是按 `(x_train, x_test, y_train, y_test)` 这个确切顺序排列的元组。有两点会绊住新手。其一，`x` 和 `y` 按值传入——函数会消耗它们，之后还想用原数组就得在调用前克隆。其二，两个配置参数都是 `Option`：`test_size` 传 `None` 表示 `0.3`（70/30 划分），`random_state` 传 `None` 表示从系统熵取种子（若设了全局种子，则从全局种子取）。

几个错误分支值得在被它们意外击中之前就搞清楚：空数据集是 `Error::EmptyInput`；`x`/`y` 长度不一致是 `Error::DimensionMismatch`；`test_size` 落在开区间 `(0, 1)` 之外是 `Error::InvalidParameter`；数据集小到无法划分（只有一个样本）是 `Error::InvalidInput`。函数还会做钳制：它总在两侧各保留至少一行，所以对十行数据取 `test_size = 0.99`，训练侧仍会剩一行而不是零行。

要是跳过划分，直接在训练用过的那些行上评估，你算出的准确率衡量的是记忆能力，不是泛化能力——留出 `x_test` 的全部意义，就是拿模型从没见过的数据来打分。对分类问题还有一个坑：类别不平衡时，普通的随机划分可能把某个类别整个甩到一侧、另一侧一个都不剩。解法是 `train_test_split_stratified`，它对每个类别独立划分。不过它带一个实打实的约束：标签必须满足 `Clone + Eq + Hash`，而 `f64` 既不是 `Eq` 也不是 `Hash`。所以你没法在 `fit` 想要的 `f64` 标签上做分层——得在整数（或字符串）标签上分层，之后再转成 `f64`：

```rust,ignore
use rustyml::utils::train_test_split::train_test_split_stratified;

// 整数标签满足 Eq + Hash；只在把它们交给 `fit` 时才转成 f64
let (x_train, x_test, y_train_i, y_test_i) =
    train_test_split_stratified(x, y_int, Some(0.25), Some(42)).unwrap();
let y_train: Array1<f64> = y_train_i.mapv(|v| v as f64);
```

划分的具体机制和分层变体，[4.1. 训练集与测试集划分](../Chapter-04/4.1._训练集与测试集划分.md) 有深入讲解。

## 1.4.5. 标准化时不泄露测试信息

逻辑回归靠梯度下降拟合，而梯度下降在意特征的尺度。特征 2 比特征 1 大一百倍时，梯度被特征 2 主导，损失曲面的条件数很糟，收敛既慢又偏。把每个特征标准化到零均值、单位方差，能修好条件数，让同一个学习率在每一列上都管用。这一步凭这个理由站得住脚，不是摆设。

接下来是绊倒所有人的地方。RustyML 的 `standardize` 是一个**无状态、一次性**的变换。它的签名是 `standardize(data: &ArrayBase<S, D>, axis: StandardizationAxis) -> Result<Array<f64, D>, Error>`，从**你传进去的那个数组**算出均值和标准差，返回一个新的标准化数组。没有存储统计量的 `fit`，也没有重新套用统计量的 `transform`——不像 scikit-learn 的 `StandardScaler`，这个函数没地方保存训练集的均值和标准差。

```rust
use ndarray::array;
use rustyml::utils::standardize::{standardize, StandardizationAxis};

fn main() {
    // 按列标准化用的是每一列自己的均值/标准差，而且从这个
    // 确切的数组算出。没有可留给第二个数组复用的持久状态。
    let x = array![[1.0, 200.0], [3.0, 400.0], [5.0, 600.0]];
    let z = standardize(&x, StandardizationAxis::Column).unwrap();
    println!("standardized shape: {:?}", z.dim());
    println!("{:?}", z);
}
```

这种无状态，用得不动脑子就是个泄漏陷阱。诱人的做法是对 `x_train` 调一次 `standardize`，再对 `x_test` 调一次。可第二次调用是拿**测试集自己的**统计量来标准化测试集，于是训练集和测试集落到两套不同的尺度上，而模型——在训练集尺度上训练出来的——却拿另一套尺度的输入来打分。更糟的是在划分**之前**就标准化整个矩阵，那会把测试集的均值和方差揉进模型训练所用的数字里：教科书级的泄漏，会虚高你报出的准确率。

正确的套路是：从训练集算一次统计量，把同一批数字应用到两个划分上。既然 `standardize` 不替你保存统计量，就用 ndarray 显式地算：

```rust,ignore
let mean = x_train.mean_axis(Axis(0)).unwrap();   // 逐列均值，来自训练集
let std = x_train.std_axis(Axis(0), 0.0);         // 总体标准差（ddof = 0）
let x_train_std = (&x_train - &mean) / &std;       // 沿行广播
let x_test_std = (&x_test - &mean) / &std;         // 对测试集套用相同的均值/标准差
```

`std_axis(Axis(0), 0.0)` 用的是 `ddof = 0.0`，即总体标准差，恰好和 `standardize` 自己的约定一致，所以这条手写路径在训练行上能复现库给出的数字，同时在测试行上不泄漏。`&array - &mean` 和 `/ &std` 这两个表达式，靠的是 ndarray 把一个长度为 `n_features` 的向量沿每一行广播。有个边角情况要记着：常数列的 `std = 0`，除以它会得到 `NaN`。RustyML 的 `standardize` 对此有防护，会把常数特征的尺度当作 `1.0`；如果你手写这个变换，得补上同样的防护（或者像这里一样，确保没有哪个特征是常数）。更完整的标准化故事，包括 `Row`/`Column`/`Global` 三种轴和归一化的替代方案，见 [4.2. 标准化与归一化](../Chapter-04/4.2._标准化与归一化.md)。

## 1.4.6. 训练模型

```rust,ignore
let mut model = LogisticRegression::new(true, 0.5, 1000, 1e-6).unwrap();
model.fit(&x_train_std, &y_train).unwrap();
```

`LogisticRegression::new(fit_intercept, learning_rate, max_iterations, tolerance)` 返回 `Result<Self, Error>`，因为它会先校验超参数：非正或非有限的学习率、为零的 `max_iterations`、非正的容差，都会各自返回 `Error::InvalidParameter`，而不是训练到一半才炸。`LogisticRegression::default()` 给你的是 `fit_intercept = true`、`learning_rate = 0.01`、`max_iter = 100`、`tol = 1e-4`；我把学习率和迭代预算都调大了，因为标准化后的特征容得下更大的步长，而我想要一个拟合到位的模型。正则化默认关闭；用 `.with_regularization(RegularizationType::L2(alpha))` 打开，这个方法同样可能失败（负的或非有限的 `alpha` 会被拒绝）。

`fit(&x, &y) -> Result<&mut Self, Error>` 按引用接收两个数组（它不像划分那样消耗它们）。除了 `0.0`/`1.0` 标签检查，它还防范空输入（`Error::EmptyInput`）、`x`/`y` 长度不一致（`Error::DimensionMismatch`）以及非有限的特征值（`Error::NonFinite`）；如果权重或损失溢出，它也会在循环中途触发 `Error::NonFinite`——未标准化的大尺度特征配上过大的学习率，干的正是这件事。当相邻迭代间的损失变化落到 `tol` 以下，或者耗尽 `max_iter`，两者谁先到就停在谁那里。`model.get_actual_iterations()` 返回 `Option<usize>`——读回来就知道是上面哪种情况。如果它等于你的 `max_iter`，说明模型撞到了上限而非收敛，你该调高 `max_iter` 或重新审视学习率。优化器里没有随机性，所以这一切都和种子无关。模型自己的章节 [2.2. 逻辑回归](../Chapter-02/2.2._逻辑回归.md) 讲了正则化、截距项和多项式特征扩展。

## 1.4.7. 预测与 i32/f64 的接缝

```rust,ignore
let preds: Array1<i32> = model.predict(&x_test_std).unwrap();
let preds_f64: Array1<f64> = preds.mapv(|v| v as f64);
```

`predict` 返回 `Result<Array1<i32>, Error>`：硬类别标签 `0` 或 `1`，由 sigmoid 概率在 `0.5` 处阈值化得到。留意类型——是 `i32`，不是 `f64`。这很关键，因为下一步的指标要的是 `f64`，所以你用 `preds.mapv(|v| v as f64)` 转一下。这个小小的 `i32`→`f64` 接缝很容易漏，忘了它就会报类型错误。如果你要的是底层概率而非硬标签——为了自定义阈值，或做 ROC/PR 分析——就调 `predict_proba`，它返回落在开区间 `(0, 1)` 内的 `Result<Array1<f64>, Error>`。

`predict` 会在你能预料到的两种情况下大声失败：在 `fit` 之前调用它是 `Error::NotFitted`；传入的特征数与模型训练时的不同是 `Error::DimensionMismatch`。第二种正说明上一节那套防泄漏纪律不只是统计上的卫生习惯——模型在标准化输入上训练，你却把**原始的** `x_test` 喂给 `predict`，它不会报错（形状还是对得上），只会默不作声地给出更差的预测。类型系统抓不出尺度错配；只有你的流水线纪律能。

## 1.4.8. 准确率与混淆矩阵

```rust,ignore
let acc = accuracy(&y_test, &preds_f64);
let cm = ConfusionMatrix::new(&y_test, &preds_f64);
let (tp, fp, tn, fn_) = cm.get_counts();
println!("{}", cm.summary());
```

`accuracy(y_true, y_pred) -> f64` 是标签相符的比例；它在 `f64::EPSILON` 精度内比较，所以对以 `f64` 存储的整数值标签也管用，而且两个参数对称。可单单一个数字，藏住了模型**错在哪里**。`ConfusionMatrix::new(y_true, y_pred)` 构建 2x2 的分解，把两个输入都在 `0.5` 处二值化（概率或硬标签都能用），`get_counts()` 按 `(tp, fp, tn, fn)` 这个固定顺序返回计数。从这个结构体你可以读出 `accuracy()`、`precision()`、`recall()`、`specificity()`、`f1_score()`、`balanced_accuracy()` 和 `mcc()`，也可以打印 `summary()` 得到前面那张格式化表格。数据不平衡时，别用原始准确率，转而用 `balanced_accuracy()` 或 `mcc()`——一个总是预测多数类的分类器可以刷出很高的准确率却毫无用处，而混淆矩阵让这种失败一眼可见。

有一个尖锐的差别把指标和上面一切区分开来：它们**panic**，而不返回 `Result`。`accuracy` 和 `ConfusionMatrix::new` 在长度不一致或输入为空时会 panic。这里没问题，因为 `y_test` 和 `preds_f64` 从构造上就等长，但这意味着当尺寸不可信时，得你自己先校验长度再调用。完整的分类指标面貌——多分类混淆矩阵、ROC AUC、平均精度、对数损失、Cohen's kappa——都在 [5.2. 分类指标](../Chapter-05/5.2._分类指标.md)。

## 1.4.9. 保存与加载模型

```rust,ignore
model.save_to_path("logreg_model.bin").unwrap();
let loaded = LogisticRegression::load_from_path("logreg_model.bin").unwrap();
```

`save_to_path(&self, path: &str) -> Result<(), Error>` 用 [postcard](https://docs.rs/postcard) 把整个模型——权重、截距开关、学习率、迭代次数、正则化设置——序列化成一坨紧凑的二进制。`load_from_path(path: &str) -> Result<Self, Error>` 把它读回来。无论文件扩展名是什么，格式都是二进制；我用 `.bin` 是为了老实说明这一点（集成测试里恰好用了 `.json` 的名字，但字节内容照样是 postcard——扩展名只是外观）。失败以 `Error::Io` 形式冒出来，里面包着一个文件系统错误，或者——当文件被截断、或由不兼容的构建写出时——一个反序列化错误。

这个往返是精确的：逻辑回归的 `predict` 是确定的、权重逐字节序列化，所以 `loaded.predict(...)` 给出的预测和原来的完全一致——程序里那句 `assert_eq!` 之所以成立就是这个原因。像这里这样用完即弃时，事后用 `std::fs::remove_file` 把文件删掉。同样的 `save_to_path`/`load_from_path` 这一对，crate 里每个模型都会生成，所以你摸清了 `LogisticRegression` 的，也就摸清了 `KMeans`、`SVC` 以及其余模型的。神经网络通过一套平行的机制持久化权重，见 [3.9. 权重保存与加载](../Chapter-03/3.9._权重保存与加载.md)；版本与兼容性的细节在 [7.2. 深入模型持久化](../Chapter-07/7.2._深入模型持久化.md)。
