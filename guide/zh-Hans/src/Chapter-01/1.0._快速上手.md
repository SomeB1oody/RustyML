# 1. 快速上手

RustyML 是一个完全用 Rust 写成的机器学习与深度学习库——不用链接 BLAS，没有 Python 运行时，也没有 C++ 绑定要费心对付。本章带你从一个空的 `Cargo.toml` 一路走到一个存在磁盘上的、训练好的模型，并把后续每一章都默认成立的约定一一交代清楚：数据如何在 `ndarray` 中流动、feature 如何决定你编译哪些代码、prelude 放在哪里、失败又是怎么返回的。如果你是从 scikit-learn 或 Keras 过来的，这里的形态并不陌生——estimator 暴露 `fit`/`predict`，神经网络层堆叠成一个 `Sequential`——但用起来是 Rust 的那一套：Python 会抛异常的地方这里返回 `Result`，NumPy 会复制的地方这里传的是借用视图，`pip install` 甩给你一个大而全单体的地方这里用 feature 精确切分。下面的小节正是围绕这些差异组织的。

**前置要求。** 你得熟悉 `cargo`、Rust 的所有权与借用，以及基本的监督学习流程（训练、预测、评估）。不要求有 `ndarray` 使用经验——[1.3](./1.3._使用ndarray准备数据.md) 会讲清楚 estimator 需要用到的那部分。所有代码都跑在 stable Rust 上（edition 2024，工具链 1.89 或更新版本），不需要安装任何系统库。

[**1.1 认识 RustyML**](./1.1._认识RustyML.md) 在你动手写代码之前先把预期立好：这个库究竟提供什么——经典机器学习 estimator、一套 Keras 风格的神经网络栈、数据预处理、评估指标，以及底层共享的数学工具——同时也坦率地算一笔账，"纯 Rust" 给你带来了什么（可移植、没有链接器的意外、内存安全），相比成熟的 Python 生态又要付出什么代价。如果你还在拿不准这个库合不合你的问题，就从这里看起。

[**1.2 安装与 Feature 配置**](./1.2._安装与Feature配置.md) 是那种被人跳过、事后又后悔的小节。RustyML 拆成了 `machine_learning`、`neural_network`、`utils`、`metrics` 和 `math`，你打开哪个就只编译哪个。这一节讲清楚 `default`、`full`、`show_progress` 这几个组合，以及为什么只启用真正用到的模块能让构建保持精简。feature 配错了，你的 import 干脆解析不了——类型都藏在定义它们的 feature 后面。

[**1.3 用 ndarray 准备数据**](./1.3._使用ndarray准备数据.md) 讲的是整本书都倚赖的这个依赖。每个模型都说 `ndarray` 这门语言：特征矩阵用 `Array2<f64>`，目标值用 `Array1<_>`，调用边界上传的是借用的 `ArrayView`。这一节演示怎么从普通的 `Vec` 构造数组、estimator 期望的行主序（样本 × 特征）布局，以及为什么传视图而不是传拥有所有权的数组，能在每次调用时省掉一次复制。

[**1.4 第一个端到端模型**](./1.4._第一个端到端模型.md) 把这些零件拼成一个能跑的程序：构造一个很小的数据集、`fit` 一个 `LinearRegression`、`predict`，再用 `save_to_path` / `load_from_path` 把模型存下来又读回来。把编译—训练—持久化这一整圈完整地看它闭合一次，你对各个部件如何衔接的最后一点疑虑也就打消了。

[**1.5 Prelude 与模块导入**](./1.5._Prelude与模块导入.md) 讲导入的用法。`use rustyml::prelude::*` 一行就把所有已启用类别的类型、trait 和函数都引入作用域，你也可以一次只取一个类别（`prelude::machine_learning`、`prelude::metrics` 等等）。这一节还会讲共享的那几个 trait——`Fit`、`Predict`、`Transform`——什么时候必须在作用域里，这正是那种让人摸不着头脑的 "method not found" 的常见根源。

[**1.6 错误处理**](./1.6._错误处理.md) 为失败这条线收尾。可能失败的操作都返回 `Result<T, Error>`，背后是一个统一的 `Error` 枚举，它的各个变体精确点出问题所在——`NotFitted`、`DimensionMismatch`、`InvalidParameter`、`NonFinite` 等等。这一节演示如何 `match` 它们、为什么 `Error` 标了 `#[non_exhaustive]`（所以你要保留一条 `_` 分支），以及 `.context()` 如何给被包裹的底层错误附上一条线索。指南里的示例为了简洁一律 `.unwrap()`；生产代码不该这么写。

**阅读顺序。** 第一遍从头顺着读下去。如果你已经熟悉 Rust 工具链，可以快速扫过 [1.2](./1.2._安装与Feature配置.md) 和 [1.3](./1.3._使用ndarray准备数据.md)，直接落到 [1.4](./1.4._第一个端到端模型.md)；如果你还在评估要不要用，就先读 [1.1](./1.1._认识RustyML.md)。后面的章节——[经典机器学习](../Chapter-02/2.0._经典机器学习.md)、[神经网络](../Chapter-03/3.0._神经网络.md) 及更往后——都把这里立下的数组、feature 和错误处理约定当作默认前提。

整个流程浓缩在一屏之内，你先对目标心里有数：

```rust
use rustyml::machine_learning::LinearRegression;
use ndarray::{Array1, Array2};

fn main() {
    // 3 个样本，1 个特征；背后的关系是 y = 2x。
    let x = Array2::from_shape_vec((3, 1), vec![1.0, 2.0, 3.0]).unwrap();
    let y = Array1::from_vec(vec![2.0, 4.0, 6.0]);

    // new(fit_intercept, learning_rate, max_iter, tol) -> Result。
    let mut model = LinearRegression::new(true, 0.05, 5000, 1e-9).unwrap();
    model.fit(&x, &y).unwrap();

    let preds = model.predict(&x).unwrap();
    println!("predicted {} values", preds.len());
}
```
